# #110 · 개인화 브리핑과 평가

2026-10-16 · WBS 6.8.14 · FS032 / FS036 / FS066-01 · D-BRF-01/02/04.

## 기반과 병합 순서

#109의 `3c8fec3` 위에 쌓은 변경이다. 순서는 #192(107·108) → #194(109) → 이 PR(110)이다. 선행 PR은 현재 닫힌 상태를 유지한다. 팀장이 병합할 때 다시 열고 순서대로 반영하며 각 단계에서 다음 PR의 base와 diff를 재확인한다. squash 병합이면 선행 커밋을 재정리한다. 자동 병합은 하지 않는다.

## 구현 및 최종 검토 보완

- 핵심 이슈에서 회차·발행 당시 시각·graphVersion을 가진 지도 링크를 제공한다. 고정 지도 소비 경계는 #109를 재사용한다.
- 보유가 있으면 조회한 모의 보유 이름·비중·평가 시각, 없으면 관심 종목 이름을 기준으로 표시한다. 0%와 비중 미제공은 구분하며 둘 다 없으면 공통 브리핑과 내 종목 진입을 제공한다. 개인화 선정 계산은 서버 응답을 사용한다.
- 개인화 응답의 회차·발행 내용·항목 순서·시각·버전을 검증하고, 매칭 기업은 같은 이슈의 기업인지만 확인한다. 보유·관심 중 어느 기업과 겹치는지는 서버가 정한다(보유가 있어도 관심 종목 매칭을 버리지 않는다). 다른 발행본이면 적용하지 않고 공통 본문과 재시도를 유지한다.
- 이 회차에 없는 관심 종목 이름은 기업 상세에서 가져온다. 비중을 계산하지 못하면 서버가 준 이유(`weightUnavailableReason`)를 함께 보인다.
- 회차·이슈 평가를 현재 회원과 결과 버전에 묶는다. 전체 커서를 조회하고 중복·반복 커서·다른 대상·버전 오류를 거부한다. 읽기 실패는 평가 없음과 구분하여 쓰기를 막고 다시 확인할 수 있게 한다.
- 좋아요·싫어요·취소와 선택적 사유를 서버 확인 후 반영한다. 실패 시 이전 평가를 유지하고 다시 시도할 수 있다. 409는 같은 버전으로 다시 보내도 거절되므로 다시 시도 대신 새로 고침을 안내한다. graphVersion이 없는 회차는 평가를 읽거나 보내지 않고 이유를 보인다. 저장 응답의 대상·버전·평가 값도 검증한다.
- 계정 전환 시 이전 회원 요청과 입력을 버린다. 브리핑 직접 진입도 쿠키 세션을 복원하며 확인 중·확인 실패·재시도를 제공한다. 공통 브리핑 조회는 계속 가능하다.
- UI는 Tailwind와 기존 토큰을 사용한다. 새 CSS 파일·의존성·계약 정본 변경은 없다. 공통 FeedbackButtons 패턴은 ui-style-guide에 기록한다.

## 검증과 한계

- PR #196 검토 보완 후 Vitest 전체 34개 파일·333개 테스트 통과. 보완 전에는 329개였다. 세션 복원 추가 후 기존 공개 브리핑 테스트의 게스트 초기 상태를 명시했으며 관련 68개 테스트도 통과했다.
- ESLint·제품/테스트 TypeScript·Prettier·프로덕션 빌드를 확인했다. 기존 지도 번들 크기 경고는 유지한다.
- Chromium 1440px·390px에서 개인화 기준·저장·평가 조회 실패 및 복구·가로 넘침 없음·런타임 오류 없음을 합성 API로 확인했다.
- 이슈 평가의 `briefing_issue` targetId(`{회차 ID}/{eventId}`)는 프로토타입 BFF 형식을 따른다. openapi `FeedbackVote`에는 아직 정해져 있지 않다(docs/erd 미결 항목).
- 실제 개인화/평가 producer와의 E2E는 미검증이다. 테스트는 합성 계정·쿠키/CSRF fixture를 사용한다. 실제 사용자 기록·외부 기사 수집·유료 AI 호출·배포는 포함하지 않는다.

이 변경을 되돌릴 때는 110 커밋만 되돌린다. 서버 데이터 변경이나 이행은 없다.
