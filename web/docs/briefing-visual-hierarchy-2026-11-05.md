# D-BRF-01/02 · Impeccable 원칙을 적용한 브리핑 시각 정리

## 목적과 범위

사용자 요청은 기존 서비스의 정형적인 AI 생성 UI 인상을 줄이는 것입니다.
첫 적용 화면은 브리핑입니다. 출퇴근에 주요 이슈와 관련 기업·근거를 읽는
목적에 맞춰 기존 디자인 체계 안에서 위계와 장식을 정리합니다.

검토 기준은 기존 `docs/design/design-direction.md` §1.2·§5.7의
“회차당 하나의 경계, 내부는 행으로 평탄화”와 D-BRF-01/02 와이어프레임입니다.
공식 Impeccable의 [기존 화면 개선](https://impeccable.style/docs/improve-design/),
[디자인 체계 유지](https://impeccable.style/docs/design-system/),
[정보 정리](https://impeccable.style/docs/distill/),
[타이포그래피](https://impeccable.style/docs/typeset/),
[중첩 카드 등 반복 패턴](https://impeccable.style/slop/) 원칙을 참고했습니다.
공식 문서에 근거한 수동 검토·적용이며, Impeccable CLI·플러그인·후크를
설치하거나 자동 검사 점수를 산출한 것은 아닙니다.

## 검토한 방향

| 방향                                   | 장점                                        | 판단                                                            |
| -------------------------------------- | ------------------------------------------- | --------------------------------------------------------------- |
| 현재 체계 안에서 정보 위계와 표면 정리 | 현재 서비스와 이어지고 변경을 비교하기 쉬움 | 이번 로컬 수정본                                                |
| 뉴스 편집 중심의 전면 재배치           | 브리핑 읽기를 강하게 강조할 수 있음         | 화면 구성·문구 변경이 필요해 후속 검토                          |
| 새 브랜드·색·글꼴로 재설계             | 개성을 크게 바꿀 수 있음                    | 팀에서 정한 기존 테마와 글꼴 결정을 바꾸므로 이번 범위에서 제외 |

## 구현 기준

공용 `ui-style-guide.md`는 열린 PR #578과 겹쳐 이번 변경에서 제외합니다.
브리핑에 한정해 design-direction §5.7의 평탄한 내부 구조를 적용하며,
`briefingStyles.ts`의 `CARD`/`SECTION`/`DISCLOSURE`/`ISSUE_ROW`/
`ISSUE_SUMMARY`/`ISSUE_BODY`/`EMPTY`/`PRIMARY_BUTTON` 레시피를 사용합니다.
#578 머지 후 규칙 자체는 공용 `ui-style-guide.md`의 "Briefing exception"
단락으로 옮겼습니다. 이 문서에는 판단 근거와 전후 비교만 남깁니다.

리뷰 후 보정한 내용(2026-11-05):

- 섹션과 접기 영역이 서로 다른 방향의 선을 그어, 평가 섹션 뒤에 접기 영역이
  오면 선이 두 줄 생겼습니다. 회차 헤더와 같은 "아래쪽 선만, 마지막 블록은 없음"
  규칙으로 통일했습니다.
- `SECTION_TITLE`이 h4 소제목에도 쓰여 섹션 제목과 크기가 같아졌습니다. h4에는
  `SUBSECTION_TITLE`(`text-lead`)을 씁니다.
- 펼친 이슈 본문의 위쪽 선이 이슈 사이 구분선과 같아 소속이 모호했습니다. 본문은
  왼쪽 선과 들여쓰기로 이슈에 묶습니다.
- #578 이후 페이지 배경(`#f5f5f5`)과 토글 바탕(`#efefed`)이 거의 같아져, 토글에
  `border-zoop-border` 테두리를 더했습니다. 기준 필터의 hover는 면 대신 글자색만
  바꿔 선택 표시(밑줄)보다 강조되지 않게 했습니다.

- 회차 외곽의 기존 `rounded-xl`과 표면색은 유지하고 그림자를 제거합니다.
- 내부 섹션은 회색 상자 대신 여백과 구분선으로 나눕니다. 실제 오류·누락·정정
  안내와 긍정/부정 같은 의미 있는 상태 표면은 구별 가능하게 유지합니다.
- 기본 이슈·시장 전체 우선 이슈·개인화 우선 이슈에 같은
  `ISSUE_ROW`/`ISSUE_SUMMARY`/`ISSUE_BODY`를 씁니다. 접기·펼치기와 근거 조회 시점,
  그룹 구성, 정정 위치는 바꾸지 않습니다.
- 제목에는 기존 display/title/title-sm/lead 역할을 사용합니다. 데스크톱 기준
  페이지 28px → 회차 22px → 섹션 18px → 이슈 16px이고, 모바일은 기존 반응형
  토큰을 그대로 따릅니다. Pretendard·Wanted Sans·SUIT의 역할도 유지합니다.
- 기준 선택과 읽기 방식을 한 도구 영역에 모읍니다. 네이티브 버튼의
  `aria-pressed`·주소 쿼리·키보드 포커스를 유지하며, 선택 표시는 밑줄로도 구분합니다.
- 간단히 보기의 지표 3열은 개별 카드 대신 열 구분선을 씁니다. 값·출처·시각·
  null/0 표기와 전체 보기의 3행/3열 분기는 그대로입니다.
- 새로운 팔레트·글꼴·의존성·API 필드·데이터는 추가하지 않습니다.

## 검증과 증거

- 배포 서비스의 정상 브리핑은 생성 실패 상태여서 정상 발행본은 로컬 실제
  `BriefingPage`와 계약에 맞는 합성 HTTP 응답으로 비교합니다.
- 합성 응답은 기존 `morningBriefing.test.tsx`의 fixture에서 출발합니다.
  화면의 제목·요약·출처에 합성 검증임을 표시합니다. 운영 데이터로 해석하면 안 됩니다.
- 전후 캡처는 같은 데이터·테마·뷰포트·읽기 방식을 사용합니다.
- 기존 테마/쿼리/키보드 테스트에 중첩 표면과 제목 역할 확인을 보강했습니다.
  해당 테스트와 이슈 행 회귀 검사는 기존 코드에서 실패하는 것을 확인했습니다.
- 네이티브 summary는 단위 테스트에서 클릭과 DOM 구조를 확인하고, 실제 브라우저에서
  Enter로 열고 닫아 포커스가 유지되는 것을 확인합니다. jsdom을 위해 키보드 핸들러를
  제품 코드에 새로 넣지 않습니다.
- 전체 테스트·정적 검사 결과와 캡처 경로는 작업 재개 기록에 남깁니다.

## 서비스 전체의 후속 범위

1. 공통 헤더·필터·상태 안내: 이번 브리핑 결과를 검토한 뒤 같은 정보 역할을 일관되게 맞춥니다.
2. 로그인 장식: 기존 #181 버튼 구성과 인증 흐름을 유지하는 범위에서 3D 배경의 역할을 검토합니다.
3. 기업 상세: 기존 3단 구성과 금융 수치 형식을 유지하면서 중첩된 표면을 검토합니다.
4. 지도: 열린 #570의 캔버스·포커스·미니맵 변경과 분리합니다. 합의된 노드·간선·좌표·대비는 유지합니다.

이 문서는 브리핑 로컬 검토 범위이며, 서비스 전체가 수정됐다는 뜻은 아닙니다.
