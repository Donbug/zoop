# 줍(Zoop) 프론트엔드 디자인 규칙 가이드 (DESIGN.md)

이 문서는 줍(Zoop) 웹 프론트엔드 구현자가 항상 곁에 두고 준수해야 하는 **디자인 규칙 요약본**입니다. AI 슬롭(UI Slop)을 배제하고, 차분하고 신뢰할 수 있는 금융 지식 지도를 구현하기 위해 아래 규칙을 엄격히 적용합니다.

---

## 1. 허용 폰트 및 타이포그래피 규칙

### 1.1 폰트 패밀리
- **허용 폰트**: `SUIT Variable` 단일 패밀리 (`@sun-typeface/suit@2.0.5`, OFL-1.1, `wght 100~900`).
- **금지**: `Pretendard`, `Inter` 등 타 서체 전면 제거.
- **폴백 스택**: SUIT Variable은 KS X 1001 한글 완성형 2,668자만 포함하므로, 기사 원문의 희귀 음절 표시를 위해 아래 폴백을 반드시 유지합니다.
  ```css
  font-family: "SUIT Variable", "SUIT", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif;
  ```
- **숫자 고정폭 (`tnum`)**: 모든 가격, 등락률, 날짜, 수치 표기에는 OpenType `tnum`(`tabular-nums`)을 기본 적용하여 폭 흔들림을 방지합니다.

### 1.2 타입 스케일 및 글자 크기 하한선
평평한 인상은 폰트 종류가 아니라 **크기·굵기·간격 대비**로 해결합니다. 스케일을 6단계로 축소하고 본문/헤딩 대비를 크게 만듭니다.

| 토큰 | 크기 | 용도 | 굵기 규칙 |
|:---|:---:|:---|:---|
| `text-sm` | **13px** | 보조 설명, 발행 시각, 출처, 각주, 법적 고지 (**13px 미만 엄격 금지**) | Regular(400) |
| `text-base` | **15px** | 기본 본문 텍스트, 컴팩트 리스트 (**데스크톱 본문 하한선**) | Regular(400) |
| `text-md` | **16px** | 모바일 본문 및 폼 입력 필드 (**iOS 포커스 시 자동 확대 방지 기준**) | Regular(400) / Medium(500) |
| `text-lg` | **18px** | 섹션 제목, 리스트 헤더, 기업명 대표 라벨 | Semibold(600) |
| `text-xl` | **22px** | 패널 헤딩, 다이얼로그 모달 제목, 주요 가격 수치 | Semibold(600) / Bold(700) |
| `text-2xl` | **28px** | 화면 대표 타이틀, 온보딩 대형 헤딩 (**화면당 1회 제한**) | Bold(700) |

> ⚠️ **절대 규칙**: 11px(`2xs`), 12px(`xs`) 사용을 금지합니다. 면책 문구·출처·각주도 최소 13px(`text-sm`) 이상이어야 합니다.

## 2. 형태(Shape) 및 Radius 스케일

### 2.1 Radius 3단계 스케일
라운드는 **인터랙티브 컨트롤**과 **떠 있는 표면**에만 허용됩니다. 내부 콘텐츠는 라운드를 주지 않습니다.

| 토큰 | 반경 | 허용 대상 | 적용 금지 대상 |
|:---|:---:|:---|:---|
| `radius-none` | **0px** | **목록 행, 섹션, 패널 내부 항목**, 테이블, 캔버스, 구분선 | 버튼, 팝오버 |
| `radius-sm` | **8px** | **인터랙티브 컨트롤**: 버튼(`Button`), 입력창(`Input`), 세그먼트 탭 선택 배경 | 카드 컨테이너, 목록 행 |
| `radius-lg` | **16px** | **떠 있는 표면**: 바텀시트 상단 모서리, 다이얼로그 모달, 토스트, 팝오버 | 일반 패널, 내부 항목 |
| `radius-full` | **9999px** | **원형 컨트롤**: 라디오 버튼, 토글 스위치 썸, 원형 노드 | 상태 배지, 리스트 아이템 |

### 2.2 SEED 동심원(Concentric Radius) 및 평탄화 원칙
- **콘텐츠 박스화 금지**: 리스트 항목, 패널 내부 사건, 브리핑 목록을 둥근 테두리 박스(카드)로 감싸지 않습니다. **행(Row) + 구분선(Border) + 여백(Spacing)**으로 평탄화합니다.
- **동심원 규칙**: $R = 16px$인 바텀시트나 모달 내부의 컨트롤은 패딩을 고려하여 $R = 8px$(`radius-sm`)을 유지합니다 ($R_{inner} \le R_{outer} - Padding$).

## 3. 색상(Color) 및 테마 규칙

### 3.1 중성 팔레트 우선 및 브랜드 색상 절제
- 화면 면적의 **90% 이상은 중성 회색(`neutral` 계열)**으로 구성합니다.
- 브랜드 딥 틸(`#0A5C48`)은 **화면 내 주 행동(Primary CTA) 버튼 1개**와 **현재 활성 탭/선택 상태**에만 제한 사용합니다.

### 3.2 다크 모드: 저채도 중성 원칙
- **네온/글로우 금지**: 밝은 민트 청록(`#2DD4BF`), 형광 시안, 배경 네온 글로우를 전면 배제합니다.
- **다크 브랜드 색상**: 차분하고 저채도인 **딥 세이지 틸(`#47A189`)**을 사용하며, 버튼 위 텍스트는 어두운 반전 텍스트(`#0A1612`)로 WCAG AA 대비(5.98:1)를 확보합니다.
- **레이어 밝기 원칙**: 다크 모드에서는 고도가 높을수록 더 밝은 표면색을 사용합니다 (`surface-base: #0E1110` < `surface-raised: #161918` < `surface-overlay: #1D2220`). 중성 회색은 브랜드 hue(170) 쪽으로 아주 약하게 기울어 있습니다. 정확한 값은 `docs/design/tokens.json`..

### 3.3 금융 등락 및 시각 보조 3중 병기
- 한국 관례(상승 빨강 `up`, 하락 파랑 `down`)를 따르되, 색 단독 전달을 엄격히 금지합니다.
- **상승 표기**: 빨강 + `+` 부호 + `▲` 아이콘 + 수치 (예: `▲ +2.34%`)
- **하락 표기**: 파랑 + `-` 부호 + `▼` 아이콘 + 수치 (예: `▼ -1.50%`)

### 3.4 그래프: 노드는 색, 간선은 선 모양 + 요약 (v3, GraphDB식)
- **노드는 모두 원, 구분은 색**입니다. ~~기업 원 / 사건 육각형처럼 모양으로 구분~~(v3 폐기)
  - 기업: 상징색(`brandColor`) 원 + 흰색 또는 거의 검정(대비가 큰 쪽) 로고 실루엣(`logoUrl`). 로고가 없으면 이니셜, 상징색이 없으면 `graph-company-fallback-1..8` 중 `company_id` 해시로 고른 고정색.
  - 사건: 범주색 `graph-node-issue` 원 하나 + 번개(`Zap`) 아이콘.
  - 보유·관심: 3px 바깥 테두리(`graph-node-mark`). 선택: 3px 브랜드 외곽선(글로우 없음).
- **간선 가운데에 관계 요약(`summary`)**을 선을 따라 회전해 배경 받침과 함께 씁니다. 관계 유형은 선 모양으로 계속 구분합니다.
- 범례는 Neo4j식 라벨 칩(표지 + 이름 + 개수). 상세 규칙: `docs/design/design-direction.md` §4.

| 간선 유형 | 형태 | 색상 (라이트 / 다크) | 의미 |
|:---|:---:|:---:|:---|
| `involves` | **2px 실선 + 화살표** | `#2D6359` / `#83AFA6` | 사건→기업 직접 관련 |
| `structurally-related` | **2px 파선 + 화살표** | `#626B68` / `#8D9491` | 승인 기준 구조적 관련 |
| `follows` | **1.5px 실선 + 화살표** | `#895F34` / `#C8A47A` | 사건→사건 시계열 후속 |
| `shares-issue` | **1.5px 점선, 방향 없음** | `#858B88` / `#6D7371` | 기업–기업 동일 사건 파생 (직접 관계 아님: 간선 상세에서만 설명) |

### 3.5 모션 (SEED)
- 값은 당근 SEED 모션(`tokens.json` `motion`): 마이크로 ≤200ms, 매크로 >200ms. 등장 `enter` 곡선 250ms, 퇴장 `exit` 곡선 200ms, 제자리 이동 `standard`.
- 쓰는 곳: 화면 전환(`motion-page`), 시트·다이얼로그 진입·퇴장(`motion-sheet-*`, `motion-dialog`, `motion-scrim`), 팝오버·툴팁(`motion-pop`), 토스트(`motion-toast`), 세그먼트·탭 선택 표시 슬라이드, 목록 첫 표시(`stagger`), 눌림 축소(`pressable`, 세로 2px), 그래프(첫 배치 퍼짐 600ms, 선택 카메라 300ms, 모드 전환 때 남는 노드 위치 유지).
- transform·opacity만, 오버슈트 금지. `prefers-reduced-motion`이면 모두 즉시.

## 4. 배지(Badge) 및 상태 표기 규칙

### 4.1 SEED 배지 5대 원칙
1. **객체당 최대 1~2개**: 한 카드나 행에 배지를 3개 이상 붙이지 않습니다.
2. **Weak 톤 기본**: 배경이 강한 배지는 시각 잡음을 만듭니다. 연한 중성 배경(`bg-weak`) 또는 텍스트 위주로 표현합니다.
3. **중복 라벨 제거**: 목록 내 모든 행에 '직접 관련'을 반복하지 말고, 섹션 헤더에서 1회 묶음으로 안내합니다.
4. **클릭 금지**: 클릭 가능한 토글이나 필터는 `Chip` 또는 `Button`으로 만들고, `Badge`는 순수 상태 표시에만 한정합니다.
5. **보라색 합성 배지 삭제**: 합성 데이터 표지는 튀는 보라색 칩이 아닌 중성 배지(`surface-sunken` / `text-secondary`)로 표시합니다.

### 4.2 없는 값은 자리 자체를 두지 않기 (v3)
- 시세, 감성 분석, AI 요약, 재무 지표, 평가금액처럼 미제공 데이터는 **행·칸·글자를 모두 그리지 않습니다.** ~~`QuietValue`로 `시세 준비 중` 표시~~(v3 폐기)
- 데이터를 지어내지 않는다는 원칙은 그대로입니다.

### 4.3 메타 정보는 아이콘으로 (`SourceIndicator`, `IconHint`, `IconCount`)
- `datasetKind`는 **상단 헤더 1회**, **근거 창 머리 1회**에만, 글자 없는 아이콘 버튼(실제 기사 `ShieldCheck`, 저장본 `Archive`, 합성 `FlaskConical`)으로 보입니다. 툴팁·aria-label이 `데이터 출처: …`를 읽습니다. ~~출처 글자 표시~~(v3 폐기)
- 부제·섹션 설명문·`(미확정)`·`인용 확인됨`·관계 유형 글자 태그는 지우거나 `IconHint`(아이콘 + 툴팁 + 누르면 팝오버)로 바꿉니다. 개수 메타는 `IconCount`(아이콘 + 숫자, 이름은 스크린리더에만).
- 남기는 문장: 투자 권유 아님 고지 1줄(브리핑·기업 상세 하단), AI 생성 답변 표시(`Sparkles` + aria-label), 파생 경로가 직접 관계가 아니라는 설명(간선 상세에서만).
- 아이콘만 있는 컨트롤은 반드시 `aria-label` + 툴팁. 같은 뜻에는 같은 lucide 아이콘(지도 `Map`, 브리핑 `Newspaper`, 관심 `Star`, 보유 `Wallet`, 기업 `Building2`, 사건 `Zap`, 근거 `FileText`, AI `Sparkles`).

## 5. UI 슬롭(Slop) 금지 체크리스트

구현 및 코드 리뷰 시 아래 14개 항목을 반드시 체크합니다.

- [ ] **카드 중첩 금지**: `Card` 안에 또 다른 `Card`를 넣지 않았는가? (행과 구분선으로 평탄화)
- [ ] **테두리 + 그림자 동시 사용 금지**: 하나의 컨테이너에 border와 shadow를 둘 다 주지 않았는가?
- [ ] **사이드 스트라이프 금지**: 카드/패널 좌측에 두꺼운 3~4px 유색 강조선을 긋지 않았는가?
- [ ] **아이콘 타일 금지**: 둥근 사각형/원형 배경 상자 안에 아이콘을 가두지 않았는가? (인라인 아이콘 사용)
- [ ] **장식 격자/점 배경 금지**: 그래프 캔버스나 배경에 무의미한 dot grid, 점선 격자를 깔지 않았는가?
- [ ] **네온 글로우 금지**: 다크 모드 노드나 버튼 주위에 반투명 번짐(glow) 효과를 제거했는가?
- [ ] **헤딩 위 알약 금지**: 섹션 제목 위에 불필요한 카테고리 알약 칩(`방식 1/2` 등)을 달지 않았는가?
- [ ] **모바일 가로 넘침 금지**: 390px 화면에서 가로 스크롤(`scrollWidth > 390`)이 발생하지 않는가?
- [ ] **터치 영역 44×44px 보장**: 버튼, 탭, 아이콘 컨트롤의 클릭 히트 영역이 44×44px 이상인가?
- [ ] **시스템 구현 용어 차단**: `BFF`, `PoC`, `Mock`, `announced` 등 개발 내부 용어가 화면에 노출되지 않는가?
- [ ] **데이터 지어내기 금지**: PoC에 없는 시세 수치, AI 상승 확률, 긍부정 감성 점수를 임의로 날조하지 않았는가?
- [ ] **거짓 완료 금지**: 튜토리얼에서 패널을 열기만 해도 완료 처리되는 버그를 막았는가?
- [ ] **아이콘 전용 컨트롤 이름**: 아이콘만 있는 버튼에 `aria-label`과 툴팁이 있는가?
- [ ] **메타 문구 나열 금지**: `준비 중`, `합성 데이터`, 부제·설명문을 글자로 늘어놓지 않았는가? (없는 값은 자리 삭제, 출처는 아이콘)

## 6. UX 라이팅 원칙 (토스 8대 원칙 + 줍 실무 규칙)

1. **해요체 전면 통일**: `확인되었습니다` → `확인했어요`, `설정하십시오` → `설정해 주세요`.
2. **능동형 및 긍정형**: `기업이 선택되지 않았습니다` → `기업을 골라주세요`.
3. **잡초 단어(Weed) 제거**: 문맥상 없어도 뜻이 통하는 수식어, 접속사, 공간 채우기용 문장을 완전히 삭제합니다.
4. **구현 사정 설명 금지**: "창을 닫아도 상태가 보존돼요", "브라우저 저장소를 초기화해요" 등 기술 사정을 사용자에게 설명하지 않습니다.
5. **결과를 예측할 수 있는 CTA**: 단순 `확인`, `다음` 대신 `내 종목 지도 보기`, `관심 종목 3개 선택 완료`처럼 구체적 결과를 명시합니다.
6. **오류 문구 3요소**: **상황 + 이유 + 사용자 해결책**을 한 문장으로 제공합니다. (예: `네트워크 연결이 불안정해요. 잠시 후 다시 시도해 주세요.`)
7. **다이얼로그 닫기 버튼 통일**: 다이얼로그 취소/닫기 버튼은 `[닫기]`로 통일합니다 (`취소`는 작업 철회로 오인될 수 있음).
