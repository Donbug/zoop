# 줍(Zoop) 프로토타입 실행 가이드

프론트엔드(`web`)는 BFF(`bff`)의 실제 HTTP 응답만 표시합니다. 디자인시스템 페이지에만 정적 **예시** 데이터가 있습니다. 시세·감성·AI 요약은 생산자가 없으므로 **준비 중**, AI 질문은 **예시 답변**으로 표시합니다.

## 1. 사전 준비

- Node.js 22 이상, pnpm, Python 3.12 이상, uv가 필요합니다.
- PoC는 비공개 저장소 [`Donbug/investmate-poc`](https://github.com/Donbug/investmate-poc)의 고정 커밋을 BFF가 의존성으로 받습니다(`bff/pyproject.toml`). 조직 구성원 계정으로 `gh auth login` 후 `gh auth setup-git`을 한 번 실행하면 `uv sync`가 받아 옵니다. PoC 코드를 바꾸면 PoC 저장소에 올린 뒤 `pyproject.toml`의 `rev`를 새 커밋으로 바꾸고 `uv lock`을 실행합니다.
- 라이브 DB를 쓰려면 Docker의 `zoop-poc` 전용 PostgreSQL·Neo4j 컨테이너를 준비합니다. 자세한 격리·초기화·승인 데이터 생성 절차는 [`docs/evidence/poc-backend.md` §7~8](../docs/evidence/poc-backend.md)을 먼저 읽어 주세요. 기존 다른 프로젝트의 컨테이너나 볼륨을 삭제하지 마세요.
- 스냅샷 시연에는 Docker가 필요 없습니다. 기본 스냅샷은 실제 뉴스가 아닌 합성 데이터입니다.

## 2. BFF 실행 (터미널 하나)

저장소 루트에서:

```sh
cd prototype/bff
uv sync
uv run uvicorn zoop_bff.main:app --host 127.0.0.1 --port 8787
```

`http://127.0.0.1:8787/api/health`에서 상태를 확인합니다. API 문서는 `/docs`, OpenAPI 스키마는 `/openapi.json`입니다. 세부 환경변수와 API 계약은 [BFF README](bff/README.md)를 참조하세요.

## 3. 웹 실행 (다른 터미널)

```sh
cd prototype/web
pnpm install
pnpm api:types   # 위 BFF가 켜져 있어야 합니다
pnpm dev
```

`http://127.0.0.1:5173`을 엽니다. `/api` 요청은 Vite가 `http://127.0.0.1:8787`로 전달합니다. 세션 쿠키가 호스트에 묶이므로 `localhost`와 `127.0.0.1`을 섞어 쓰지 마세요.

```sh
pnpm typecheck  # TypeScript strict 검사 (tsc --noEmit)
pnpm build      # 토큰 생성 → 타입 검사 → 배포 파일 dist 생성
pnpm preview    # http://127.0.0.1:4173 (BFF는 계속 켜 두세요)
```

- 데모 이메일: `demo@zoop.local`, 비밀번호: `zoop-demo`. 시작 화면에서 **이메일로 회원가입**(약관 동의, 서버가 항목별로 검사), **개발용 모의 로그인**(실제 소셜 계정 아님, `/mock-idp` 동의 화면), **로그인 없이 둘러보기**도 고를 수 있습니다.
- 초기 설정: 투자 여부 → (투자 중) 가상 계좌 연결 또는 건너뛰기 → 관심 종목(개수 제한 없음, 0개여도 시작) → 메인 지도. 메인 지도 위에서 5단계 튜토리얼(지도 움직이기 → 기업·사건 → 관계선 → 근거 → AI에게 묻기)을 직접 해 보며 진행하고, 언제든 건너뛸 수 있습니다. 계정 메뉴 **튜토리얼 다시 보기**로 다시 엽니다.
- **로그인 없이 둘러보기**는 시장 전체 지도와 같은 튜토리얼을 제공합니다. `내 종목`(개인화) 모드·관심 종목·계좌 연결은 로그인 안내가 나옵니다.
- 회원·설정·관심 종목·가상 계좌·튜토리얼 완료·세션은 BFF 상태 DB(SQLite, `ZOOP_STATE_DIR`)에 저장돼 BFF를 재시작해도 유지됩니다. 재로그인하면 설정을 마친 회원은 바로 지도(또는 로그인 전에 가려던 화면)로 들어갑니다.

## 4. 데이터 전환

사용자가 보는 지도는 **활성 그래프 버전**입니다. BFF는 상태 디렉터리(`ZOOP_STATE_DIR`, 기본 `prototype/bff/var/`)가 비어 있을 때 한 번만 `ZOOP_SNAPSHOT_PATH`를 v1로 등록합니다. 그래서 다른 데이터로 시연하려면 **상태 디렉터리도 따로** 지정합니다. 이미 v1이 있는 디렉터리에 다른 파일을 주면 v1은 그대로이고 `/api/health`의 `warnings`에 차이가 표시됩니다. 웹 코드는 바꾸지 않습니다.

```sh
# 고정 합성 스냅샷 (기본 파일)
ZOOP_STATE_DIR=/tmp/zoop-state-synthetic uv run uvicorn zoop_bff.main:app --port 8787

# 지정 승인 스냅샷
ZOOP_STATE_DIR=/tmp/zoop-state-custom ZOOP_SNAPSHOT_PATH=/절대경로/inspect.json uv run uvicorn zoop_bff.main:app --port 8787
```

PoC 원장(Docker `zoop-poc`)의 새 결과를 사용자에게 보이려면 관리자 패널 `/admin/pipeline`에서 새 버전을 게시합니다. 사용자 API는 원장을 직접 읽지 않으며, 이전 `ZOOP_SOURCE=live` 방식은 폐지됐습니다(설정하면 기동 실패).

데이터 종류와 저장 위치는 별개입니다. `datasetKind`와 `sourceMode`는 API에 유지하고 화면에서는 출처 아이콘의 툴팁·접근성 이름으로만 안내합니다. 종목 카탈로그가 별도라면 `ZOOP_COMPANY_CATALOG`도 설정하세요. 소스 장애는 오류로 표시하며 0건으로 바꾸지 않습니다.

### 검수한 실제 뉴스로 시연하기

아래 명령은 `prototype/bff`에서 실행합니다. 완화 정책으로 처리한 실제 기사의 저장본입니다. 수동 검수에서 확인된 잘못된 후속 관계 1개는 첫 기동 때 관리자 검수 기록(거부)으로 옮겨져 사용자 화면에서 빠집니다. 원장에는 그 관계가 남아 있습니다. 제외 근거는 파일의 `review_exclusions`와 [PoC 실행 기록 §9](../docs/evidence/poc-backend.md#9-완화-정책-재판정)에 있습니다. 공유 데모는 기본 상태 디렉터리(`var/`)에 이 스냅샷을 v1로 등록해 두었습니다.

```sh
ZOOP_SNAPSHOT_PATH="$PWD/fixtures/poc-real-inspect.json" \
ZOOP_COMPANY_CATALOG="$PWD/fixtures/poc-real-companies.json" \
uv run uvicorn zoop_bff.main:app --host 127.0.0.1 --port 8787
```

웹은 `prototype/web`에서 `pnpm dev`를 실행하고 `http://127.0.0.1:5173`에 접속합니다. 저장본 조회에는 모델 호출이 발생하지 않습니다. 관리자 패널의 원장 조회·작업에는 Docker `zoop-poc` 컨테이너가 필요하고, 컨테이너가 꺼져 있으면 관리자 원장 화면만 오류를 보입니다(사용자 지도는 그대로).

## 6. 토큰 수정하기 (비전공자용)

1. `/design-system`에서 바꾸려는 색·크기의 이름을 찾습니다. 예: `brand-primary`. 규칙 요약은 [`web/DESIGN.md`](web/DESIGN.md), 전체 명세는 [`docs/design/design-direction.md`](../docs/design/design-direction.md)입니다.
2. 저장소의 `docs/design/tokens.json`을 엽니다. 예시 이름은 `color → brand → primary → $value`에 있습니다.
3. `$value`만 바꿉니다. 색은 `#0A5C48` 같은 6자리 값, 간격은 `16px` 같은 형식을 지킵니다.
4. 다크 테마 값은 `color → dark` 아래의 같은 이름도 함께 살펴봅니다.
5. `prototype/web`에서 `pnpm tokens`를 실행합니다. `src/styles/tokens.css`와 `tokens.generated.ts`가 자동 생성됩니다. 두 생성 파일은 직접 고치지 않습니다.
6. `/design-system`을 새로고침하고 라이트/다크를 모두 확인합니다. 명도 대비 표에서 일반 글자는 4.5:1, 큰 글자·UI 요소는 3:1 이상이어야 합니다.
7. `pnpm dev`·`pnpm build`·`pnpm typecheck`도 시작할 때 토큰을 자동 생성합니다.

## 7. 코드 찾기

- `src/components/ui`: Radix 기반 기본 부품(Button, Segmented, Tabs, Dialog/Sheet/BottomSheet, ListRow, AppBar, BottomTabBar 등). 계약은 [`src/components/README.md`](web/src/components/README.md)
- `src/components/domain`: 사건 행(EventRow)·데이터 출처(SourceIndicator)·그래프 등 줍 전용 부품
- `src/pages`: 화면별 조합
- `src/admin`: 관리자 패널(별도 레이아웃·세션 가드·조회 훅 `admin/api.ts`). `App.tsx`가 `React.lazy`로 불러와 사용자 번들과 청크가 분리됨
- `src/features`: 앱 셸·인증 가드·지도 탐색·상세 패널·근거/AI 창
- `src/api/schema.d.ts`: OpenAPI에서 생성한 타입. 직접 수정하지 않고 `pnpm api:types`로 갱신
- `src/api/client.ts`, `queries.ts`: BFF 호출, TanStack Query 캐시와 AbortSignal 취소. 요청별 키로 늦은 A 응답이 B 선택을 덮어쓰지 않음(TC-16)

글꼴은 SUIT Variable(OFL, `@sun-typeface/suit`)을 자체 호스팅합니다. 이 글꼴에 없는 드문 한글은 시스템 한글 글꼴로 표시됩니다. 그래프는 기본 cose, 흐름 정렬은 cytoscape-dagre를 쓰며 모션 줄이기 설정을 존중합니다.

검증 캡처: 개편 전 감사는 [`docs/design/audit`](../docs/design/audit/)와 [`slop-audit.md`](../docs/design/slop-audit.md), 개편 후는 [`docs/design/v2`](../docs/design/v2/)에 있습니다. v1 명세·캡처는 `docs/design/archive/`에 보관합니다.

## v3 그래프·아이콘·모션

- 조회에서 `depth`를 생략해 선택 종목의 전체 연결 요소를 표시합니다. 전체 모드는 전체 사건을 표시합니다. 기본 안전 상한은 500노드이며 잘리면 `metadata.truncated=true`입니다.
- 기업과 사건은 모두 원형입니다. 기업은 상징색·로고, 사건은 범주색·아이콘으로 구분합니다. 로고가 없는 기업은 이니셜을 사용합니다.
- 선에는 역할·기준 관계·공유 사건 수를 바탕으로 만든 짧은 요약이 붙습니다. 화면이 축소되면 일부 라벨을 숨기고 확대·선택 시 표시합니다.
- 상시 메타 라벨과 미제공 값의 자리를 없앴습니다. 출처·인용 상태 등은 아이콘의 툴팁과 접근성 설명으로 확인합니다.
- SEED의 duration/easing을 참고해 선택 표시, 페이지·시트 전환, 목록 등장, 그래프 배치·카메라 이동에 모션을 적용했습니다. 동작 줄이기 설정에서는 비활성화하거나 최소화합니다.
- v3 캡처·녹화: `docs/design/v3/`. `live-interim-*`는 검수 전 중간 캡처이고 `reviewed-*`가 최종 검수 데이터 캡처입니다.

## v4 그래프 탐색 기능 (임시 기본값)

회의 전 임시 기본값으로 구현했습니다. 이유와 대안은 [임시 기본값과 고민할 점](../docs/design/graph-ux-decisions.md), 전체 계획은 [개선 계획](../docs/design/graph-ux-improvement-plan.md)에 있습니다.

- **연결 없는 사건 묶음:** 기업과 연결이 없는 사건은 원 하나(“연결 없는 사건 N”)로 모입니다. 누르면 상세에 사건 목록이 나옵니다. 목록 보기에서는 모든 사건이 그대로 보입니다.
- **포커스 모드:** 노드 상세의 `이 노드 중심으로 보기` → 포커스 바에서 1단계/2단계 선택, `✕`나 뒤로 가기로 복귀. 주소에 `focus=…&hops=1|2`가 남습니다. 기존 `선택 관계만 남기기`는 이 기능으로 대체했습니다.
- **선 라벨:** 선택 시 최대 6개(최신 사건 순), 12자 초과는 말줄임, 선을 가리키면 전체.
- **근거 배지·연동:** 사건 노드에 근거 수 배지(확대했을 때 표시). 근거 창의 `지도에서 보기`를 누르면 그 인용이 뒷받침하는 연결선이 강조됩니다.
- **범례 필터:** 범례 칩을 눌러 노드 종류·관계 유형을 켜고 끕니다. 노드 위치는 바뀌지 않습니다.
- **두 기업 사이 경로:** 기업 상세의 `다른 기업과의 연결 보기` → 다른 기업을 고르면 사건을 거치는 최단 경로(파생 선 제외, 방향 무시)가 강조되고 상세에 단계 목록이 나옵니다. 주소에 `path=A,B`가 남고 `✕`·뒤로 가기로 복귀합니다. 포커스와 함께 쓰지 않습니다.
- **미니맵:** 데스크톱에서 보이는 노드가 60개를 넘으면(300노드 합성 데이터) 캔버스 오른쪽 아래에 나타납니다. 사각형을 끌면 화면이 따라갑니다. 키보드는 확대·축소·화면에 맞추기 버튼을 씁니다.
- **API 추가 필드:** 그래프 응답의 사건 노드 `evidenceCount`, 연결선 `evidenceIds`(하위 호환).

## v5 메인 그래프 (요구사항 정의서 14·17–25)

- **모드 2개:** 시장 전체(`mode=all`) / 내 종목(`mode=personal`, 보유+관심 함께 중심). 3모드(시장·관심·자산)는 없앴습니다. 보유가 없으면 관심만으로, 둘 다 없으면 `no_personal_stocks` 빈 상태에서 관심 종목 고르기로 안내합니다. 세그먼트 옆에 `보유 N · 관심 M 기준`을 적습니다.
