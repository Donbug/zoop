## 배포 전 결정·검증 목록

1. **운영 주체**: 서비스 제공자·개인정보처리자는 `돈벌래`이며 김도현이 개인정보 보호 책임자와 문의 담당자를 맡는다. 배포 계약·계정의 명의가 이 명칭과 일치하는지 확인한다.
2. **운영 범위**: 누구나 가입할 수 있지만 만 14세 미만은 가입시키지 않는 정책이다. 이메일·Google·카카오 로그인을 모두 배포한다. 연령 확인 및 제한을 실제 가입 흐름에 구현하고, 비회원 기능을 실제 배포 설정과 맞춘다.
3. **데이터 목록**: 이메일·표시명·비밀번호 해시·소셜 식별자·세션, 관심 기업·모의 계좌 연결, 채팅 질문·문맥·답변, 평가·활동 이벤트·접속 로그 중 실제 수집·보관하는 항목을 표로 대조한다. 설계에만 있는 기능은 배포 문구에서 제외하거나 활성화 전 개정한다.
4. **보유·삭제 구현**: 팀 정책은 서비스 제공 중 채팅 보관, 탈퇴 시 채팅·활동 기록·계정·약관 동의 이력 즉시 파기, 별도 장기 백업 없음, 개별 채팅 삭제 없음이다. DB·AI 복구 artifact·평가·세션·가명 통계·파일·로그·백업의 삭제 범위와 실제 처리 완료 시점을 구현·검증한다. 법령상 예외 보존 필요성은 검토한다. 현재 ERD와 서비스에는 탈퇴 즉시 전체 삭제가 구현됐다고 볼 근거가 없다.
5. **외부 사업자**: AWS 서울 리전과 OpenAI API를 사용한다. OpenAI에는 질문 텍스트와 대화 문맥만 **구조화된 필드로** 전송하고 이메일·이름·회원 ID는 첨부하지 않는 정책이다. 그러나 자유 입력 질문·문맥 자체에 개인정보가 포함될 수 있으므로 `개인정보 절대 미전송`이라고 쓰지 않는다. 실제 API endpoint·`store` 옵션, 처리 국가·계약 법인, 호스팅/로그/이메일의 실제 수탁자와 국외 이전 고지 요건을 확인한다.
6. **권리 행사 경로**: 탈퇴·정보 삭제는 `dohyun3885@gmail.com`으로 접수한다. 본인 확인, 처리 결과 통지, 열람·정정·처리정지 요청도 운영 절차로 마련한다. 개별 채팅 삭제는 제공하지 않으며, 탈퇴 시 모든 대화 내역을 일괄 삭제한다.
7. **가입 화면**: 이용약관 전문, 개인정보 처리방침 링크, 실제 법적 근거에 필요한 별도 동의 항목을 구분한다. 선택 동의를 서비스 이용의 필수 조건으로 표시하지 않는다. `SignupRequest.agreements[]`의 ID·버전·필수 여부와 승인 문서 목록을 맞춘다.
8. **승인·게시**: 운영 책임자와 개인정보/법률 검토자가 문구와 실제 처리 흐름을 확인한다. 승인 후 문서별 ID·버전·승인 시각·시행 시각·본문을 기록하고, 해당 버전만 `term_versions`에 등록한다. 가입 시 그 버전의 동의 이력을 남긴다.

대괄호 `【확정 필요: …】`가 하나라도 남은 문서는 게시하지 않는다. 승인 전 DB migration이나 seed에 본문/버전을 넣지 않는다. 운영 변경 시 문서를 먼저 검토하고 기존 승인본과 동의 이력을 덮어쓰지 않는다.

OpenAI의 [공식 API 데이터 관리 문서](https://developers.openai.com/api/docs/guides/your-data)는 API 입력·출력을 기본적으로 모델 학습에 사용하지 않는다고 설명한다(고객이 명시적으로 데이터 공유를 선택한 경우 제외). 기본 abuse monitoring 로그는 **최대 30일**이며 법적 의무·안전상 이유의 예외가 있고, endpoint별 application state 보관은 별도다. 팀은 실제 API 조직 설정, endpoint·`store` 옵션, 데이터 레지던시/국외 이전 사실을 확인해야 한다. Zero Data Retention이 자동 적용된다고 가정하지 않는다. 팀이 계약상 수신 법인을 `OpenAI OpCo, LLC`로 확인했으며, [OpenAI의 데이터 처리 부속서](https://openai.com/policies/data-processing-addendum/)와 실제 계정 계약을 배포 전에 대조한다. 공개 초안의 ‘미국’은 팀의 예정 이전 국가이며 실제 처리·보관 지역은 API 설정과 계약으로 확인한다.
