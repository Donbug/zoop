## 결론

**공개 읽기에 성공했다.** 출발 node 620-617에서 10개 페이지를 찾았고, 화면·그룹 **52개를 각각 선택해 확대 캡처**했다. 원문 설명 57개를 DOM 레이어에서 추출했다. 전체조망 캡처를 프레임 검토로 대신하지 않았다.

현재 slide-index의 실제 앱 화면 54개 가운데 **47개 화면 ID에 정적 화면 대응을 확인했고, 2개는 상태 후보만 있으며, 5개는 독립 화면 증거가 없다.** 52개 캡처는 52개의 서로 다른 제품 기능을 뜻하지 않는다. 화면 ID를 이름에 가진 44개 프레임은 43개 고유 ID이며, D-GRP-01 확대 변형·이름 없는 기업 화면·중복 후보가 포함된다. 모든 기능 동작은 미확인이다.

개선안에서 실질적인 새 구현 검토가 필요한 부분은 **그래프 시각 문법**, **기업 정보의 추가 데이터 필드**, **Google·카카오 로그인**이다. 종목 검색, 문서 탭, 기업 정보 탭 자체는 이미 현재 코드에 있으므로 새 기능으로 재산정하면 안 된다. 관리자 9개 화면은 기존 정보 구조를 유지하는 정적 대응이며 실제 운영 연동 증거는 아니다.

## 차이와 구현 영향

### 1. 지도: 기존 원형 GraphDB 표현에서 로고 중심 관계 지도 표현으로 변경

**확인된 정적 차이:** [Figma 시장 지도 619-1819](raw/wireframe_2026-10-08/frame-619-1819.png)에는 회색 캔버스, 흰 원 안 기업 로고, 검은 작은 마름모 사건, 흰 캡슐 제목 라벨, 왼쪽 상단의 NVIDIA 중심 관계 정보·범례가 보인다. 기존 [D-GRP-01](../screen-plan/captures/D-GRP-01.png)은 기업 상징색 원, 작은 사건 원, 하단 조작과 우측 미니맵을 사용한다. Figma의 개별 경로/포커스/기업 상세 내 작은 그래프에도 동일 계열 표현이 반복된다.

**정보계층·동선:** 상단 시장/내 종목·기업/사건/보유/관심·관계 종류 필터와 우측 상세 패널 분기는 유지된다. 그래프 내부에 별도의 중심 기업 제목·범례가 추가되어 전역 카운터와 지역 범례가 병존한다. 기본 시장 전체 지도에서도 “NVIDIA / 중심 관계”가 표시되므로 이를 단순 시장 전체 제목인지 실제 focus 상태인지 확인해야 한다. 상단 기업 26·사건 138·사건 공유 38과 내부 “24 COMPANIES · 18 SHARED EVENTS”는 서로 다른 숫자이다. 범위가 다른 집계인지 정적 예시인지 미확인이다.

**스타일 제안과 기능사양의 경계:** 회색 표면·선의 굵기·로고 배치·캡슐 라벨은 시각 제안이다. 사건 모양, 라벨을 무엇에서 만들지, 중심 기업과 필터 범위, “크기=활동” 의미는 데이터/동작 계약에 걸친다. “HBM4 공급 계약” 같은 Figma 제목을 실제 뉴스의 검증된 사건 데이터로 이식하지 않는다.

**영향: 비용 큰 결정 + 확인 필요.** 현재 [DESIGN.md](../../prototype/web/DESIGN.md) 68–81행은 모든 노드를 원으로 하고 사건은 원+번개로, 기업은 상징색 채움으로 규정한다. graph-elements.ts 30–44·55–94행은 사건 target/label 축약과 간선 summary를 사용하며, graph-style.ts 73–121행은 원형 노드·배율별 라벨 규칙을 구현한다. Figma 표현을 정확히 따르려면 그래프 전체·기업 그래프·회차 그래프·모바일을 함께 설계하고 화면 맞춤/겹침/선택/접근성 규칙을 재검증해야 한다. CSS 몇 줄의 확정 소작업으로 잡지 않는다. “크기=활동”은 Figma 원문도 팀 확인 대상으로 적고 있으며 중요도·인과로 바꾸지 않는다.

### 2. 종목 탐색: 새 Figma 페이지는 생겼지만 제품 기능은 이미 존재

[종목 탐색 692-2](raw/wireframe_2026-10-08/frame-692-2.png)은 삼성 검색·시장 전체/내 종목·5개 결과·보유 표기·가격·상세/지도/관심 아이콘을 보여준다. 기존 [D-STK-01](../screen-plan/captures/D-STK-01.png) 및 companies-page.tsx 60–109행과 대응한다. Figma는 검색·결과 영역을 더 좁은 중앙 열로 모으고 선택/강조 행의 외곽선을 추가했다.

**소규모 확정:** 레이어 이름이 없어도 D-STK-01 대응을 등록할 수 있다. 기존 검색·지도 이동·관심 저장을 미구현 기능으로 다시 산정하지 않는다. 열 폭·행 밀도·선택 외곽선은 스타일 제안이다. 어떤 조작의 포커스/선택을 표현한 것인지는 미확인이고, 44px 대상 크기·키보드 복귀를 줄이지 않는다.

원본 03 페이지 안내는 D-STK-01 “파일에 없음”이라고 말하지만 실제 03.5 페이지의 692-2에 화면이 있다. 원문은 보존하고 현재 관찰이 그 안내의 누락 주장을 반박한다고 기록한다.

### 3. 기업 상세: 문서 탭 상태가 새로 보이며, 기업 정보는 데이터 필드가 확장됨

**배치:** [기업 요약 637-2222](raw/wireframe_2026-10-08/frame-637-2222.png), [차트 637-6212](raw/wireframe_2026-10-08/frame-637-6212.png), [시점 후보 658-8442](raw/wireframe_2026-10-08/frame-658-8442.png)는 좌측 기업 검색·보유/관심/최근/연결 목록, 중앙 시세·모의 보유·탭·차트, 우측 관계 그래프의 기존 3열 역할을 유지한다. Figma는 좌측 목록에 HOLDINGS/WATCH/RECENT/LINKED 보조 표제를 붙이고 선택 기업을 외곽선으로 강조하며 컨트롤을 흑백으로 정리한다. 새로운 기업 전환 API가 필요한 증거는 아니다.

**문서:** [663-14180](raw/wireframe_2026-10-08/frame-663-14180.png)에서 문서 탭이 선택되고 “근거 문서 10건”과 출처·발행 시각·기사 목록이 실제로 보인다. D-COM-02에 정적 1:1 대응이 가능하다. 반면 [Frame 658-7834](raw/wireframe_2026-10-08/frame-658-7834.png)는 인접 설명이 D-COM-02여도 화면은 사건 탭·차트다. 원본의 “문서 탭이 보이지 않음”은 이 옛 프레임에 대해서만 맞고 현재 페이지 전체에 적용하면 틀린다. 현재 company-page.tsx 327–369행에는 사건/문서/기업 정보 탭이 이미 있으므로 문서 탭 기능을 새 작업으로 잡지 않는다.

**기업 정보:** [663-13515](raw/wireframe_2026-10-08/frame-663-13515.png)는 정식 명칭·시장 세부구분·업종·대표·설립·홈페이지를 2열로 보여준다. 현재 company-page.tsx 394–410행은 종목 코드·시장 ID 접두사·다른 이름·업종의 실제 카탈로그 값만 표시한다. 기업 정보 탭이 없어서 생기는 문제가 아니라 **필드와 데이터 원천 계약이 다르다.** 정식 법인명·시장 세부구분·대표·설립·홈페이지의 공급자·갱신·누락 처리를 정해야 한다. Figma 값을 하드코딩하지 않는다. 새 공식 화면 ID는 없어 D-COM-01의 tab=info 상태로 연결하되 팀 ID 확정이 필요하다.

**시점/버킷:** 658-8442에 기간·관계 필터·최신 시점·가격 차트·사건 목록은 보이나 선택 버킷과 asOf 변경 결과가 보인다고 확정할 수 없다. 기존 계획의 D-COM-05/06은 후보 대응으로 남긴다. 현재 소스 300–305·343–359행에는 동일 asOf 그래프와 버킷/시점 콜백이 이미 있어 “Figma 독립 프레임 미확인”을 “기능 미구현”으로 바꾸지 않는다.

### 4. 로그인·초기 설정: 동선은 유지, 실제 소셜 제공자는 별도 계약

[Figma 로그인 619-1080](raw/wireframe_2026-10-08/frame-619-1080.png)은 기존 이메일 폼→회원가입→비회원 시작의 계층을 유지하면서 “구글 로그인”, “카카오톡 로그인” 두 버튼과 검은 주 CTA를 보여준다. 기존 [D-AUT-01](../screen-plan/captures/D-AUT-01.png)은 개발용 모의 로그인 버튼 하나와 모의 제공자 안내를 보여준다. login-page.tsx 105–115행은 서버의 providers 목록을 사용하며 development 안내를 표시한다.

**스타일 제안:** CTA 색·버튼 외곽·폼 밀도는 시각 차이다. **비용 큰 결정/확인 필요:** Google·카카오의 실제 provider 연결은 앱 등록·redirect·동의·검수 정보가 필요한 통합 작업이다. 버튼 존재를 연결 완료로 해석하지 않는다. 원문도 실제 소셜 연동 미확인을 명시한다. 검은 CTA/선택 스타일은 현재 DESIGN.md 54–56행의 딥 틸 사용 계약과 다르므로 시스템 색을 무승인 전면 교체하지 않는다.

투자 여부→선택적 가상 계좌→관심 종목의 분기는 원문과 화면계획서가 대응한다. 관심 0개 완료·계좌 건너뛰기는 여전히 기획 규칙이다. 4개 관심 상태와 모의 provider 동의는 독립 프레임을 찾지 못했다.

### 5. 브리핑·AI·판정 예시: 배치를 기능 완료로 오인하지 않음

출근/퇴근 날짜·회차 선택과 KOSPI/KOSDAQ/원달러·핵심 이슈·회차 지도 링크의 계층은 [기존 브리핑](../screen-plan/captures/D-BRF-01.png)과 Figma 620-948/1278이 대응한다. Figma는 중앙 본문·지표 수치·흑백 컨트롤의 밀도를 조정한 시각 제안이다. 05 페이지에 추가된 730-278 회차 지도는 03 페이지 619-10871의 D-BRF-04와 중복 후보이며 새 기능/새 화면 ID로 더하지 않는다.

AI 620-4314(D-AI-02)는 되묻기 대화가 보이나 저장 작업 복구 실행을 입증하지 않는다. 620-4859(D-AI-02b)에도 되묻기 대화가 보이고 오류·재조회 버튼은 보이지 않는다. **확인 필요:** 명명된 상태와 실제 정적 UI가 다르므로 오류 UI 완료 근거로 사용하지 않는다. 정적 배치가 동일하다는 이유로 실제 저장/복구 구현이 없다고 단정하지도 않는다.

D-SEN-01/02는 원문이 예시 전용이라고 명시한다. 실제 긍부정·전망 데이터나 모델 호출의 증거가 아니다. 원문에 “긍정·부정·혼합·보류”가 남아 있음을 보존한다. 사용자의 현재 명칭 결정인 긍정/부정을 우선 적용하되 혼재/판단보류 제거 결정으로 확대하지 않는다.

### 6. 모바일: 전/후 쌍 설명과 현재 실제 렌더가 어긋남

6개 모바일 그룹 각각을 선택해 캡처했다. 현재 렌더는 왼쪽 휴대폰 1개와 오른쪽 빈 영역이 보인다. 설명은 여전히 “전/후 쌍 1개 프레임”이라고 적지만 이번 증거는 **현재 보이는 상태 하나**만 뒷받침한다. 그룹 자체 확인과 설명상의 두 상태 확인을 분리한다.

특히 [M-GRP-01 620-5928](raw/wireframe_2026-10-08/frame-620-5928.png)은 선택 기업 시트 위 지도가 회색 빈 영역이며 기존 [M-GRP-01-after](../screen-plan/captures/M-GRP-01-after.png)의 실제 노드·간선이 보이지 않는다. 이를 의도한 단순화인지, 그래프 이미지가 빠진 것인지, 다른 상태로 옮긴 것인지 알 수 없다. 시트 제목·시세·하단 5탭 배치는 확인되지만 지도 정보 감소를 개선으로 평가하지 않는다. M-STK-01도 현재 휴대폰에 기업 상세 상태만 보여 목록→상세 전환 전체가 검증된 것은 아니다. M-BRF-01은 퇴근 선택 화면만 확인한다.

휴대폰 외곽틀·status bar는 문서 presentation 요소로 간주하며 실제 웹 앱에 추가할 요구로 해석하지 않는다. 본문 16px·보조 13px·44px 대상·키보드·시트 단계는 current DESIGN.md 계약을 유지한다. screenshot 축소 비율로 준수 여부를 판정하지 않는다.

### 7. 관리자: 9개 대응이 있으나 화면 스타일과 운영 계약은 별개

A-ADM 9개 ID는 Figma 레이어 이름·원문 경로·기존 slide-index 페이지 61–69와 일치한다. 대시보드의 상단 운영 지표→최근 브리핑/작업→AI 요청/이용 현황 구조는 [기존 A-ADM-01](../screen-plan/captures/A-ADM-01.png)과 대응하며 Figma는 폭·흑백 선택·외곽선을 바꾼다. 다른 운영 목록의 정적 배치는 확인했다. 새로운 파이프라인 실행·관리자 역할·회원 회수 기능이 추가됐다는 증거는 없다. 원문이 명시한 R1 승인·재검증·피드백 마스킹·권한 정책은 여전히 확인 대상으로 남긴다.

## 남는 증거·검증 요청

Main은 이 문서를 근거 인덱스에 등록하고 재산정에서 해결된 D-STK/문서 탭을 누락 기능으로 중복 집계하지 않으면 된다. 다음 팀 확인에는 (1) 그래프 의미·크기·라벨 데이터 규칙, (2) 기업 정보 공급 계약, (3) 실제 소셜 제공자 준비 상태, (4) 모바일 전/후와 지도 노드, (5) 버킷/asOf·AI 오류/복구의 상태 캡처를 함께 제시한다. 새 사용자 평가를 주장할 근거는 없다.

수집한 브라우저 탭은 종료했다. 소유 서버는 시작하지 않았다. 앱 코드·원본 var·화면계획서·고정본·근거 README는 변경하지 않았다. build/lint/test/formatter·웹 기능 검사를 실행하지 않았으며 런타임 검증 결과를 주장하지 않는다.
