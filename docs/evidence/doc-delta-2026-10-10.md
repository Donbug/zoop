## 4. 작업자 선택 (관측 아님)

- **현행/이력**: 목차가 가리키는 v2 시트(04·08)를 현행 상세로, 03·07을 이력으로 둔다. 목차 밖 ID가 이력·정정 목록에 없으면 생성기가 hard error를 낸다.
- **AI 번호 재사용**: 옛 046 권한·중복 작업 통제는 단일 신규 ID가 없다. 서버 공통 의무(대화 소유·근거 권한 재검증, 작업 ID 내용 불일치 거절, 같은 대화 동시 접수 하나, 조회/회수와 신규 접수의 구분)를 FS045·FS047·FS051·FS060과 NFS001/003, OpenAPI `aiJobs`로 보존했다. 옛 047~053의 의미는 현재 046~051로 이행했다. 이 보존이 팀 원문의 v2 상세에 반영돼 있다는 뜻은 아니며 AI 명세 담당자 확인을 요청한다.
- **API·WBS 재연결**: 번호 치환이 아니라 의미로 다시 연결했다(`createConversation`→FS050, 대화·작업 조회·재시도·취소→FS051, 근거 조회→FS049, `submitQuestion`→FS045~051). WBS 6.9.2~6.9.9 산출물의 옛 번호는 `rawSpecIds`에 남기고 업무명·역할·v2 상세로 편집 연결한다.
- **재무**: 목차 FS042는 시점 그래프이고 요구 42(재무·실적)는 최신 정의서에 그대로다. 새 FS·WBS 없이 `getCompanyFinancials`에 요구 번호로만 연결하고 유보로 표시한다. 담당·일정은 팀 결정 전까지 없음이다.
- **추천 기능**: `listRecommendations`는 삭제·무동작 대체 없이 유보하고 활성 기능·수용 범위에서 제외했다.
- **차트·시장 데이터 계약**: 1D=5m·1W=1h·1M=1d·1Y=1wk를 목표 계약으로 고정하고 정상 부재 200 `unavailable`(3개 사유)과 공급자 장애 503을 구분했다. 로컬 BFF의 같은 경계는 가짜 공급자 HTTP 40건으로 확인됐다(정확성 스모크). 저장된 BFF 관측본은 갱신하지 않았다.
- **NFS007**: 동시 사용자 수·응답시간 목표·오류율 합격 기준·부하 규모·표본 수의 숫자는 원문에 없다. 임의 수치를 팀 기준으로 승격하지 않는다.
