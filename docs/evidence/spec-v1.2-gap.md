## 3. 팀이 정해야 할 것

1. **자동 검수 규칙 R1@2와 FS059·D11.** FS059는 「자동 검증을 통과한 결과만 공개」를 요구한다. R1@2는 사람이 우회하는 것이 아니라 규칙이므로 FS067-02와 직접 충돌하지는 않는다. 하지만 PoC 검증기가 보류한 후보를 역할만 비워 공개하므로, R1을 「자동 검증 정책의 일부」로 볼지 팀 승인이 필요하다. 지금 R1은 사건 43건·기업 7곳의 공개를 좌우한다(`review-policy.md` §6). 승인되지 않으면 PoC 검증기에서 역할을 선택 필드로 바꾸는 안(재검증 유료)이 대안이다.
2. **명세가 「확인 필요」로 남긴 운영 값.** 로그인 반복 실패 제한(FS002), 가입 필드·약관 본문(FS003), 소셜 제공자·계정 연결(FS004), 튜토리얼 건너뛰기를 완료로 볼지(FS016), 핵심 이슈 중요도 점수·동점 규칙(FS030), 브리핑·대화·작업 보존 기간(FS035·FS060·NFS003·NFS008), 사건 병합 기준(FS056), 관리자 권한 등급·대화록 열람 범위·마스킹 목록(FS066-03·FS067-02·FS073·NFS001), 성능 목표·지원 브라우저·접근성 점검표(NFS007·NFS010·NFS011).
3. **개인화 브리핑(FS036, P2)**: 생성 조건·대상 수·재사용 기준이 미정이라 착수하지 않았다.

## 4. 데이터·외부 연동이 막는 것

- **시장 요약·시장 변수(FS028·FS029·FS031·FS033)**: 생산자가 없다. 브리핑은 승인 사건 선정까지만 한다.
- **재무·실적(FS042)**: 매출·영업이익 추이 등 재무 자료 공급자가 없다. 현재는 네이버 증권 지표(시가총액·PER 등)만 표시한다.
- **생성형 AI 답변(FS025·FS045–FS053)·뉴스 요약 평가(FS066-01)**: 챗봇은 승인 근거를 인용하는 규칙 기반 예시 답변이며 모델을 호출하지 않는다. 작업 모델(§2 FS053)은 모델 없이도 먼저 만들 수 있다.
- **추천 산업·테마(FS011-02)**: 분류 데이터가 없다. 추천은 승인 사건 수 기준 기업만 근거와 함께 보여 준다.
- **실제 소셜 IdP(FS004·FS061)**: 개발용 모의 제공자만 있다.
- **정기 수집 05·35분과 10·40분 반영 보장(FS058·FS059·NFS012)**: 수집은 관리자 수동 작업(`ingest-run`)이다. 자동 정기 수집·반영 확인 파이프라인이 없다.
- **시세(FS063)**: 명세는 토스 API를 지정한다. 토스증권 Open API 약관 제5조 ③항은 시세를 「개인투자자 본인의 매매 목적에 한하여」 이용하고 제3자 제공·배포를 금지하므로, 여러 사용자에게 보여 주는 서비스의 시세 출처로 쓰려면 별도 확인이 필요하다(현재는 Yahoo·네이버 공개 자료).
