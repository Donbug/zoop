## PoC 백엔드가 줄 수 있는 것과 없는 것

- **있음:** 뉴스 수집 → 사건(Issue) 추출·중복 판별 → 기업 관계 후보 → 원문 인용 검증(Jev) → 승인 원장(PostgreSQL) → Neo4j 투영. 간선 5종: `REPORTS`, `PROVIDES_BACKGROUND`(기사→이슈), `INVOLVES`, `STRUCTURALLY_RELATED_TO`(이슈→기업), `FOLLOWS`(이슈→이슈). 근거는 `Evidence(article_id, article_version, start, end, quote)`로 원문 구간과 일치한다.
- **없음:** HTTP API, 인증·계좌·관심종목, AI 요약, 긍·부정 감성, 브리핑, 시세, 기업–기업 승인 간선. 검증기의 확률은 감성 점수가 아니다.
- **연동 계약:** `PostgresRepository.inspect()`가 반환하는 `{issues, candidates, errors}` 형태가 PoC의 실질적 읽기 계약이다. CLI `poc inspect --with-evidence --output FILE`도 같은 형태를 낸다.

## 프로토타입이 채택하는 가정

미정 사항 때문에 작업이 멈추지 않도록 아래를 **프로토타입 한정 가정**으로 둔다. 2026-10-01 저녁부터 기능 기준은 [기능·비기능명세서 v1.2 고정본](raw/functional-spec_2026-10-01/00-명세-목차.csv)(명세 ID `FS…`·`NFS…`)이다. 명세의 「확인 필요 사항」으로 남은 값은 아래 가정을 유지하고, 팀 결정이 나오면 교체한다.

1. API 경로는 명세 v0.2 §8 초안(`/api/graph`, `/api/companies/{id}`, `/api/events/{id}`, `/api/evidence/{id}`, `/api/briefings`, `/api/me/settings`, `/api/portfolio` 등)을 기본으로 하고, 정의서 구현에 필요한 경로(가입·소셜·관리자 `/api/admin/*`·계측·피드백·기업 문서)를 더했다. 전체 목록은 BFF `/openapi.json`과 [BFF README](../../prototype/bff/README.md)에 있다.
2. 그래프·이슈·근거는 PoC의 실제 승인 데이터(`inspect()`)에서 가져온다. 사용자에게는 관리자가 게시한 **그래프 버전**(첫 기동 때 스냅샷이 v1)에 관리자 검수 기록을 덮어 보여 주고, 응답 `metadata.graphVersion`에 버전을 적는다. `datasetKind`는 실제 기사 스냅샷(`approved-snapshot`)과 합성 미리보기(`synthetic-preview`)를 구분한다.
3. 인증·계좌·관심종목·AI 예시 답변은 PoC에 생산자가 없으므로 BFF가 맡는다. 회원·세션·설정은 BFF SQLite(`ZOOP_STATE_DIR`)에 저장한다. 소셜 로그인은 실제 제공자가 정해지지 않아 **개발용 모의 제공자**로 흐름만 구현했다(화면에 표시). 가상 계좌는 명세대로 모의 데이터다.
4. 요약·감성·시세·재무·산업·테마는 생산자가 생기기 전까지 만들지 않는다. 해당 값의 자리와 "준비 중" 라벨은 숨기고 값을 지어내지 않는다(기업 상세의 주가 차트·재무, 이슈의 긍정·부정 해석 포함).
5. 기업–기업 연결은 승인 간선이 아니므로 "같은 이슈를 공유"하는 파생 경로로만 표시하고 실선 관계처럼 보이지 않게 한다. 관계 유형(공급·고객 등)은 표시하지 않는다.
6. 온보딩은 정의서 8–16을 따른다. 투자 여부를 먼저 묻고, 관심종목은 **개수 무제한·0개 허용**이다. 튜토리얼은 실제 지도 위 5단계이며 건너뛸 수 있고, 비회원도 같은 튜토리얼을 거친다. 가입 후에는 자동 로그인 뒤 초기 설정으로 간다(DEC01 미결정).
7. 브리핑은 정의서 26–33을 따른다. 발행 예정 시각은 07:40/18:10 KST이고, 회차는 발행 후 바꾸지 않는다. 핵심 이슈는 최대 3개이며 부족하면 채우지 않는다. 오류는 정정으로 덧붙이고, 원문은 그대로 남긴다. 예측·상승 확률 문구는 넣지 않는다.

## 초기 실제 연동·실험 결과 (엄격 정책)

프로토타입 실행법과 검증 기록은 [prototype/README.md](../../prototype/README.md), 디자인은 [디자인 방향](../design/design-direction.md), 근거가 된 외부 조사는 [UX 리서치](../research/design-ux-research.md)에 있습니다.

실제 뉴스 19건 중 전체 원문이 있는 18건을 별도 DB에서 실행했습니다. 최종 승인 사건 1개·인용 1건·승인 기업 연결선 0개입니다. 후보 65개 중 64개가 보류 상태이며 마지막 배치에 미처리 4건이 남았습니다. 세 배치는 모두 오류로 종료 코드 1을 반환했습니다. 승인 기준을 낮추거나 보류 관계를 화면에 보충하지 않았습니다.

보고된 모델 사용량은 600회, 입력 7,896,703토큰·출력 577,694토큰입니다. 실제 과금액은 미제공입니다. 추가 유료 재시도는 중단했습니다. 구체적인 오류·출처 이용 제약·스냅샷 경로는 [PoC 조사 §8](poc-backend.md#8-실제-뉴스-라이브-실행)에 있습니다. **화면 연동 성공과 뉴스 처리 파이프라인 전체 성공은 별개입니다.**

## v3 완화 정책·현재 시연 데이터

사용자 승인에 따라 지지 문턱을 0.90→0.65, 모순 허용 문턱을 0.05→0.10으로 바꾸고 독립 웹 확인을 필수 조건에서 제외했다. 원문 인용 위치와 출처 이용 권한 검사는 유지했다. 상세한 정책 버전·사용량·오승인 점검은 [PoC 조사 §9](poc-backend.md#9-완화-정책-재판정)를 참조한다.

현재 공개 시연은 검수한 **실제 기사 스냅샷**이다. BFF `/api/graph` 확인 결과 사건 31개 + 연결된 기업 3개 = **34노드**, 직접 관련 17개 + 사건 공유 파생 경로 1개 = **18개 연결**이다. 기업 카탈로그는 14개지만 나머지 기업의 연결을 임의로 만들지는 않았다. 기본 전체 조회에 `depth=null`, `truncated=false`임을 확인했다.

확인된 후속 관계 오승인 1개는 `review_exclusions` 기록과 함께 공개 스냅샷에서 제외했다. 실험 DB에는 아직 남아 있으므로 검수 스냅샷과 구별한다. 승인 문턱 완화는 오승인 위험을 높일 수 있으며 정확도 검증 완료를 뜻하지 않는다.
