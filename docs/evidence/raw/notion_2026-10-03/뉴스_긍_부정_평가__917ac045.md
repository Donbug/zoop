### 분석 단위를 이슈 X 기업 으로 잡기
이슈x기업 별 기대와 우려를 분석하여 실제 주가 흐름과 함께 보여준다.
- 핵심은 뉴스가 긍정적인 것인지, 기업에 유리하다는 것인지, 주가가 상승한다는 것인지 구분해야함. 
- 무엇의 긍정 부정인지 먼저 정의
  | 분석값 | 의미 | 화면 표현 |
  | **뉴스 기반 사업 영향 해석** | 해당 기업의 매출·원가·생산·경쟁 환경에 대한 기대와 우려 | 기대 요인 / 우려 요인 |
  | **커뮤니티 반응** | 수집한 게시물에서 나타나는 낙관·비관 의견 | 수집 게시물의 반응 분포 |
  | **실제 가격 변화** | 정해진 기간의 관측된 수익률 | 최근 1일·5일 등락률 |
- 긍/부정 비율 계산
  - **대상:** 특정 이슈에 연결된 특정 기업.
  - **기간:** 최근 7일 등 명시한 기간.
  - **단위:** 전재·복제를 묶은 기사 그룹별 기업 영향 판정.
  - **분류:** 긍정·부정·혼재·중립·판단 불가.
  - **근거:** 각 판정의 원문 구간.
- 그래프에서는 ‘방향’보다 ‘해석과 변화’ 보여주기

  **분석:**매출 기회에 관한 긍정 해석 우세

### 뉴스·투자자 의견·주가 반응 분석 방향 제안
# 뉴스·투자자 의견·주가 반응 분석 방향 제안
> **핵심 방향:** 뉴스에 담긴 긍정·부정 요인, 사람들이 이를 해석하는 방식, 실제 주가 움직임을 각각 분석하고 연결한다.
세 결과를 하나의 점수로 합쳐 주가 방향을 단정하지 않고, **무엇이 확인됐고 무엇이 아직 설명되지 않는지** 보여준다.
### 1. 먼저 전체 방향 이해하기
### 무엇을 분석하고 보여줄 것인가?
| 구분 | 핵심 질문 | 분석 방법 | 사용자에게 제공할 결과 |
| **① 뉴스·공시 분석** | 어떤 기업에 어떤 사건이 발생했고, 어떤 긍정·부정 요인이 있는가? | LLM으로 기업·사건·주장·비교 기준·근거 문장 추출 | 기업·사건별 긍정·부정 요인과 원문 근거 |
| **② 투자자 의견 분석** | 사람들은 해당 사건의 어떤 부분을 어떻게 해석하는가? | 의견을 세부 사건·주장에 연결하고 평가·전망 구분 | 수집된 의견의 주요 해석과 의견 차이 |
| **③ 시장 움직임 확인** | 해당 시점 전후에 가격·거래량이 어떻게 변했는가? | 미리 정한 구간의 시세 데이터 계산 | 수익률·거래량 변화 등 관측 결과 |
| **④ 통합 제공** | 세 결과가 어떻게 연결되며, 어디까지 설명할 수 있는가? | 시점·대상·근거를 대조 | 확인된 사실, 해석 후보, 확인되지 않은 부분 |
**뉴스의 세부 요인을 분석하는 것과 ‘감성분석 → 주가 방향’ 연결을 재설계하는 것은 충돌하지 않는다.**
전자는 기사 해석을 개선하는 작업이고, 후자는 그 해석을 가격 예측으로 잘못 확장하지 않도록 하는 작업이다.

### 2. 왜 이 구조가 필요한가?
기존의 단순한 방식에는 다음과 같은 문제가 있다.
| 단순한 접근 | 발생할 수 있는 문제 | 개선 방향 |
| 기사 하나에 긍정 또는 부정 하나만 부여 | 한 기사에 함께 있는 상반된 요인을 놓침 | 기업·사건·평가 항목별로 구분 |
| 긍정적인 의견이 많으면 좋은 뉴스라고 판단 | 사람들의 기대를 사실 판단과 혼동 | 기사 내용과 의견을 별도 기록 |
| 긍정 기사·댓글 비율로 상승 가능성 제시 | 비율을 상승 확률로 해석할 근거가 없음 | 정보 분포로만 제공하고 예측과 분리 |
| 주가가 올랐으므로 뉴스도 긍정으로 수정 | 결과에 맞춰 과거 해석을 바꾸게 됨 | 최초 분석을 보존하고 추가 근거를 별도 기록 |
| 뉴스 이후 주가가 움직였으므로 원인이라고 설명 | 같은 시점의 다른 요인이나 시간 순서를 놓침 | 관련 시점의 움직임과 인과관계를 구분 |
목표는 모든 주가 움직임에 이유를 붙이는 것이 아니라, **사용자가 여러 근거를 비교하고 확인할 수 있도록 만드는 것**이다.

### 3. 방안 1 — 뉴스에서 기업·사건별 요인 추출
### 3.1 단순 문장 분할이 아니라 ‘의미 단위 구조화’
LLM이 전체 문맥을 읽고, 기사 안의 서로 다른 사건·주장·비교 기준을 구분한다.
문장만 잘라 따로 분석하면 앞뒤에 있는 조건, 부정 표현, 예상치 비교 등을 놓칠 수 있으므로 **원문 문맥과 근거 위치를 함께 보존**한다.
### 3.2 예시
아래는 설명을 위한 **가상의 기사**다.
> A기업의 영업이익은 전년 대비 20% 감소했다. 다만 시장이 예상한 40% 감소보다는 양호했다. 회사는 다음 분기 수익성 개선을 전망했다.
| 추출 항목 | 대상·비교 기준 | 분석 결과 | 정보의 성격 |
| 영업이익 20% 감소 | A기업 실적 / 전년 대비 | 실적 감소라는 부정 요인 | 기사에 제시된 실적 수치 |
| 예상한 40% 감소보다 양호 | A기업 실적 / 사전 예상 대비 | 예상치 상회라는 긍정 요인 | 예상치 출처 확인 필요 |
| 다음 분기 수익성 개선 전망 | A기업 수익성 / 미래 기간 | 긍정적 전망 | 회사의 전망이며 실현된 사실은 아님 |
**전체 기사를 하나의 긍정·부정으로 압축하지 않고, 각 요인을 유지한다.**
### 3.3 저장할 주요 항목
| 항목 | 저장 목적 |
| 대상 기업·사건 ID | 무엇에 관한 정보인지 식별 |
| 주장과 평가 항목 | 매출·비용·생산·수익성 등 구분 |
| 비교 기준·대상 기간 | 전년 대비인지, 예상 대비인지 구분 |
| 사실·전망·의견 및 발언 주체 | 회사의 전망을 확정 사실처럼 처리하지 않기 |
| 긍정·부정·중립·판단 불가 | 근거가 부족할 때 억지로 분류하지 않기 |
| 원문 근거·출처·위치 | 분석 결과를 사용자가 확인할 수 있게 하기 |
| 사건 공개 시각·기사 게시 시각 | 정보가 알려진 순서와 재보도 여부 확인 |
※ ‘판단 불가’는 ‘중립’과 다르다. 중립은 방향성이 없다는 해석이고, 판단 불가는 판단할 정보가 부족한 상태다.

### 4. 방안 2 — 사람들의 의견을 세부 사건에 연결
### 4.1 목적
커뮤니티 의견은 **뉴스의 정답을 결정하는 자료가 아니라, 해당 사건을 사람들이 어떻게 해석하는지 보여주는 자료**로 사용한다.
따라서 방안 2는 방안 1의 대체재가 아니라 보완 기능이다.
### 4.2 의견도 하나의 감성으로 압축하지 않는다
앞의 가상 기사에 다음 의견이 있다고 가정한다.
> “실적 자체는 별로지만, 예상보다는 덜 나빠서 주가는 오를 것 같다.”
| 의견의 세부 내용 | 연결 대상 | 분류 |
| 실적 자체는 별로다 | 전년 대비 영업이익 감소 | 실적에 대한 부정 평가 |
| 예상보다는 덜 나쁘다 | 예상치 상회 | 예상 대비 긍정 평가 |
| 주가는 오를 것 같다 | 향후 주가 | 작성자의 상승 전망 |
이렇게 하면 **사람들이 어느 부분에는 동의하고, 어느 부분에서는 해석이 갈리는지** 보여줄 수 있다.
### 4.3 수집·분석 원칙
- 기사 링크나 구체적인 사건 내용으로 **대상이 명확한 의견부터 연결**한다.
- 같은 종목을 언급했다는 이유만으로 같은 사건에 연결하지 않는다.
- 중복·홍보성 게시글을 관리하고, 대상이 불분명하면 연결을 보류한다.
- 수집 플랫폼·기간·의견 수를 표시한다.
- 의견이 없으면 ‘반응 자료 없음’으로 표시한다.
- 다수 의견을 사실의 정답이나 전체 시장의 생각으로 표현하지 않는다.
표현 예시:
> **“투자자들은 긍정적으로 판단했다”가 아니라,“해당 기간에 수집된 의견에서는 예상치 상회를 긍정적으로 해석하는 반응이 나타났다.”**

## 5. 주가 데이터는 어떻게 연결하는가?
### 5.1 가격 움직임을 별도로 계산한다
| 지표 | 의미 |
| 수익률 | 정해진 구간에 가격이 얼마나 상승·하락했는가 |
| 거래량 변화 | 평소 또는 정해진 비교 구간보다 거래가 얼마나 늘거나 줄었는가 |
| 변동성 | 정해진 구간에서 가격이 얼마나 크게 흔들렸는가 |
기사 분석과 가격 계산을 분리하고, **가격 결과에 맞춰 기사 분석을 자동으로 바꾸지 않는다.**
비교 구간도 결과를 보고 유리하게 선택하지 않고 사전에 정한다. 장중·장후 발표를 구분하고, 필요한 시각 데이터가 없으면 분석 범위를 제한한다.
### 5.2 분석 결과와 가격 방향이 다를 때
| 확인 순서 | 점검 내용 |
| ① 기사 해석 확인 | 대상 기업, 예상치 비교, 조건·부정 표현 등을 놓쳤는가? |
| ② 시간 순서 확인 | 주가 변동 후 나온 기사나 의견을 원인처럼 사용했는가? |
| ③ 다른 자료 대조 | 동시기 공시·뉴스·시장 움직임 등 추가 근거가 있는가? |
| ④ 설명 범위 결정 | 근거가 있는 설명 후보만 제시하고, 확인되지 않은 원인은 남겨둔다. |
**설명하지 못하는 부분이 있다고 전체 결과를 버리는 것은 아니다.**
확인된 사실은 제공하고, 원인·기여도처럼 확인하지 못한 부분만 판단을 보류한다.

## 6. 사용자에게 보이는 최종 결과
다음은 **출력 형식 예시**이며 실제 분석 결과가 아니다.
| 화면 영역 | 제공 내용 |
| **기사에서 확인한 요인** | 실적 감소 / 예상치 상회 / 회사의 수익성 개선 전망 |
| **수집된 의견** | 실적 감소를 우려하는 해석과 예상치 상회를 긍정적으로 보는 해석 |
| **관측된 시장 움직임** | 미리 정한 발표 전후 구간의 수익률·거래량 변화 |
| **설명 후보** | 근거가 확인된 경우에만 예상치 상회 등의 해석 제시 |
| **확인되지 않은 부분** | 해당 사건이 가격 변화에 기여한 정도, 단독 원인 여부 |
| **근거 확인** | 원기사·공시·의견·시세의 출처와 기준 시각 |
그래프에서는 **기사 → 사건 → 기업**, **의견 → 해당 사건·주장**을 연결한다.
가격 변화는 별도 관측 정보로 연결하며, **그래프에 연결선이 있다는 것 자체가 영향이나 인과관계의 증명은 아니다.**

## 7. 구현 우선순위와 검증 방향
아래는 팀 논의를 위한 **우선순위 제안안**이다.
| 단계 | 구현 범위 | 검증할 내용 |
| **1단계: 핵심** | 뉴스·공시에서 기업·사건·복수 요인·근거 추출 | 상반된 요인을 놓치지 않는가? 원문에 없는 주장을 만들지 않는가? |
| **2단계: 핵심** | 시점 관리와 가격 데이터 비교 | 사건·기사 시각과 가격 측정 구간이 맞는가? 계산이 정확한가? |
| **3단계: 확장** | 대상이 명확한 투자자 의견 연결 | 의견이 올바른 사건에 연결되는가? 평가와 가격 전망을 구분하는가? |
| **별도 검토** | 향후 상승·하락 예측 | 시간순으로 분리한 미사용 데이터에서도 예측 성능이 유지되는가? |
초기에는 소규모 기사 표본을 팀원이 독립적으로 검토해 기준을 맞추고, 자동 분석 결과와 비교한다. 다만 **팀원 간 합의가 전문가 수준의 금융 판단을 보증하는 것은 아니므로**, 우선 원문 일치와 연결 정확성처럼 확인 가능한 항목부터 검증한다.
참고할 연구로는 기업·사건 단위 분석을 다루는 [EFSA](https://aclanthology.org/2024.acl-long.402/)와 투자자 게시글의 감정을 다루는 [StockEmotions](https://arxiv.org/abs/2301.09279)가 있다. 두 연구는 서로 다른 분석 대상을 설계하는 참고자료이며, 우리 서비스의 성능은 별도 검증이 필요하다.

## 최종 정리
| 단계 | 한 문장 요약 |
| **읽는다** | 기사에 어떤 기업·사건·긍정·부정 요인이 담겼는지 추출한다. |
| **연결한다** | 각 요인과 기업, 해당 요인에 대한 사람들의 의견을 연결한다. |
| **비교한다** | 정보가 공개된 순서와 실제 시장 움직임을 대조한다. |
| **설명한다** | 확인된 사실과 해석 후보를 제시하고, 모르는 부분을 구분한다. |
> **우리가 만들려는 것은 ‘긍정 뉴스가 많으니 오른다’고 알려주는 서비스가 아니다.**
**같은 사건에 어떤 요인이 있고, 사람들이 무엇을 다르게 해석하며, 실제 시장에서는 무엇이 관측됐는지를 근거와 함께 보여주는 서비스다.**
### 외부 자료들을 이용해서 자료준비를 어떻게 할지에 관한 대답
### **관심 종목과 연결된 사건을 추적하고, 연결 이유·변경 사항·상반된 해석을 근거와 함께 보여주는 서비스**
**감성분석은 핵심 서비스 자체가 아니라, 사건을 설명하는 보조 기능으로 사용하고, 커뮤니티 의견은 다음 단계에 붙이는 방향**이야.
# 1. 최종 방향성
> **내 관심 종목과 관련된 사건은 무엇이고, 이전과 무엇이 달라졌으며, 왜 관련 있는지를 확인하는 금융 정보 탐색 서비스**
사용자가 답을 얻어야 하는 질문은 네 가지야.
| 사용자 질문 | 제공할 기능 |
| **내 종목과 무슨 관계야?** | 사건 → 제품·거래처·산업 → 관심 기업의 연결 경로와 근거 |
| **전에 읽은 내용과 뭐가 달라졌어?** | 동일 사건 기사 묶기, 변경·정정·후속 진행 표시 |
| **좋은 요소와 나쁜 요소가 각각 뭐야?** | 기업·사건·비교 기준별 긍정·부정 요인 |
| **실제로 시장에서는 어떻게 움직였어?** | 정해진 구간의 가격·거래량 변화와 시장 대비 움직임 |
이렇게 정하면 뉴스의 긍부정과 주가가 반대로 움직여도 서비스의 가치가 사라지지 않아. **우리가 약속하는 것은 근거 있는 정보 연결과 비교이며, 모든 가격 움직임의 원인을 확정하는 것이 아니기 때문**이야.
### 이번 MVP의 범위 제안
| 기능 | 판단 | 이유 |
| 기업·사건 추출 및 근거 연결 | **핵심** | 관계도를 만드는 기반 |
| 동일 사건 묶기·후속 변화 추적 | **핵심** | 사용자의 반복 확인 부담을 줄임 |
| 사건별 긍정·부정 요인 | **포함** | 사건을 이해하는 보조 정보 |
| 가격·거래량 비교 | **포함** | 텍스트 분석과 실제 관측 결과를 분리해서 제공 |
| 커뮤니티 의견 분석 | **후속 확장** | 수집 가능성과 사건 연결 정확도를 먼저 확인해야 함 |
| 상승 확률·매수/매도 추천 | **이번 MVP 제외** | 별도의 예측 검증이 필요한 기능 |

# 2. 앞에서 이야기한 방안들을 어떻게 적용할까?
## 전체 처리 과정
| 순서 | 수행할 작업 | 적용 방법 | 결과물 |
| ① 수집 | 뉴스·공시·시세 확보 | 출처, 게시 시각, 수집 시각을 함께 저장 | 원자료 |
| ② 구조화 | 기업·사건·주장·수치 추출 | LLM이 전체 문맥을 읽고 구조화된 형식으로 반환 | 사건 후보와 원문 근거 |
| ③ 사건 연결 | 같은 사건인지, 후속 사건인지 확인 | 기업·상대방·제품·날짜·금액 비교. 유사도는 후보 검색에 활용 | 사건 묶음·진행 이력 |
| ④ 요인 분석 | 긍정·부정 요인 구분 | 누구에게, 무엇에 대해, 어떤 기준인지 명시 | 사건별 요인 |
| ⑤ 검증 | 원문과 결과 대조 | 근거 위치·수치·대상·시점 검사. 애매한 관계는 보류 | 검증 상태가 붙은 결과 |
| ⑥ 저장·조회 | 관계 탐색 지원 | Neo4j에 기업·사건·문서와 근거 있는 관계 저장 | 조회 가능한 관계망 |
| ⑦ 시장 비교 | 가격·거래량 움직임 확인 | 미리 정한 구간의 데이터를 코드로 계산 | 관측 결과 |
| ⑧ 제공 | 사건 카드·관계도·타임라인 표시 | 사실·해석·미확인 사항 분리 | 사용자 화면 |
여기서 역할을 명확히 해야 해.
- **LLM:** 문서에서 사건·주장·관계 후보와 근거를 추출한다.
- **벡터 검색:** 비슷한 사건·문서를 찾아 비교 후보를 좁힌다.
- **검증 로직:** 수치·시점·원문 일치 등을 검사한다.
- **그래프 DB:** 검증 상태가 붙은 관계를 저장하고 탐색한다.
**벡터 유사도가 높다고 동일 사건으로 확정하지 않고, 그래프 DB에 저장됐다고 사실로 확정하지 않는 구조**가 중요해.
## 커뮤니티는 어디에 붙이나?
기사와 사건을 연결하는 기반이 만들어진 다음에 붙여.
> 의견 수집 → 대상 사건 확인 → 의견의 주장·입장 추출 → 해당 사건에 연결
예를 들어 ‘공급 계약 체결’ 사건에 다음을 별도로 보여주는 거야.
- 계약 규모를 긍정적으로 평가하는 의견
- 수익성을 우려하는 의견
- 주가 상승을 예상하는 의견
이것들을 투표처럼 합쳐 **“이 계약은 긍정적이다”라는 정답으로 만들지는 않아.**

# 3. 언급한 연구·데이터셋은 어디에 쓰면 되나?
**이 자료들은 최신 뉴스를 대신하는 데이터가 아니라, 추출 기준·모델·평가 방법을 만드는 참고자료야.** 전부 넣고 학습시키는 방식부터 시작할 필요는 없어.
| 자료 | 무엇을 다루나? | 우리 프로젝트에 적용할 방법 | 주의점 |
| **[EFSA](https://aclanthology.org/2024.acl-long.402/)** | 기업·산업·사건·감성을 함께 분석하는 연구와 중국어 뉴스 데이터 | **사건별 요인 추출 구조와 라벨 기준 설계에 우선 참고** | 중국어 데이터이므로 한국어 서비스 성능은 따로 검증 |
| **[FinEntity](https://github.com/yixuantt/FinEntity)** | 금융 문서 안의 개별 기업·대상별 감성 | 한 기사에 여러 기업이 등장할 때 **대상별 감성을 구분하는 평가 방식** 참고 | 사건·시점·비교 기준까지 모두 해결해주는 것은 아님 |
| **[StockEmotions](https://arxiv.org/abs/2301.09279)** | StockTwits의 영어 댓글 1만 건과 투자자 감정 | 커뮤니티 분석 단계에서 **감정 라벨 설계와 모델 비교**에 참고 | 어떤 기사·사건에 대한 의견인지 연결하는 작업은 별도로 필요 |
| **[KR-FinBERT-SC](https://huggingface.co/snunlp/KR-FinBert-SC)** | 한국어 금융 감성분석 모델 | LLM 방식과 비교할 **기본 비교 모델**로 사용 | 사건 추출·근거 검증까지 수행하는 모델은 아님 |
| **[FinRED — 관계 추출 데이터셋](https://github.com/soummyaah/FinRED)** | 금융 뉴스·실적발표 자료에서 대상 간 관계 추출 | 기업·인물·조직 등의 **관계 유형과 추출 평가 방식** 참고 | 데이터셋 관계 종류와 우리가 원하는 공급망 관계가 일치하는지 확인 필요 |
| **[FinCausal](https://aclanthology.org/2022.fnp-1.16/)** | 금융 문서에서 원인·결과로 서술된 내용 추출 | “원가 상승으로 이익 감소”처럼 **문서에 명시된 설명을 구조화** | 문서가 주장한 인과관계 추출이지, 실제 시장 인과관계의 증명은 아님 |
### 내가 추천하는 사용 순서
1. **EFSA를 참고해 우리 출력 형식과 분류 기준을 만든다.**
1. **한국어 기사에 LLM을 적용하고, KR-FinBERT-SC와 비교한다.**
1. **관계 추출이 부족한 부분에 FinRED 등의 설계를 참고한다.**
1. **커뮤니티 기능을 개발할 때 StockEmotions를 검토한다.**
외국어 데이터를 번역해 참고 사례로 쓸 수는 있지만, **자동 번역한 라벨을 그대로 한국어 평가 정답으로 사용하지는 않는 게 좋아.** 원문과 번역의 의미를 검토해야 해.
또한 실제 학습·배포 전에 자료별 라이선스와 원문 이용 조건을 확인해야 해. 공개 저장소에 있다는 것만으로 모든 사용이 허용되는 것은 아니야.

# 4. 감성분석과 커뮤니티 외에 더 적용할 만한 방법
나는 아래 방법들이 우리 서비스에서는 **감성 점수 자체보다 우선순위가 높을 수 있다**고 봐.
| 방법 | 답할 수 있는 질문 | 적용 방식 | 우선순위 |
| **① 신규 정보·변경 탐지** | 이 기사에서 새로 나온 내용은 무엇인가? | 이전 사건 기록과 비교해 금액·기간·상태·상대방 변경 추출 | **최우선** |
| **② 발표 사실과 해석 구분** | 계약이 확정됐나, 협의 중인가, 누군가의 전망인가? | 사실·전망·의견, 발언 주체, 조건 표현 분류 | **최우선** |
| **③ 원출처 대조** | 기사 내용이 공시와 일치하나? | 동일 사건의 공시·기업 발표와 수치·조건 비교 | **높음** |
| **④ 예상 대비 분석** | 실적이 나쁜데 왜 긍정적으로 해석할 수 있나? | 실제 발표값과 **발표 전** 예상치를 같은 기준으로 비교 | 자료 확보 시 적용 |
| **⑤ 시장·업종 대비 비교** | 이 기업만 움직였나, 시장 전체가 움직였나? | 같은 기간 종목과 비교 지수의 등락률을 나란히 제시 | **높음** |
| **⑥ 주장에 대한 입장 분석** | 사람들은 무엇에 동의하거나 반대하나? | 의견의 감정뿐 아니라 특정 주장에 대한 동의·반대·유보 분류 | 커뮤니티 단계 |
### 특히 추천하는 것은 ‘사건의 변화 추적’이야
아래는 **가상의 예시**야.
| 시점 | 확보한 정보 | 사용자에게 보여줄 변화 |
| 처음 | A기업과 B기업이 공급 협의 중 | 아직 계약 확정 아님 |
| 이후 | 공급 계약 체결 공시 | **협의 → 체결** |
| 이후 | 계약 금액 수정 | **금액 변경과 정정 사유** |
| 이후 | 계약 종료 발표 | **관계 종료 및 기존 정보 갱신** |
이 기능은 주가를 맞히지 않아도 가치가 있어. 사용자는 **예전 뉴스를 지금도 유효한 사실로 오해하지 않고, 새롭게 확인할 내용을 찾을 수 있으니까.**
단, 이후에 나온 기사라는 이유만으로 후속 사건으로 연결하면 안 돼. 같은 계약인지 식별 근거를 확인해야 해.
또 ‘예상 대비 분석’은 유용하지만, **Toss나 DART에 필요한 예상치가 모두 있다고 가정하면 안 돼.** 발표 전에 존재했던 예상치의 출처와 접근 가능성을 먼저 확보해야 해.

| 3 | 기업·사건·근거·시점·비교 기준·변경 사항을 사람이 표시 | 검토용 기준 데이터 |

평가는 두 축으로 나누면 돼.
- **기술 품질:** 사건 추출, 동일 사건 연결, 관계·근거 정확성, 근거 없는 설명 비율
- **사용자 가치:** 관련 이유를 제대로 이해하는지, 변경 사항을 더 빨리 찾는지
같은 사건의 비슷한 기사들이 개발용과 평가용에 나뉘면 성능이 과대평가될 수 있으니, **사건 단위로 평가 데이터를 분리**하는 게 좋아.

## 최종 추천안
> **핵심:** 기업·사건 관계 + 원문 근거 + 변경 사항 추적
**보조:** 사건별 긍정·부정 요인 + 실제 시장 움직임
**확장:** 투자자 의견과 해석 차이
**별도 과제:** 향후 주가 방향 예측
팀에 한 문장으로 설명한다면:
**“우리는 뉴스가 좋은지 나쁜지만 판단하는 것이 아니라, 내 종목과 왜 연결되고 이전과 무엇이 달라졌는지를 근거로 확인하게 만드는 서비스를 개발한다.”**
