  이번에는 **기존 FS001~FS005를 그대로 유지하고, 각 기능 안에 검증·처리·분기·예외를 상세하게 작성**했어. 엑셀 파일은 수정하지 않았어.
  기존 문서에 없는 내용은 `[확인 필요]`로 구분했어. 아래의 **수용 기준은 구현 결과를 확인할 기준**이지, 이미 테스트를 통과했다는 의미는 아니야.
  ## FS001 — 서비스 시작 방식 선택
  | 항목 | 명세 |
  | 기능 ID | FS001 |
  | 기능명 | 서비스 시작 방식 선택 |
  | 기능 설명 | 사용자가 서비스 시작 화면에서 이메일 로그인, 이메일 회원가입, 소셜 로그인, 비회원 시작 중 원하는 이용 방식을 선택한다. 선택한 방식에 해당하는 화면 또는 절차로 연결한다. |
  | 선행조건 | 사용자가 서비스 시작 화면에 진입한 상태여야 한다. |
  | 입력값 | 사용자가 선택한 시작 방식: 이메일 로그인 / 이메일 회원가입 / 소셜 로그인 / 비회원 시작. |
  | 입력·검증 규칙 | 제공하는 네 가지 시작 방식을 구분하여 처리한다.<br>비회원 시작을 선택한 사용자에게 계좌 연결이나 관심종목 설정을 필수로 요구하지 않는다.<br>이미 로그인한 사용자가 시작 화면에 접근했을 때의 처리 방식은 `[확인 필요]`이다. |
  | 처리 절차 및 분기 | ① 시작 화면에 네 가지 이용 방식을 표시한다.<br>② **이메일 로그인 선택:** 이메일 로그인 화면으로 이동한다.<br>③ **이메일 회원가입 선택:** 가입 정보를 입력하고 약관에 동의하는 회원가입 화면으로 이동한다.<br>④ **소셜 로그인 선택:** 소셜 계정을 이용한 인증 절차로 연결한다.<br>⑤ **비회원 시작 선택:** 로그인 없이 이용할 수 없는 기능을 안내하고 메인 그래프 화면으로 이동한다. 이후 그래프 튜토리얼을 제공한다. |
  | 정상 결과 | 사용자가 선택한 이용 방식에 해당하는 화면 또는 절차가 열린다. 비회원은 가입이나 개인 종목 설정 없이 메인 그래프에 진입한다. |
  | 예외 처리 | 화면 이동이나 인증 절차 시작에 실패했을 때의 안내 문구와 재시도 방식은 `[확인 필요]`이다. 소셜 인증을 시작한 이후 발생하는 실패·취소는 소셜 로그인 기능에서 처리한다. |
  | 수용 기준 | ① 네 가지 시작 방식을 각각 선택할 수 있다.<br>② 선택한 방식에 맞는 화면 또는 절차로 연결된다.<br>③ 비회원 시작 시 회원가입·계좌 연결·관심종목 설정을 완료해야만 진입할 수 있도록 막지 않는다. |
  | 확인 필요 사항 | `[확인 필요]` 로그인 상태에서 시작 화면에 접근한 경우의 동작.<br>`[확인 필요]` 화면 이동·인증 시작 실패 시 안내 및 재시도 방식. |
  ## FS002 — 이메일 로그인
  | 항목 | 명세 |
  | 기능 ID | FS002 |
  | 기능명 | 이메일 로그인 |
  | 기능 설명 | 사용자가 이메일과 비밀번호를 입력하여 로그인한다. 인증에 성공하면 초기 설정 완료 여부에 따라 초기 설정 화면 또는 메인 화면으로 이동한다. |
  | 선행조건 | 사용자가 이메일 로그인 화면에 진입한 상태여야 한다. 로그인에 성공하려면 입력한 정보로 인증할 수 있는 계정이 존재해야 한다. |
  | 입력값 | 이메일, 비밀번호. |
  | 입력·검증 규칙 | ① 이메일과 비밀번호의 필수 입력 여부를 확인한다.<br>② 입력된 정보로 계정 인증을 수행한다.<br>③ 입력 누락 또는 인증 실패 상태에서는 로그인 성공으로 처리하지 않는다.<br>④ 이메일 형식 검사 방식, 공백 처리, 비밀번호 입력 제한 등 세부 규칙은 `[확인 필요]`이다. |
  | 처리 절차 및 분기 | ① 사용자가 이메일과 비밀번호를 입력하고 로그인을 요청한다.<br>② **필수 입력 누락:** 누락 오류를 안내하고 다시 입력할 수 있도록 한다.<br>③ **필수 입력 충족:** 입력된 정보로 인증을 수행한다.<br>④ **인증 실패:** 오류를 안내하고 재입력을 허용한다.<br>⑤ **인증 성공:** 회원의 인증 상태를 설정하고 초기 설정 완료 여부를 확인한다.<br>⑥ **초기 설정 미완료:** 초기 설정 화면으로 이동한다.<br>⑦ **초기 설정 완료:** 기존 보유종목과 관심종목을 기준으로 메인 화면에 진입한다. |
  | 정상 결과 | 유효한 계정 정보로 로그인되며, 초기 설정 완료 여부에 맞는 화면이 표시된다. |
  | 예외 처리 | **입력 누락:** 필요한 입력이 누락되었음을 안내하고 재입력을 허용한다.<br>**인증 실패:** 로그인 실패를 안내하고 재입력을 허용한다.<br>**인증 서비스 장애·응답 지연:** 안내 및 재시도 방식은 `[확인 필요]`이다.<br>**반복 인증 실패:** 제한 여부와 처리 기준은 `[확인 필요]`이다. |
  | 수용 기준 | ① 이메일 또는 비밀번호가 누락되면 로그인이 완료되지 않고 오류가 안내된다.<br>② 잘못된 인증 정보로는 로그인되지 않는다.<br>③ 오류 안내 후 다시 입력하여 로그인을 시도할 수 있다.<br>④ 인증 성공 후 초기 설정 미완료 사용자는 초기 설정 화면으로 이동한다.<br>⑤ 초기 설정 완료 사용자는 기존 보유·관심종목을 기준으로 메인 화면에 진입한다. |
  | 확인 필요 사항 | `[확인 필요]` 입력 형식·공백 처리 등 세부 검증 규칙.<br>`[확인 필요]` 인증 유지 기간과 반복 실패 제한 정책.<br>`[확인 필요]` 초기 설정 완료의 판단 기준과 중단된 설정의 재개 위치.<br>`[확인 필요]` 서비스 장애·응답 지연 시 처리 방식. |
  ## FS003 — 이메일 회원가입
  | 항목 | 명세 |
  | 기능 ID | FS003 |
  | 기능명 | 이메일 회원가입 |
  | 기능 설명 | 사용자가 가입 정보를 입력하고 필수 약관에 동의하여 계정을 생성한다. 필수 입력, 입력 형식, 필수 약관 동의, 이메일 중복 여부를 회원가입 기능 내부에서 검증한다. |
  | 선행조건 | 사용자가 이메일 회원가입 화면에 진입한 상태여야 한다. |
  | 입력값 | 이메일을 포함한 가입 정보, 필수 약관별 동의 여부.<br>이메일 외의 구체적인 가입 필드와 필수·선택 구분은 `[확인 필요]`이다. |
  | 입력·검증 규칙 | ① 필수 가입 정보가 모두 입력되었는지 확인한다.<br>② 각 입력값이 해당 항목의 형식에 맞는지 확인한다.<br>③ 필수 약관에 동의했는지 확인한다.<br>④ 가입하려는 이메일이 기존 계정과 중복되는지 확인한다.<br>⑤ 검증에 실패한 항목을 사용자에게 안내한다.<br>⑥ 검증을 통과하지 못한 상태에서는 계정을 생성하지 않는다.<br>필드별 형식·길이·허용 문자와 이메일 중복 판정의 세부 기준은 `[확인 필요]`이다. |
  | 처리 절차 및 분기 | ① 사용자가 가입 정보와 약관 동의 여부를 입력하고 회원가입을 요청한다.<br>② 필수 입력·입력 형식·필수 약관 동의·이메일 중복 여부를 검증한다.<br>③ **검증 실패:** 잘못되거나 누락된 항목을 안내하고 사용자가 수정할 수 있도록 한다.<br>④ **수정 후 재요청:** 변경된 입력값으로 검증을 다시 수행한다.<br>⑤ **검증 통과:** 계정을 생성한다.<br>⑥ **계정 생성 이후:** 자동 로그인 여부와 다음 화면은 `[확인 필요]`이다. |
  | 정상 결과 | 검증을 통과한 가입 정보로 계정이 생성된다. 가입 직후의 인증 상태와 이동 화면은 결정된 정책에 따라야 하며, 현재 문서에서는 미확정이다. |
  | 예외 처리 | **필수 입력 누락·형식 오류:** 해당 항목을 안내하고 수정할 수 있도록 한다.<br>**필수 약관 미동의:** 가입을 완료하지 않고 동의가 필요함을 안내한다.<br>**이메일 중복:** 해당 이메일로 계정을 생성하지 않고 중복 사실을 안내한다.<br>**계정 생성 중 저장 실패·응답 미수신:** 생성 여부 확인 및 재요청 처리 방식은 `[확인 필요]`이다. |
  | 수용 기준 | ① 필수 입력 누락 상태에서는 계정이 생성되지 않는다.<br>② 확정된 입력 형식에 맞지 않는 값은 거절되고 수정할 항목이 안내된다.<br>③ 필수 약관 미동의 상태에서는 계정이 생성되지 않는다.<br>④ 중복 이메일로 추가 계정이 생성되지 않는다.<br>⑤ 오류를 수정한 뒤 다시 가입을 요청할 수 있다.<br>⑥ 모든 검증을 통과한 가입 정보로 계정이 생성된다. |
  | 확인 필요 사항 | `[확인 필요]` 가입 필드 목록과 필수·선택 구분.<br>`[확인 필요]` 필드별 형식·길이·허용 문자.<br>`[확인 필요]` 필수 약관 목록.<br>`[확인 필요]` 이메일 중복 판정 기준.<br>`[확인 필요]` 이메일 소유 확인 절차의 도입 여부.<br>`[확인 필요]` 가입 직후 자동 로그인 여부와 이동 화면.<br>`[확인 필요]` 계정 생성 실패·응답 미수신 시 복구 방식. |
  ## FS004 — 소셜 로그인과 회원가입
  | 항목 | 명세 |
  | 기능 ID | FS004 |
  | 기능명 | 소셜 로그인과 회원가입 |
  | 기능 설명 | 사용자가 서비스에서 지원하는 소셜 계정으로 인증한다. 기존 회원이면 로그인하고, 처음 이용하는 사용자이면 계정을 생성한다. |
  | 선행조건 | 사용자가 소셜 로그인 경로를 선택한 상태여야 한다. 서비스에서 지원하는 소셜 계정으로 인증할 수 있어야 한다. |
  | 입력값 | 선택한 소셜 제공자, 제공자가 반환하는 인증 결과와 사용자 식별 정보.<br>지원 제공자 목록과 수신 정보의 세부 항목은 `[확인 필요]`이다. |
  | 입력·검증 규칙 | ① 서버에서 소셜 인증 결과를 검증한다.<br>② 검증된 사용자 식별 정보를 기준으로 기존 회원 여부를 확인한다.<br>③ 인증 실패 또는 취소를 인증 성공으로 처리하지 않는다.<br>④ 동일한 소셜 계정의 재접속을 신규 가입으로 처리하여 계정을 중복 생성하지 않는다.<br>⑤ 동일 이메일의 기존 계정과 소셜 계정을 연결하는 기준은 `[확인 필요]`이다. |
  | 처리 절차 및 분기 | ① 사용자가 지원하는 소셜 로그인 방식을 선택한다.<br>② 선택한 소셜 제공자의 인증 절차를 진행한다.<br>③ **인증 실패 또는 사용자 취소:** 시작 화면에서 이용 방식을 다시 선택할 수 있도록 한다.<br>④ **인증 결과 수신:** 서버에서 결과를 검증하고 사용자를 식별한다.<br>⑤ **기존 회원:** 로그인 처리한다. 로그인 완료 후 초기 설정 미완료 사용자는 초기 설정 화면으로, 완료 사용자는 메인 화면으로 연결한다.<br>⑥ **최초 이용자:** 계정을 생성한다. 계정 생성 직후의 인증 상태와 이동 방식은 `[확인 필요]`이다. |
  | 정상 결과 | 기존 소셜 회원은 해당 계정으로 로그인된다. 처음 이용하는 소셜 사용자는 계정이 생성된다. |
