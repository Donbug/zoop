**기업 정보 제공 서비스**
- 각 그래프의 로드를 선택했을 때 어느 기업의 기업 정보를 얻을 수 있고 기업 정보를 하단에는 AI 질문 버튼을 넣어서 AI한테 질문을 할 수 있게 설계함
- 기업 모드에서도 확인을 할 수 있고 이슈 모드랑 간선에서도 정보들을 확인할 수 있음
- 모든 기업 모드나 간선들로부터 AI 질문을 할 수 있게 바로 이동할 수 있게 해서 전용 AI 챗봇을 여기다 둠
- 출퇴근 VP 페이지는 출근하기 전과 퇴근하기 전에 벌어진 뉴스들에 대한 요약과 전날 전날 브리핑된 내용과의 비교를 통해서 현재 출근과 퇴근 사이에 벌어진 일들에 대한 브리핑 내역과 전날에 있었던 뉴스 내용들과 비교를 해서 보여주는 페이지임

**시퀀스 다이어그램**
- 시퀀스는 동시 작업해야 되는 것임
- 시퀀스 다이어그램을 작성해서 각각 뭐가 필요한지 보고 요구 사항 명세서를 작성한 다음 WBS를 작성함
- 개발을 할 때 아키텍처를 어떻게 잡았으니까 뭐가 구축이 되어 있어야 되고 클라이언트 클라우드에는 서버가 필요하니 미리 배포 파이프라인 만들어 놓고 이런 과정들이 있을 거임

**WBS의 작성**
- 기능 명세서를 작성했으면 기능 명세서에 맞는 개발의 범위들이 브레이크 다운이 될 테니까 그걸 좀 더 세분화해서 하루나 이틀 단위로 WBS를 만들면 됨
- WBS가 있어야 개발 범위도 알 수 있고 개발의 진척도도 알 수 있고 누가 담당을 했는지 향후의 계획은 어떻게 했는지를 알 수 있는 기준표가 될 것임
- 마일스톤 격의 일정이 있어야 함

- 화면 기획을 한 번에 만들 거냐 아니면 화면 기획을 한 번에 만들 거냐에 대해 이야기하고 있음

**기능 명세서**
- 기능 명세서나 개발 계획서를 작성할 때 기능 명세서를 기반으로 해서 기능 명세서를 만들고 비기능 명세서를 만들면 좋음
- 기능 명세서를 만들었으면 그걸 위주로 해서 요건 중에 어떠한 기능을 어떻게 만들 건지에 대한 설계가 같이 이루어져서 그걸 토대로 해서 개발을 하면 됨
- 요구 사항 명세서를 기능 비기능 요구 사항으로 세 파트로 나눠서 작성할 것임
