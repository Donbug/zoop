## 문제 정의
기존 은행 챗봇은 주로 FAQ 검색과 정형화된 답변 제공에 머물러 있습니다. 따라서 사용자가 실제로 원하는 다음과 같은 질문을 해결하지 못합니다.
- “나에게 가장 유리한 적금은 무엇인가?”
- “금리가 높은 상품을 조건별로 추천해줄 수 있는가?”
- “A상품과 B상품 중 어떤 것이 내 상황에 더 적합한가?”
- “이 혜택을 받으려면 내가 충족해야 할 조건은 무엇인가?”
## 서비스 목표
> 사용자의 자연어 질의를 이해하고, 공식 금융상품 정보와 사용자 조건을 바탕으로 적절한 답변과 금융상품 추천을 제공하는 AI 금융상품 추천 서비스
## 핵심 기능
- 자연어 기반 금융상품 질의응답
- 금리, 기간, 월 납입액, 연령, 우대조건 등을 반영한 상품 추천
- 여러 상품의 금리·혜택·가입 조건 비교
- 추천 이유와 상품별 유의사항 제공
- 상품설명서·약관 등 공식 출처 기반 답변 제시
- 사용자 조건이 불충분할 때 필요한 정보만 추가 질문
## 기존 은행 AI 챗봇 대상 질의 및 결과
### 1. 금리가 높은 적금 상품 추천 요청
**질의**
> “현재 정기 적금 상품 중에서 금리가 높은 순으로 5개의 상품만 추천해줄래?”
**챗봇 응답**
> “우리은행의 다양한 금융상품을 아래 상품몰에서 확인해보세요.”
**문제점**
- 사용자가 요청한 ‘금리순 상위 5개’라는 조건을 반영하지 못함
- 상품을 검색·정렬·추천하지 않고 단순 상품몰 링크로 회피함
- 사용자는 다시 직접 상품을 탐색하고 비교해야 함
**시사점**
> 챗봇이 상품 정보를 단순 안내하는 수준에 머물러 있으며, 상품 데이터를 기반으로 한 조건부 추천 기능이 부재함
---
### 2. 특정 적금의 우대금리 조건 질문
**질의**
> “우리 두근두근 행운적금을 들 경우, 행운카드를 받을 때마다 연 2%의 우대 금리를 준다고 했는데, 행운카드를 받을 수 있는 기준을 알려줄래?”
**챗봇 응답 요약**
- 급여이체, 연금이체, 공과금 자동이체, 신용카드 결제실적 등에 따라 우대금리가 적용된다는 일반적인 설명 제공
- ‘빙고 적금’ 등 질문과 무관한 다른 상품의 정보도 함께 제공
**문제점**
- ‘행운카드 지급 기준’이라는 구체적인 질문에 답하지 못함
- 우대금리 조건과 행운카드 지급 조건을 구분하지 못함
- 관련 없는 상품 정보를 섞어 제공해 오히려 혼란을 유발함
- 답변의 근거나 상품 약관 출처를 확인할 수 없음
**시사점**
> 상품명·세부 혜택·이벤트 조건을 정확히 연결할 수 있는 구조화된 상품 데이터와 원문 근거 기반 답변이 필요함
---
### 3. 두 금융상품 간 혜택 비교 요청
**질의**
> “내가 만일 이 적금 상품 말고 청년미래저금을 들었을 때, 내가 얻을 수 있는 혜택을 우리 두근두근 행운적금과 비교해줄래?”
**챗봇 응답**
> “질문 내용을 이해하지 못했어요. 저는 구체적이고 쉬운 말을 더 잘 이해할 수 있어요.”
**문제점**
- 실제 금융상품 선택 과정에서 매우 중요한 ‘비교’ 요청을 처리하지 못함
- 사용자가 충분히 구체적으로 질문했음에도 복합 질의로 인식하지 못함
- 사용자에게 더 쉬운 표현을 요구하며 문제 해결 책임을 사용자에게 전가함
**시사점**
> 사용자의 나이·소득·납입금액·가입 목적 등 조건을 반영해 상품별 혜택, 금리, 가입 조건을 비교하는 추천 기능이 필요함
---

## **해외 사례에서 반복되는 실패 패턴**
- 정확도가 여전히 최대 약점: 2025년 딜로이트 조사에서 은행 고객의 74%가 여전히 단순 문의에도 사람 상담원을 선호했고, 챗봇 이용자의 57%는 정확도를 최우선 개선점으로 꼽았습니다. 
- 마케팅과 실제 성능의 괴리가 신뢰를 깎아먹음 — "AI비서"라고 홍보하지만 실제로는 정해진 답변 DB에 갇혀 있는 경우가 많고, 기대와 실제 경험의 격차가 불만으로 이어진다는 지적이 반복적으로 나옵니다.
- 반대로 잘된 사례(BofA 'Erica')는 처음부터 "챗봇"이 아니라 "가상 금융비서"로 포지셔닝했고, 잘 설계된 챗봇 시스템은 고객 충성도 지표가 15% 개선됐다는 맥킨지 조사 결과도 있습니다. 
- 음성/보이스 AI 쪽은 더 구조적인 문제가 있는데, 배포 전에 실패 모드를 이해하지 못하고 사기 분쟁이나 계좌 도용 같은 고위험 상담에 투입하면 자동화가 아니라 오히려 법적 책임 부담을 키운다는 지적이 있고, 유럽은행감독청(EBA)의 2026년 6월 리스크 평가에서도 운영 실패·편향·데이터 품질·사이버공격·제3자 의존·법적 리스크가 AI 관련 우려사항으로 명시됐습니다.
## AI 실패 사례에서 배울 점 (기획 차별화의 근거)
해외/국내 금융 AI 실패에서 공통된 교훈은 “기술보다 프로세스·가드레일·핸드오프”
- **의도 파악이 러프하면 정답을 주기 어렵다**: 뱅킹 챗봇은 감정/문맥을 못 읽어서 63% 실패, 고객은 “사람 연결”을 원한다. 
- **정확성 문제**: 이자율·수수료·일정 등 금융 정보가 outdated/hallucination 되면 신뢰 붕괴
- **핸드오프 실패**: AI 가 막혔을 때 사람으로 넘어가는 경로가 불명확하면 “둠 루프” 발생, CSAT 급락.
- **프로세스 자동화 함정**: 깨진 프로세스 위에 AI 를 얹으면 실패. “수요 제거(원인 수정) → 에이전트 보조 → 완전 자동화” 순서가 안전.
- **지배구조(Governance)**: 금융은 규제·리스크가 높으므로, 검증된 지식베이스·감사 로그·에스컬레이션 규칙이 필수.
## 금융 챗봇에서 답변 품질이 낮은 이유 분석
현재 많은 금융 챗봇은 사용자 입력이 예상된 범위 안이면 답변하지만 조금 복잡해지면
> “정확한 상담을 위해 고객센터로 연결해드리겠습니다.”
> “해당 내용은 제가 답변드리기 어렵습니다.”
> “관련 메뉴로 이동하시겠습니까?”
같은 식으로 빠져나가.
그 이유를 단순히 **LLM이 멍청해서**라고 잡으면 안 되고,
> **AI에게 허용된 권한과 도구가 부족하기 때문**
이라고 보는 게 좋아.
예를 들어 사용자가
> “월급 300만 원인데 대출 2천만 원 있고 매달 80만 원 정도 저축할 수 있어. 대출 먼저 갚을까 ETF를 살까?”
라고 물었을 때 기존 챗봇은 상당히 어려워해.
왜냐하면 이 질문에는 동시에
```plain text
사용자 자산 조회
↓
대출 금리 확인
↓
월 현금흐름 계산
↓
비상금 여부 확인
↓
투자 가능 금액 계산
↓
투자 위험도 판단
↓
시나리오 비교
```
가 필요하거든.
그런데 기존 챗봇은 대부분 **답변 생성**만 할 수 있고 이 작업들을 수행할 Tool이 없어.
그래서 네가 쓴
> “조금만 복잡하면 매크로 응답을 호출하는 반쪽짜리 시스템”
이라는 문제의식은 맞는데, 발표에서는 약간 다듬어서
> **기존 금융 챗봇은 제한된 시나리오 기반 응답 구조에 의존하기 때문에 복합적인 금융 의사결정을 수행하기 어렵다.**
정도로 표현하면 좋을 것 같아.

# 해결 ② 금융 AI를 '챗봇'에서 'Agent'로
여기서 너희 프로젝트 방향이 명확해진다.
LLM 하나만 두는 게 아니라
```plain text
                     ┌─ 계좌 조회 Tool
                     │
사용자 ─→ AI Agent ──┼─ 대출 분석 Tool
                     │
                     ├─ 소비 분석 Tool
                     │
                     ├─ 금융상품 검색 Tool
                     │
                     ├─ 투자 시뮬레이션 Tool
                     │
                     └─ 금융 계산기 Tool
```
이런 구조를 만드는 거야.
AI의 역할은 모든 계산을 직접 하는 게 아니라
> **사용자의 목적을 이해하고 → 필요한 도구를 선택하고 → 결과를 종합해 설명**
하는 것.
이게 Agent 구조의 핵심이고.
---
## 특히 너희가 말한 '권한과 경계 분리'가 중요함
금융 AI에서는 Agent라고 해서 모든 걸 마음대로 실행시키면 안 돼.
그래서 오히려 이런 구조가 좋아.
```plain text
LEVEL 1
정보 조회
→ 자동 실행 가능

LEVEL 2
분석 / 계산
→ 자동 실행 가능

LEVEL 3
금융상품 추천
→ 근거 제시 필수

LEVEL 4
이체 / 상품 가입 / 투자 주문
→ 사용자 확인 필수

LEVEL 5
고위험 금융행위
→ 실행 제한 또는 추가 인증
```
즉,
**AI의 능력을 막는 것이 아니라 AI가 움직일 수 있는 경계를 명확하게 정의하는 것.**
이걸 너희가 말한 **Harness** 개념으로 연결하면 좋아.
Agent Harness가
- 사용할 수 있는 Tool
- 권한
- 실행 조건
- 금융 안전 규칙
- 사용자 승인
- 로그
- 결과 검증
을 통제하는 거지.


은행 AI 챗봇이 답을 못 하는 이유는 크게 두 가지야.
**① 질문은 이해했지만, 필요한 데이터나 기능에 접근할 권한이 없는 경우**
**② 애초에 챗봇이 처리하도록 설계된 질문 범위를 벗어난 경우**
네 프로젝트에서 말하는 **권한(permission)**은 주로 ①에 해당하고, 생각보다 범위가 넓어.
### 예를 들어보자
사용자가 은행 챗봇에게 이렇게 물어봤다고 해.
> “내가 지금 가진 대출 중 금리 높은 것부터 갚고, 남는 돈으로 적금을 들면 한 달에 얼마 정도 남아?”
사람 입장에서는 그냥 하나의 질문인데, AI 입장에서는 최소한 아래 작업이 필요해.
`내 대출 조회 → 각 대출 금리 조회 → 월 상환액 조회 → 계좌 잔액/월급 확인 → 지출 확인 → 적금 상품 조회 → 계산 → 결과 설명`
그런데 기존 챗봇에게 **“적금 상품 검색” 권한만 있다면**, 앞부분은 할 수 없어.
그래서 결국
> “대출 관련 내용은 대출 메뉴에서 확인해주세요.”
같이 다른 화면으로 보내게 되는 거지.

## 1. 가장 기본적인 권한: 데이터 조회 권한
AI가 **무슨 정보를 볼 수 있느냐**야.
예를 들어 은행 챗봇이라고 해도 모든 고객 데이터를 읽을 수 있는 건 아니야.
AI에게 줄 수 있는 조회 권한은 이런 식으로 나눌 수 있어.
| 조회 권한 | 가능한 것 |
| 상품정보 조회 | 예금·적금·대출 상품 금리와 조건 |
| 계좌 조회 | 잔액, 입출금 계좌 |
| 거래내역 조회 | 카드/이체/출금 내역 |
| 대출 조회 | 대출잔액, 금리, 만기 |
| 자산 조회 | 예금, 투자, 대출 종합 |
| 신용정보 조회 | 신용점수, 부채 현황 등 |
| 외부 금융정보 조회 | 다른 은행, 카드사, 증권사 자산 |
예를 들어 챗봇에게 **상품 DB만 허용**되어 있으면
> “신입사원에게 좋은 적금 알려줘.”
정도는 가능해.
그런데
> “내 상황에서 가장 좋은 적금 알려줘.”
는 어려워져.
**'내 상황'을 알 수 있는 권한이 없으니까.**
---
## 2. 개인화 권한
조금 더 들어가면 AI가 **사용자의 정보를 어디까지 활용할 수 있는가**가 있어.
예를 들어,
```plain text
사용자
월급: 300만원
월세: 70만원
대출: 2,000만원
대출 금리: 6.2%
월 평균 소비: 130만원
```
을 AI가 알 수 있다면 훨씬 좋은 답변을 할 수 있겠지.
그런데 실제 금융서비스에서는 개인정보와 금융정보 때문에 아무 모델에게나 이런 데이터를 넘길 수 없어.
그래서 AI가 볼 수 있는 정보를 제한할 수밖에 없어.
예를 들어:
```plain text
AI가 볼 수 있음
- 연령대
- 현재 이용 중인 상품
- 상품 가입 여부

AI가 볼 수 없음
- 전체 거래내역
- 정확한 소득
- 타행 대출
- 투자 자산
```
이렇게 되어 있으면 개인화 수준이 크게 떨어져.
그래서 AI가 아무리 똑똑해도 결국
> “일반적으로 대출금리가 높다면 대출 상환을 먼저 고려할 수 있습니다.”
같은 **두루뭉술한 답변**만 하게 돼.

# 3. Tool 사용 권한
이게 **Agent AI에서 제일 중요한 권한**이야.
LLM은 기본적으로 글을 읽고 글을 쓰는 모델이지, 은행 시스템을 조작하는 프로그램이 아니야.
그래서 별도의 Tool을 줘야 해.
예를 들어:
```plain text
getAccountBalance()
getLoanInfo()
getTransactionHistory()
searchDepositProducts()
calculateLoanInterest()
compareProducts()
transferMoney()
subscribeDeposit()
buyETF()
```
이런 함수/API를 만들어서 AI에게 제공하는 거지.
그러면 AI가 질문을 보고
> “이 질문은 대출정보를 먼저 확인해야겠네.”
라고 판단해서
```plain text
getLoanInfo()
```
를 호출할 수 있어.
이걸 **Tool Calling**이라고 해.
---
## 기존 챗봇은 이 Tool이 굉장히 제한적인 경우가 많음
예를 들어 AI가 사용할 수 있는 기능이
```plain text
searchFAQ()
searchProduct()
openMenu()
connectAgent()
```
딱 네 개라고 해보자.
그러면 사용자가
> “내 지난 6개월 소비를 분석해서 통신비가 과한지 알려줘.”
라고 물었을 때 AI가 할 게 없어.
AI가 생각하기에는
```plain text
거래내역 조회가 필요함
↓
그런데 getTransactionHistory Tool이 없음
↓
수행 불가능
```
이 돼.
그러니
> “소비내역은 자산관리 메뉴에서 확인해주세요.”
하고 화면을 넘기는 거야.
이게 네가 말한 **“다른 화면으로 전환하게 유도하는 현상”**의 주요 원인 중 하나야
