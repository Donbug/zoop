GraphDB 기반 관계 탐색과 타임라인 및 출퇴근 브리핑의 목표 서비스
요구사항

# 작성 목적

팀이 구현할 서비스 범위를 합의하고, 기능별 처리 규칙과 완료 기준을
정의한다. 최종 통합 흐름도와 기존 요구사항을 기준으로 접속·종목
설정·관계 그래프·기업 상세·타임라인·브리핑·근거 확인·AI 질문을 연결한다.
현재 시연의 구현 완료 보고서가 아니라 팀 검토용 목표 명세다.

# 2. 서비스 개요

| **구분** | **작성 내용** |
|:--:|----|
| 서비스 한 줄 설명 | 보유·관심 기업과 뉴스·공시의 사건을 관계 그래프로 연결하고, 시간 변화와 근거를 탐색하는 금융 정보 서비스 |
| 사용자 시나리오 | 계정 또는 비회원 시연으로 접속 → 보유/관심 종목 설정 → 그래프 탐색 → 기업·사건·관계 선택 → 상세·타임라인·근거·AI 질문. 브리핑에서도 같은 맥락으로 후속 탐색 |
| 핵심 데이터 | 기업·종목 마스터, 가상 보유 정보, 관심 목록, 뉴스·공시, 사건·이슈, 기업 관계, 사건별 영향, 시계열, 근거, 브리핑 버전 |
| AI 활용 포인트 | 엔티티 정규화·동일/후속 사건 판별·관계 후보 생성과 근거 기반 질문 응답. 데이터 분석 단계와 대화 단계는 분리 |
| MVP 방향 | 가상 계좌와 제한된 종목 집합으로 전체 흐름 구현. 종목 수·산업·조회 깊이는 팀 확정 필요 |
| 시연과 실제 구분 | 예시 데이터·미연결 기능은 표시. 실제 계정·OAuth·모델·외부 데이터 연결을 구현 완료로 간주하지 않음 |

# 3. 기능 요구사항

Must는 핵심 흐름, Should는 확장 기능이다. 표의 담당은 역할 제안이며 실제
담당자와 일정은 팀에서 배정한다. 자동 검수에는 고정 테스트 데이터·API/UI
테스트·스키마 검증을 사용하며 사람의 주관적 평가 점수를 합격 기준으로
요구하지 않는다.

| **ID** | **기능명** | **설명** | **우선순위** | **담당** | **완료 기준** |
|:--:|----|----|----|----|----|
| FR-01 | 로그인 상태 확인 | 접속 시 서버가 세션의 유효성을 확인한다. 유효하면 계정 설정을 조회하고 설정 완료 여부에 따라 이동한다 예외: 세션 만료·위조 시 로그인 또는 비회원 선택 제공 | Must | Backend | 유효·만료·변조 세션 테스트에서 각각 지정 화면으로 이동하고 만료 세션의 개인 데이터 요청이 거절됨 |
| FR-02 | 이메일 회원가입 | 이메일·비밀번호·필수 동의 입력 후 가입 요청. 서버에서 형식·중복·비밀번호 정책 검사 예외: 형식 오류·중복·필수 동의 누락 시 계정 생성하지 않음. 이메일 인증 방식 D-02 | Must | Backend | 유효 입력만 계정 생성. 중복 요청에 중복 계정이 생성되지 않음 |
| FR-03 | 이메일 로그인 | 등록 계정의 인증 성공 시 세션 생성. 기존 설정 유무로 후속 경로 결정 예외: 인증 실패 시 비밀번호 등 민감정보 없이 오류 안내·재시도 제공 | Must | Backend | 정상 자격정보는 성공, 잘못된 정보는 실패, 실패 시 개인 데이터가 응답에 포함되지 않음 |
| FR-04 | 소셜 OAuth 인증 | 선정된 제공자의 인증 결과를 검증하고 서비스 계정과 연결 예외: 사용자 취소·인증 실패 시 시작 화면 복귀. 계정 병합 기준 D-03 | Should | Backend | 모의 제공자 성공·취소·실패 응답이 각 경로로 처리되고 잘못된 인증 응답이 거절됨 |
| FR-05 | 비회원 시연 | ‘계정 없이 체험’ 선택 시 예시 데이터로 진입. 시연 데이터임을 표시 예외: 저장·개인정보 기능 접근 시 로그인 안내. 접근 허용 목록 D-01 | Must | Backend | 인증 없이 예시 탐색 가능. 타 사용자 계좌·설정 API 접근은 차단됨 |

| FR-08 | 시작 모드 선택 | 보유 종목 또는 관심 종목으로 시작한다. 계정 소유와 주식 보유 여부는 별개로 취급 예외: 닫기·취소 시 이전 화면 복귀 | Must | Frontend / Backend | 두 선택지가 각 설정 화면으로 이동하며 인증 상태를 임의 변경하지 않음 |

## 적재 원칙

- LLM은 허용된 JSON 후보를 생성하고 서버가 검증 후 적재한다. 임의 Cypher
  실행이나 직접 데이터 변경은 허용하지 않는다.

- 원문 근거·엔티티 존재·관계 타입·중복·시간 정합성을 검사한다. 모델의
  자기 보고 신뢰도만으로 승인하지 않는다.

- 같은 사건은 출처를 묶고, 같은 시점의 다른 사건과 후속 사건은 별도
  Event로 보존한다.

- P/S는 사용자 포트폴리오에 따른 표시 역할이지 별도 기업 정체성이
  아니다. 기존 9개 P/S/I UI 필터 유지 여부는 최신 화면 설계와 함께
  확정한다.

- 후보·검증 통과·거절/보류 상태를 분리하고 사유·버전·기준 시각을
  기록한다.

| **단계** | **처리** | **결과** |
|:--:|----|----|
| 1 | 수집 | 문서·시장·가상 자산 원천과 접근 결과 기록 |
| 2 | 정제 | 중복 문서 제거·본문 정제·출처·공개 시각 유지 |
| 3 | 엔티티 추출·정규화 | 기업·티커·제품·주제를 표준 ID로 연결. 불확실 항목 보류 |
| 4 | 사건 판별 | 동일 사건은 출처 추가, 후속/독립 사건은 별도 생성 |
| 5 | 관계 후보·기업별 영향 | 허용 타입·방향·시간·근거·경로 생성 |
| 6 | 검증·적재 | 원문·스키마·ID·관계 검사 후 저장. 실패 로그 유지 |
| 7 | 부분 그래프·타임라인 조회 | 기업·기간·필터별 사건과 관계 반환 |
| 8 | 브리핑 구성 | 기준 시각에 맞춘 사건·근거 묶음과 버전 보존 |

| **질문 유형** | **예시** | **조회 경로** | **출력** |
|:--:|----|----|----|
| 시장·관계 | 이 규제가 삼성전자에 왜 연결돼? | GraphDB + 근거 문서 | 관계 경로·영향 가설·출처 |
| 뉴스·사건 | 최근 HBM 관련 사건은? | 문서/Vector 검색 + Event | 시점별 사건·요약·출처 |
| 개인 자산 | 내 보유 비중은? | 권한 검증된 자산 RDB/API | 실제 저장값 또는 명시된 가상 값·기준 시각 |
| 복합 | 이 사건이 내 종목과 어떻게 연결돼? | Graph + 문서 + 허용 자산 | 개인화 경로와 근거 |
| 정보 부족 | 이 종목 영향은? | 대상·기간 확인 질문 | 추가 입력 요청 |
| 지원 외 | 주식을 매수해줘 | 지원 범위 안내 | 주문 미지원·탐색 기능 안내 |

라우팅은 자동 테스트 질문 집합으로 검사한다. 참고 문서의 의도 분류
정확도 85%는 데이터셋·채점 규칙 확정 전에는 승인된 기준으로 사용하지
않는다. 근거 부족은 답변 생성으로 숨기지 않고 판단 보류로 처리한다.

# 12. MVP 범위와 제외 사항

| **우선순위** | **범위** | **정의** |
|:--:|----|----|
| Must | 기본 사용자 흐름 | 이메일 인증·비회원·가상 계좌·관심 설정·복원 |
| Must | 관계 탐색 | 시장/자산/관심 모드·기업/이슈/관계 패널·근거 |
| Must | 기업 상세·타임라인 | 차트·기간·동시 사건·동일 출처·후속 사건·경로 복귀 |
| Must | 기본 브리핑 | 아침/저녁 선택·관계도/요약·근거·질문 연결. 자동 생성 범위는 별도 확정 |
| Must | 근거 기반 질문 | 일반/맥락 질문·근거·보류·실패·새 대화 |
| Should | 확장 인증·질문 | OAuth·AI 그래프 하이라이트 |
| Should | 브리핑 검증 | 과거 가설과 후속 근거 비교·원본 버전 보존 |
| Could | 과거 관계 스냅샷 비교 | 별도 합의 시 추가. 사건 타임라인과 다른 기능 |

## MVP 제외 사항

- 매수·매도·결제·이체 및 주문 권한.

- 주가·수익률 직접 예측과 특정 종목 추천.

- 전 종목의 자동 관계 구축과 초 단위 실시간 처리 보장.

- 검증 없는 AI 관계 적재.

- 확정되지 않은 관리자 콘솔·알림 발송·유료 요금제.

## 발표 및 구현 전 확정 사항

지원 종목 목록·산업·조회 깊이·노드 수, 팀 배정·일정, 외부 공급자와 표시
권한, 인증 정책, 설정 취소·복귀, 혼합/불확실 분류, 브리핑 수집
마감·발행·휴장일, 자동 검증 기준, AI 비용·한도, 개인정보·대화 보존과
삭제, 성능 목표를 확정한다.

현재 시연은 이메일 입력 검사·메모리 설정·고정 관계·예시 사건·규칙 기반
답변 수준이다. 위 목표 기능의 구현·배포·테스트 통과를 뜻하지 않는다.
