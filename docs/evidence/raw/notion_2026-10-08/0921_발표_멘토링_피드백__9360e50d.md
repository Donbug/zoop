### 피드백

- 기술 검증을 통해 잘 되면 주식 종류를 여러 개 해도 될 것 같다
- 너무 난잡하게 할 필요는 없고 사용자의 여정에 맞게 기능을 넣으면 된다

### 해야할 것

- 사용자 여정 → 요구사항 명세서(by 사용자나 고객) → 기능 요구/비기능 요구(by 구현, 개발) → WBS(1일~3일) → 일정 → (팀장이나 PM이 관리)
- 빠르면 10월 초까지 WBS 확정하기
- 사용자와 요구사항 명세서 나오면 화면 기획을 할 수 있다.
- 20개 종목으로 그래프 DB/지식 그래프 → 사용자?관리자? 관리자 측면에서 50개정도 되면 기능은 충분할거다

### 질문 답변

- 프로토타입에 대한 화면 기획에서 화면이 넘어가는거면 그거에 대한 설명이 있어야한다
- 모바일로 화면이 작아져서 그래프가 작아져도 넣는건 좋다고 생각한다. 넣어도 화면을 터치 드래그 하면서 움직이면서 보는 형식이나 다른 형식을 생각해봐야한다 - 모바일 리액트 네이티브 개발로 방향은 가되, 화면구성을 어떻게 할지는 조금 더 생각.
- 텍스트로 내려오는 구조로 옵션을 만들고 마지막에 이미지를 보여주는 형식으로 해도 충분하다
- 그래프 DB를 어떻게 구현하는지는 멘토분들도 접해보지 않아서 모른다, 직접 해봐야한다
