# 2026.09.17 데일리 스크럼 피드백 회의록
- **주제:** 금융 정보 관계 시각화 서비스의 중간 발표 자료 검토
- **녹음 분량:** 약 26분 18초
- **참석자 표기:** 전사본의 참석자 번호를 사용하며, 참석자 3은 피드백 담당자, 참석자 1·4·5·6·7은 프로젝트 설명 및 질의 참여자로 구분함.
- **작성 기준:** 발언 시점은 녹음 시작 기준이며, 회의와 무관하게 혼입된 대화는 제외함. 제안·권고 사항은 확정된 결정과 구분함.
## 1. 회의 개요
주식·뉴스·공시에서 추출한 이슈와 기업 간 관계를 시각화하는 서비스의 중간 발표 자료를 검토하였다. 발표 논리, 페르소나, 핵심 기능과 차별성, KPI, 개발 일정·진척도 및 신규 AI 검증 기술의 도입 근거를 점검하였다.
## 2. 주요 논의 사항
### 2.1 페르소나와 사용자 요구의 일관성 [00:00~04:06]
- **참석자 1**
  - 서비스 개발 배경과 두 가지 페르소나를 설명함.
  - 계좌가 있는 사용자와 없는 사용자를 구분하고, 계좌가 없어도 관심 종목을 선택하여 관계 정보를 확인할 수 있도록 기획했다고 설명함.
- **참석자 3**
  - 초보 투자자의 어려움과 “이 뉴스를 왜 봐야 하는가”라는 요구 문구가 자연스럽게 연결되지 않는다고 지적함.
  - “관심 종목과 관련된 뉴스를 알고 싶다”는 요구와 초보자 페르소나의 요구가 중복되어 보이므로, 사용자별 문제와 니즈를 명확히 구분하도록 요청함.
- **참석자 4**
  - 초보자는 시장이 작동하는 방식이나 뉴스가 종목에 미치는 영향을 추적하기 어려우므로, 시장 관계와 영향 구조에 대한 이해를 돕는 것이 목적이라고 설명함.
**논의 요지:** 페르소나의 상황·어려움·요구·제공 가치가 일관되도록 문구를 재정리할 필요가 있음.
### 2.2 개발 배경과 문제–해결책 연결 [04:07~07:45]
- **참석자 1**
  - 프로젝트 목표와 메인 화면 프로토타입을 소개하며, 화면 디자인은 아직 확정되지 않았다고 설명함.
- **참석자 3**
  - 자료에는 ‘정보 분산’, ‘사용자가 관계를 직접 해석해야 하는 부담’, ‘가격 중심 확인’이라는 문제만 있고, 해당 문제를 도출한 배경 설명이 부족하다고 지적함.
  - 정보가 많아지는 상황에서 투자 초보자가 겪는 어려움처럼, 문제 제기로 이어지는 맥락을 먼저 제시하도록 요청함.
  - 문제를 세 가지 제시했다면 각각에 대응하는 해결책도 보여줘야 한다고 강조함.
  - 해결책을 정리한 뒤 핵심 기능과 프로젝트 개발 범위를 도출하는 흐름이 필요하다고 설명함.
- **참석자 5**
  - 분산된 정보를 모아 관련 종목과 연결하는 것이 해결 방향이라고 설명함.
- **참석자 1**
  - 여러 문제의 해결책을 하나로 묶어 표현한 상태임을 설명함.
**논의 요지:** 개발 배경 → 문제 정의 → 문제별 해결책 → 핵심 기능·개발 범위의 연결을 보완해야 함.
### 2.3 핵심 기능 설명과 용어 정리 [07:46~13:46]
- **참석자 1·4·5·6**
  - 뉴스·공시에서 이슈와 관계를 추출하고, 관계를 뒷받침하는 원문을 확인할 수 있게 하는 기능을 설명함.
  - 원문 근거는 뉴스와 이슈뿐 아니라 기업과 기업 간 관계에도 제공하려는 것이라고 보충함.
- **참석자 3**
  - ‘관계별 원문 근거’라는 표현만으로는 무엇을 입증하는 근거인지 이해하기 어렵다고 지적함.
  - 기업–기업, 뉴스–기업 등 **추출한 관계를 뒷받침하는 원문 출처를 제공한다**는 의미가 드러나도록 설명을 구체화하도록 요청함.
  - ‘AI 코파일럿’은 기존 제품명과 혼동되거나 기능의 의미가 모호할 수 있어 다른 표현을 검토하도록 요청함.
  - ‘내 투자 변화 타임라인’도 실제로 무엇의 변화를 어떤 방식으로 보여주는지 설명이 부족하다고 지적함.
- **참석자 7**
  - 하루 동안의 변화를 정리한 장 마감 리포트를 제공하려는 기능이라고 설명함.
- **참석자 3**
  - 개별 주식 상세 정보 조회는 일반적인 기본 기능이므로 대표 핵심 기능과 구분할 필요가 있다고 설명함.
  - 중복된 설명을 통합하여 핵심 기능을 3~4개로 압축할 것을 제안함.
- **참석자 1**
  - 기능 설명을 정리하는 방향에 수긍함.
### 2.4 벤치마킹과 차별성 표현 [13:47~16:38]
- **참석자 3**
  - 토스증권·구글 파이낸스와 비교했을 때, 팀 서비스가 보완하려는 부분이 비교표에서 명확하게 드러나지 않는다고 지적함.
  - 경쟁 서비스의 부족함을 단정하기보다, 팀이 집중하려는 가치를 강조해야 한다고 설명함.
  - 뉴스에서 이슈를 추출하고 정보를 연결하는 기능이 핵심이라면, 이를 비교 항목과 강점에 명시하도록 요청함.
  - ‘좌측 목록·우측 상세 정보’와 같은 일반적인 화면 구성은 차별화 요소로 보기 어렵다고 지적함.
  - 그래프 기반으로 관계를 탐색하는 방식과 사용자가 얻는 이점을 구체적으로 설명하도록 요청함.
  - 비교표의 불필요한 여백을 줄이고 중요한 차이가 눈에 띄도록 강조할 것을 제안함.
**논의 요지:** 화면 배치보다 ‘이슈 추출·정보 연결·관계 탐색’이 제공하는 사용자 가치를 차별점으로 표현해야 함.
### 2.5 KPI와 ‘2-hop’ 표현의 의미 검토 [16:39~20:28, 23:07~24:07]
- **참석자 3**
  - 목표 지표를 제시한 점은 긍정적으로 평가했으나, 탐색 깊이를 2-hop으로 제한하는 것이 왜 성과 목표인지 근거가 불분명하다고 지적함.
  - 질문에 필요한 탐색 단계가 달라질 수 있으므로, 단순히 단계가 적다는 이유만으로 장점이라고 설명하기 어렵다고 언급함.
- **참석자 4**
  - 팀이 의도한 것은 많은 노드와 관계를 사용자가 보기 편하도록 제한·압축하여 표시하는 것이라고 설명함.
- **참석자 5**
  - 삼성전자를 중심으로 한 단계, 두 단계의 관계를 보여주는 예시에서 해당 표현을 사용했다고 설명함.
  - 자료의 표현이 의도와 다르게 전달된 점을 인정함.
- **참석자 3**
  - 화면에서 보여주는 관계 범위와 답변을 찾는 탐색 과정의 의미를 구분하여 설명하도록 요청함.
**논의 요지:** ‘2-hop’의 적용 대상과 목적을 명확히 하고, 화면 표시 정책과 성능 KPI를 구분해야 함. 해당 지표의 최종 수정안은 확정되지 않음.
### 2.6 검증 흐름과 성능 지표의 구분 [19:20~21:36]
- **참석자 4**
  - AI가 수집한 자료에 기계적 검증과 AI 기반 팩트체크를 적용하는 구조를 설명함.
  - 자료 부족, 모호한 내용, 테스트 미통과 등으로 보류된 결과는 사람이 검토하고, 검토 상태를 사용자 UI에 표시하는 방식을 제시함.
- **참석자 3**
  - ‘검토 상태 표시’는 서비스 기능이나 처리 과정에 대한 설명이지 성능 KPI는 아니라고 지적함.
  - 목표 기준에는 프로젝트가 도달하려는 성능 수준을 제시해야 한다고 설명함.
**논의 요지:** 검증 절차·상태 표시 등의 기능 요구사항과, 검증 성능을 평가하는 지표를 분리해야 함.
### 2.7 개발 범위·일정·현재 진척도 보완 [20:29~23:01]
- **참석자 3**
  - 발표 자료에 개발 범위, 일정, 현재 상태에 관한 설명이 부족하다고 지적함.
  - 전체 구상 중 이번 프로젝트에서 어디까지 구현할 것인지 명시하도록 요청함.
  - 데이터 수급, 그래프 기반 구성, 설계, 개발, 화면 구현 등의 진행 방법과 시점을 제시하도록 요청함.
  - 중간 발표인 만큼 기획 소개뿐 아니라 지금까지 완료한 내용, 현재 수행 중인 작업, 남은 작업을 설명해야 한다고 강조함.
  - ‘1주 차’ 등 상대적인 일정만 제시하지 말고 실제 날짜와 현재 위치를 표시하도록 요청함.
  - 가능하면 진행률도 제시하되, 최소한 현재 어디까지 진행되었는지는 알 수 있어야 한다고 설명함.
- **참석자 4**
  - 일정표에 현재 위치를 표시하는 방향을 언급함.
### 2.8 신규 AI 검증 기술의 도입 기준 [24:08~26:02]
- **참석자 4**
  - 사람의 검토를 최소화하면서 LLM의 부정확성을 줄이기 위한 PoC를 진행하고 있다고 보고함.
  - 자연어 입력에 대해 선택지 또는 참·거짓 형태로 빠르게 판단하는 신규 AI 기술을 검토 중이라고 설명함.
  - 초기 테스트에서는 높은 정확도를 보였다고 언급했으나, 공개된 지 얼마 되지 않은 기술이라 도입해도 되는지 질문함.
  - 최종 채택 여부는 PoC와 관련 자료 검토 후 결정할 계획이라고 설명함.
- **참석자 3**
  - 신규 기술을 사용하는 것은 가능하되, 선택 이유를 설명할 수 있는 비교 자료가 필요하다고 답변함.
  - 수작업 또는 기존 방식과 비교하여 처리 시간과 정확도 등에서 어떤 차이가 있는지 제시하도록 요청함.
- **참석자 4**
  - 동일한 테스트에서 기존 LLM과 신규 기술의 지연 시간 및 통과 개수를 비교하는 방식이 적절한지 확인함.
- **참석자 3**
  - 비교 근거를 확보하는 방향에 동의함.
**주의:** ‘30초·8/10개 통과’와 ‘3초·10/10개 통과’는 비교 방식의 예시이며, 확정된 실험 결과가 아님. 신규 기술의 정확한 명칭은 추가 확인이 필요함.
## 3. 결정 사항(Conclusion)
### 회의에서 확인된 방향
1. **핵심 기능 설명을 정리한다.**
  중복된 내용을 통합하고 일반적인 조회 기능은 구분하여, 대표 핵심 기능을 3~4개 수준으로 압축하는 방향을 수용함. 최종 목록은 미확정임.
1. **신규 AI 기술은 비교 검증을 전제로 도입을 검토한다.**
  기존 방식과 처리 시간·정확도 등을 비교한 근거를 확보한 후 채택 여부를 판단하기로 함. 신규 기술의 도입 자체가 확정된 것은 아님.

- 벤치마킹 자료에 이슈 추출·정보 연결·관계 탐색의 차별성 명시
- 화면 표시 범위, 기능 요구사항, 성능 KPI의 구분
