# ZOOP AI 챗봇 보조 웹 검색 설계

문서 상태: 2026-10-28 팀 결정 · 서버 도구·예산, agent 경로 승인 gate, Q02-only 기본 검색 구현(2026-10-30, [api/docs/chat-web-search.md](../../api/docs/chat-web-search.md)), 혼합 질문은 요구별 승인 매핑 전까지 내부 부족 뒤 검색, 인용 계약 전까지 agent와 동시 활성 금지 · 공급자/출시 확인 별도

기준 정책: [ZOOP-AIG-001 v0.11](../ZOOP_AI_거버넌스_정책.md) / [설계 요약](ai-chatbot-design-summary.md) / [Luna MCP 실행 계약](ai-chatbot-mcp-actions.md)

화면 추적: D-AI-01, D-AI-02. 현재 OpenAPI·화면 구현과 아래 목표 계약을 구분한다.

## 1. 유형별 검색 순서

| 유형 | 검색 시점 | 실패 시 |
| --- | --- | --- |
| Q01 서비스 안내 | 웹 도구 노출·호출 금지 | 승인된 내부 정책/도움말만 사용, 없으면 안내 |
| Q02 일반 개념 | 기본 보조 근거로 웹 검색을 1회 시도할 수 있도록 최초 단계에 배치 | 실패·0건·비활성·예산 부족이면 Luna의 제한된 일반 개념 설명과 원인 안내 |
| Q03~Q08 | 내부 DB·공개 스냅샷·원문 조회를 먼저 수행하고 미충족 요구에만 마지막 검색 | 확보된 검증 근거로 답변/부분 답변, 전혀 답할 수 없으면 고정 안내 |

Q02 검색은 정상 활성·예산 내에서는 기본 시도한다. 항상 성공해야 답변하는 선행 조건은 아니다. 범용 용어 사전은 만들지 않는다. Q02의 일반 지식은 최신 기업 상태·가격·수치·점유율·공시·전망을 대신하지 못하며 그러한 요구는 Q03~Q08로 함께 분류한다.

Q03~Q08은 최초 내부 조회와 웹을 병렬 시작하지 않는다. 내부 자료가 있어도 **질문이 요구한 범위**를 충족하지 못하면 마지막 검색이 가능하다. 외부 출처를 명시한 요구는 내부 문서만으로 충족됐다고 판단하지 않지만 내부 조회를 건너뛰지는 않는다. Q01+Q03 복합 질문의 웹 결과는 Q03 requirementId에만 연결한다.

## 2. 검색 gate와 원천 권위

Jev는 유형·기능 후보를 제공하고 Luna가 허용된 web.search의 인자와 호출 여부를 선택한다. 서버는 아래 상태와 미충족 requirementId가 기록된 경우에만 Q03~Q08 검색을 허용한다. Jev 확률만으로 검색을 시작하지 않는다.

| 내부 상태 / 요구 | 허용 여부와 표시 |
| --- | --- |
| 조회 성공, 해당 범위 0건 | 부족한 공개 사실에 대해 검색 허용, 내부 0건 사실 유지 |
| 자료는 있으나 인용 가능한 근거 또는 질문의 세부 사실 부족 | 해당 부족 항목에만 검색 |
| 질문 기간에 맞는 자료가 없음 | 최신성 미충족으로 기록 후 검색 |
| 사용자가 명시한 외부 출처 요구 미충족 | 내부 확인 뒤 외부 출처 검색 |
| 내부 근거가 모든 요구를 충족 | 추가 검색 안 함 |
| 내부 조회가 truncated | 전체 확인으로 해석 안 함. 공개 사실 보완만 허용하고 조회 한계 유지 |
| 내부 연결 장애, direct 복구도 불가 | 장애 원인 유지. 독립 공개 사실만 웹 보완 가능 |
| 권한·grant 거부 / 비공개 자료 | 거부된 자료를 찾는 대체 검색 금지 |
| Q01 서비스 규칙 | 다른 유형에서도 웹 근거로 우회 답변 금지 |

‘근거 충분’은 건수로만 결정하지 않는다. 서버는 대상·기간·필수 필드·인용 존재를 확인하고 Luna의 부족 판단은 신호로 받는다. 최종 주장 지지는 Jev가 검사한다. 의미적으로 부족한 근거를 evidenceSufficient=true 하나로 잠그지 않는다.

| 유형 | 웹으로 보완할 수 있는 것 | 웹으로 대신할 수 없는 것 |
| --- | --- | --- |
| Q02 | 일반 개념의 정의·설명·출처 | ZOOP 서비스 규칙, 최신 사실을 일반 지식으로 단정 |
| Q03 | 공개 기업·사건의 공시·보도 | 내부 근거 검수/공개 상태 |
| Q04 | 조회된 관계 배경, 별도 외부 보도 | 실제 지도 간선·경로 존재. 웹에만 있는 관계를 graphTargets/uiActions로 생성 금지 |
| Q05 | 비교 기간의 외부 사건 배경 | 버전 차이·서버 계산값·변경 원인 |
| Q06 | 발행 회차의 배경 또는 발행 후 소식 | 발행 내용·선정 목록·dataAsOf |
| Q07 | 본인 범위 확인 뒤 개별 공개 기업 정보 | 보유 여부·개인 데이터·포트폴리오 범위 |
| Q08 | 공개 사건 배경 | 기록된 규칙 revision·실제 선정 이유 |

Q05/Q08의 배경 보도를 ‘이 기사 때문에 변경/선정됐다’고 연결하지 않는다. Q06 발행 후 소식은 회차의 원래 내용과 분리한다.

## 3. 호출·검색어 예산

[Luna MCP 실행 계약 3.2절](ai-chatbot-mcp-actions.md#32-호출시간-초기-상한)의 총 8회·내부 6회·웹 2회, 의존 3라운드·동시 4개·job 45초 안에서 실행한다. 웹 호출당 최대 7초이며 남은 기한으로 줄인다. 검색 실패 후 자동 공급자 재시도는 없다.

- 공급자 검색어 1개당 1회로 센다. 검색어 3개를 한 MCP 봉투에 넣는 방식으로 상한을 우회하지 않는다.
- Q02+Q03 복합이면 Q02 검색도 같은 2회에 포함한다. 남은 검색이 없으면 미검색 요구와 원인을 표시한다.
- Q07은 내부 배치 조회로 최대 5개 기업을 확인한다. 웹이 필요한 기업이 2개를 넘으면 최종 생성 전 사용자에게 검색할 기업을 선택하도록 clarification한다. 임의 상위 2개 선택 금지. 선택하지 않고 종료해야 하면 내부 답변과 외부 미확인 범위를 명시한다.
- 같은 정규화 검색어·기간·언어·필터는 요청 캐시/single-flight로 재사용한다. 캐시 hit도 총 시도 예산에는 포함하고 실제 공급자 호출/비용은 별도 집계한다.
- 검색어당 최대 5건, 전체 최대 10건, snippet 건당 최대 500자, 내부 문서와 합계 20개 상한.
- 초기 구현은 제목·URL·snippet·공급자 게시 시각만 사용한다. 임의 URL 본문 fetch/크롤링은 열지 않는다.
- 초기 회원별 웹 공급자 호출은 하루 20회, 프로젝트 전체 하루 500회(KST 날짜 전환)로 제한한다. retry·확인 사슬·새 job에도 누적되며 동시 요청은 원자 예약한다. 실패/timeout도 시도량으로 센다.
- 금액 상한은 공급자 가격 확정 전 미결정이다. 한도 소진은 web_budget_exhausted로 안내하고 내부 답변을 계속한다.

## 4. 웹 실패는 전체 실패로 승격하지 않는다

| 결과 | 처리 |
| --- | --- |
| 성공·유효 근거 있음 | web_reported 구간과 실제 출처 |
| 성공·0건 | web_no_results, 해당 조회 범위에서 확인 못함 |
| timeout / unavailable / 공급자 오류 | web_unavailable, 정상 내부 근거와 제한된 Q02 설명 유지 |
| 검색 미설정 / grant 없음 | web_not_configured 또는 전송 차단 사유, 외부 호출 안 함 |
| 예산·기한으로 미실행 | web_budget_exhausted, 찾았지만 없었다고 표현하지 않음 |
| 결과 schema 오류 / 유효하지 않은 URL | 결과 폐기·원인 기록, 나머지 답변 지속 |
| 외부 프롬프트 지시 / 미지지 주장 | 지시를 실행하지 않으며 검증 불가 구간 제외/차단 |

웹 실패 때문에 다른 정상 조회 결과를 버리지 않는다. 내부 근거가 모든 요구를 답하면 complete와 notice, 일부만 답하면 partial과 해당 limitation, 아무것도 답할 수 없으면 guidance/insufficient_evidence의 안내다. Q02 검색 실패 시 일반 개념 설명은 가능하되 출처를 만들어내지 않는다. 항상 사용자 응답을 제공한다는 원칙은 검증 실패 본문을 공개하거나 기술 장애를 성공 처리하는 뜻이 아니다.

장애는 evidence_insufficient로 숨기지 않는다. answered의 미충족 요구에는 원인별 limitation, 답변을 막지 않은 검색 장애에는 notices를 쓴다. `answerStatus`·`notices`와 web_* notice code는 [MCP 실행 계약 3.5절](ai-chatbot-mcp-actions.md#35-사용자-응답과-내부-실패의-구분)대로 공개 계약에 들어갔고(2026-10-30), 웹 검색 도구가 생기면 그 code를 만든다.

## 5. 개인정보와 모델 전송

- 서버가 공개 기업명·공개 키워드·기간으로 검색어를 검사한다. 질문 원문·대화 전체·userId·이메일·보유 표시·수량·매입가·수익률을 외부 검색에 보내지 않는다.
- Q07 개인 범위는 서버에서 확인한다. 전체 포트폴리오를 한 검색어로 보내지 않으며 기업 목록/조회 패턴 로그도 접근 통제한다.
- 공급자, 정제 검색어, requirementId, 결과/오류·비용·캐시 원본 toolCallId를 감사한다. 키·인증 헤더는 남기지 않는다.
- snippet을 OpenAI에 반환하기 **전에** MCP 서버가 web-search:<공급자>의 model-send grant·목적·수신자·크기/내용을 검사한다. Jev 후검증에도 별도 전송 권한을 검사한다.
- 공급자 약관, 처리 항목·국가·기간, 필요한 개인정보 처리방침·동의 절차를 확정하기 전 실제 검색은 비활성이다.

## 6. 출처·검증·재열람 목표 계약

web_reported basis와 Citation.sourceKind=web_result를 추가한다. 서버가 sourceId·requirementId·URL·제목·도메인·공급자·검색 시각·게시 시각·허용 snippet·snapshot ID를 실제 도구 결과로 구성한다. 내부 evidence_grounded나 Q01 zoop_documented로 승격하지 않는다.

결정론 검사는 출처 ID·요구 매핑·구간 인용·URL 스킴·시각·권한을 확인한다. Jev는 제공된 snippet이 주장을 지지하는지 검사한다. 이것은 원문 전체나 현실의 진실성 검증이 아니다. snippet에 없는 수치·인과·전망을 추가하지 않는다.

투자 권유·목표주가·가격/수익 예측 금지는 web_reported를 포함한 모든 구간에 적용한다. ‘매수 의견’, ‘목표주가 상향’ 같은 snippet을 인용해 금지를 우회하지 않는다. 그 부분은 제외하고 다른 확인된 사업 사실만 답하며, 필요한 구간을 안전하게 분리할 수 없으면 안내한다.

저장 권리가 허용한 snapshot만 고정하여 재열람한다. 재열람 시 검색을 재실행하지 않으며 현재 권한·철회·보유 기간을 재검사한다. 재현할 수 없는 근거 구간은 가리고 최신 사실인 것처럼 갱신하지 않는다.

## 7. 출시 전 남은 결정

| 항목 | 현재 결정 / 남은 조건 |
| --- | --- |
| 공급자·계약 | 미선정. 가격·품질·처리 국가·권리 검토 후 선정 |
| 호출 상한 | 턴 2회·회원 일 20회·프로젝트 일 500회, 실제 지표로 보정 |
| 비용 상한/경보액 | 미정. 공급자 단가로 예약 금액과 일/월 금액 상한 확정 전 활성화 금지 |
| 저장·로그 기간 | 공급자 저장/재배포 권리와 팀 정책 확정 필요 |
| 개인정보 방침·동의 | 실제 공급자 처리 조건을 반영해 검토·개정 여부 확정 |
| source grant | OpenAI·Jev 수신자/목적별 model-send 등록 필요 |
| schema·화면 | web_reported/web_result·answerStatus/notices·limitation·guard 동시 구현 필요 |
| 실제 품질·시간 | 기존 서버 계획 / Luna MCP를 같은 세트로 비교 |

개발 순서는 [개발 계획](../development/ai-chatbot-implementation-plan.md)의 latency spike(MCP 서버 단독 시험·합성 Responses replay·승인된 소량 live 측정) → 합성 MCP fixture → 호출/캐시/실패 gate → 출처·저장·화면 계약 → 개인정보/공급자 확정 → 웹 검색 포함 승인된 소량 실측이다. 기능 플래그 기본 꺼짐을 유지한다. 이 개정은 테스트 실행·실제 모델 호출·출시 승인을 뜻하지 않는다.
