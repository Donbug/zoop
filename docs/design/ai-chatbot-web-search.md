# ZOOP AI 챗봇 보조 웹 검색 설계

문서 상태: 2026-10-27 제품 결정 반영 · 구현 예정 · 실제 공급자 연결은 출시 조건 충족 후 활성화

기준 정책: [ZOOP-AIG-001 v0.10](../ZOOP_AI_거버넌스_정책.md) / [설계 요약](ai-chatbot-design-summary.md) / [MCP·복합 질의·화면 동작 계약](ai-chatbot-mcp-actions.md)

화면 추적: `D-AI-01`, `D-AI-02`

## 1. 확정된 범위

- 웹 검색은 **Q01을 제외한 Q02~Q08의 보조 도구**다. 내부 조회가 비어야만 사용할 수 있는 Q03 전용 대체 경로가 아니다.
- 사용 가능과 필수 호출은 다르다. 출처 요청, 최신 정보, 외부 설명 보완 등 목적이 있을 때만 계획에 넣는다. 단순 일반 개념은 Luna 일반 지식으로 처리할 수 있다.
- 각 도구가 웹 검색을 재귀적으로 호출하지 않는다. 서버 오케스트레이터가 요구별 검색을 계획하고 중복 호출을 합친다.
- Jev가 승인된 논리 기능 `web.search`를 후보로 제안하고, 목표 설계의 Luna coverage-verifier가 필요·누락·과잉 조회를 검토하며, 최종 실행은 서버가 승인한다.
- MCP 서버 POC에서 검색 도구를 노출한다. 기존 내부 읽기 어댑터를 재사용하며 모델은 실행 권한을 갖지 않는다. MCP 연결과 웹 검색은 아직 구현 완료 기능이 아니다.

2026-10-25 초안의 ‘MCP 미사용’, ‘Q03만’, ‘라우터는 검색 선택 불가’, ‘내부 결과 0건일 때만 검색’, ‘검색 장애를 근거 부족으로 변환’ 결정은 이 문서로 대체한다.

## 2. 유형별 사용과 원천 권한

| 유형 | 보조 웹 검색의 용도 | 웹 결과로 대신할 수 없는 것 |
| --- | --- | --- |
| Q01 서비스 안내 | 사용하지 않음 | 승인된 ZOOP 도움말·화면·정책 |
| Q02 일반 개념 | 출처 요청, 설명 보완, 최신 기술 맥락 | ZOOP 내부 정책. 최신 기업 사실은 Q03 등을 함께 분류 |
| Q03 기업·사건 | 외부 공시·보도·최신 맥락 보완 | 내부 evidence의 검수·공개 상태 |
| Q04 관계·경로 | 조회한 관계의 외부 보도·배경 보완 | 공개 그래프의 실제 간선·경로 존재 및 버전 |
| Q05 기간 비교 | 변화 당시의 외부 사건 설명 | 고정된 두 버전의 차이와 서버 계산값 |
| Q06 브리핑 | 발행 내용의 배경 또는 발행 후 소식 | 원래 회차의 내용·선정 목록·dataAsOf |
| Q07 내 종목 | 권한 확인 후 개별 공개 기업의 뉴스 | 보유·관심 여부와 사용자 개인 데이터 |
| Q08 선정 근거 | 선정에 관련된 공개 사건의 배경 | 실제 적용된 규칙 revision과 기록된 선정 이유 |

Q01+Q03 복합 질문이면 Q03 요구에만 검색을 배정한다. 웹 결과를 Q01 서비스 안내의 근거로 재사용하지 않는다. 내부 그래프에 없는 관계는 외부 보도로 구분할 수 있지만 지도에 존재하는 간선으로 답하거나 포커스 대상으로 만들지 않는다. 검색으로 게시 그래프·발행 브리핑을 수정하지 않는다.

## 3. 계획과 실행 위치

1. 매 새 질문을 requirementId별로 분해·재분류한다. 이전 세션의 분류에 고정하지 않는다.
2. 내부 조회와 외부 검색을 각각 계획한다. 검색 대상·기간이 이미 정해졌으면 독립 조회를 병렬 실행할 수 있다.
3. 관계 탐색에서 얻은 기업을 검색해야 한다면 조회 다음 stage에 검색을 둔다.
4. 성공한 조회가 실제로 비었거나 근거가 부족하면 승인된 예산 안에서 최대 1회의 보충 라운드로 검색을 추가할 수 있다. 사전 계획 검색도 허용하며 무제한 재검색은 금지한다.
5. 원천별 결과로 Luna가 최종 답변을 1회 생성하고 결정론 검사와 의미 검증을 거친다. 생성 뒤 검색·재생성 루프는 만들지 않는다.

내부 조회 장애·권한 거부·truncated를 ‘자료 없음’으로 바꾸어 검색으로 덮지 않는다. 필수 요구를 충족할 예산이 없으면 생성 전에 범위를 확인한다. 선택적 보완 검색만 생략할 때는 명시적 요구를 누락하지 않아야 하며 생략 사유를 기록한다.

## 4. 예산과 실패 처리

- 기존 전체 도구 12회·동시 4회·개별 3초·도구 단계 10초·전체 job 60초 목표 안에서 실행한다. MCP 왕복과 검색에 별도 시간을 덧붙이지 않는다. 단계별 상한 합이 전체 기한을 넘을 수 있으므로 deadline guard를 유지한다.
- 초기 웹 검색 상한은 실행 시도당 공급자 검색 호출 3회다. 이는 Q 유형 개수 제한이 아니다. 같은 결과를 여러 요구에 사용하면 requirementId 매핑을 남긴다.
- 검색어 3개를 공급자에 각각 보내면 MCP 봉투가 하나여도 전체 호출 예산에서 3회로 계산한다. 자동 재시도도 실제 호출 수·기한에 포함한다.
- 검색어당 최대 5건, 중복 제거 후 전체 최대 10건, snippet은 건당 최대 500자다. 다른 문서와 합친 기존 20개 문서 상한도 적용한다.
- POC는 공급자의 제목·URL·snippet·게시 시각만 사용하며 임의 URL 본문 fetch/크롤링을 열지 않는다.
- 성공한 검색의 0건은 근거 부족으로 처리할 수 있다. **실행한 검색의 timeout/unavailable은 기존 도구 실패 정책대로 실행 실패**이며 `evidence_insufficient`로 숨기지 않는다. 장애 시 부분 성공은 별도 정책·계약 변경 없이는 허용하지 않는다.

## 5. 개인정보와 외부 전송

- 모델은 검색 의도를 제안할 수 있지만 서버가 공개 기업명·공개 키워드·기간으로 검색어를 구성·검사한다. 원문 질문, 대화 전체, userId, 이메일, 수량·매입가·수익률을 전송하지 않는다.
- Q07은 서버에서 본인 범위를 먼저 확인한다. 외부에는 개인 식별자나 ‘내 보유 종목’ 표식 없이 필요한 개별 공개 기업 검색만 보낸다. 전체 포트폴리오를 하나의 검색어로 내보내지 않는다. 기업 목록과 조회 패턴도 민감할 수 있으므로 최소화·로그 접근 통제를 적용한다.
- 공급자, 실제 정제 검색어, 목적 requirementId, 실행 결과·비용을 접근 통제된 감사 기록에 남긴다. 키는 비밀 설정으로 관리한다.
- 실제 활성화 전 공급자 약관, 처리 위탁·국외 이전 해당 여부, 처리 항목·국가·보유 기간, 필요한 개인정보 처리방침·동의 절차를 검토·반영한다.
- snippet 모델 전송에는 원천 `web-search:<공급자>`의 operator `model-send` grant가 필요하다. 외부 문서의 지시는 비신뢰 데이터로 처리한다.

## 6. 공개 응답·검증 계약 (추가 예정)

아래는 **목표 계약**이다. 현재 DTO·OpenAPI·프런트엔드가 지원한다는 뜻이 아니다. 구현 시 계약 원본·생성 명세·클라이언트·검증기를 함께 변경한다.

| 항목 | 목표 값과 의미 |
| --- | --- |
| 구간 basis | `web_reported`: 외부 검색 자료에 근거한 설명, ZOOP 검수 evidence와 구별 |
| Citation.sourceKind | `web_result` |
| 웹 출처 | 서버 발급 sourceId, requirementId 매핑, URL, 제목, 도메인, 공급자, 검색 시각, 공급자가 제공한 게시 시각, 허용된 snippet 및 snapshot 식별자 |
| answerBasis | 여러 basis가 섞이면 기존 `mixed` 규칙 |
| 화면 | ‘웹 검색 결과 · ZOOP 미검증’, 검색 시점과 원문 링크 |

서버가 출처 ID·URL·인용문을 실제 도구 결과로 채운다. 결정론 검사는 sourceId 존재, 요구 매핑, basis 분리, 인용 구간 일치, URL 허용 스킴, 시각·버전·권한을 확인한다. Jev 의미 검증은 주장이 제공된 snippet에 의해 지지되는지 검사한다. 이는 원문의 진실성이나 전체 본문 검증을 보장하지 않는다. snippet에 없는 수치·인과·전망을 만들지 않는다.

일반 지식만 사용한 Q02 구간은 `general_knowledge`이며 인용을 꾸미지 않는다. 검색한 설명은 별도의 `web_reported` 구간이다. 웹 인용을 Q01 `zoop_documented`나 내부 `evidence_grounded`의 근거로 승격하지 않는다. 투자 판단 금지 규칙은 모든 구간에 적용한다.

## 7. 저장·재열람

약관이 허용한 결과 snapshot과 검색 시점을 고정하여 재열람한다. 재열람은 새 검색이 아니며 현재도 동일함을 보장하지 않는다. 현재 권한·철회 정책을 다시 적용하고, 저장 권리가 없거나 보관 기한이 만료되어 근거를 재현할 수 없는 구간은 가린다. ‘최신 정보 다시 조회’는 새 질문/job이다. 보관 기간은 공급자 계약 확정 전 임의로 정하지 않는다.

## 8. 구현·출시 순서

1. 합성 fixture로 `web.search` capability, 요구별 계획, MCP 봉투를 구현한다. 기능 플래그는 기본 꺼짐이다.
2. basis/sourceKind 확장, snapshot 저장, 검사·guard·화면 배지를 함께 구현한다.
3. 공급자·예산·저장 및 표시 권리·개인정보 절차·model-send grant를 확정한다. 공급자는 아직 미선정이다.
4. Q01 차단, Q02~Q08 보완, 중복 제거, 개인정보 최소화, 실패·예산·재열람을 replay로 검증한다.
5. 승인된 소량 실제 호출로 지연·비용을 측정한 뒤 활성화한다. 기존 한도를 만족하지 못하면 검색을 출시하지 않고 예산 정책을 별도로 검토한다.
