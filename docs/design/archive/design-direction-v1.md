## 1. 비주얼 방향 (Visual Direction & Identity)

### 1.1 브랜드 정체성과 핵심 은유
- **서비스 한 줄 정의**: "내 종목 주변 사건의 연결과 근거를 보여주는 금융 지도"
- **이름의 기원 ("줍 - Zoop")**:
  - 일상어 '줍다'에서 유래: 시장에 흩어진 뉴스, 공시, 공급망 관계의 파편을 "주워 모아" 유의미한 맥락으로 엮어냄.
  - 가벼운 신조어 느낌에 머무르지 않고, 금융 데이터의 신뢰성과 객관적 사실 확인이라는 본질을 결합.
- **핵심 디자인 은유: "금융 항해도와 증거 지도 (Financial Evidence Cartography)"**:
  - 복잡한 시장 정보를 다룰 때 일반적인 핀테크 앱이 취하는 '흰 카드 + 파란 CTA 버튼' 템플릿(Generic Fintech Slop)이나 화려한 보라-파랑 그라데이션(AI Slop)을 단호히 배제합니다.
  - 대신, 항해사가 바다의 지형과 암초를 파악하기 위해 펼치는 **정밀한 해도(Chart)와 나침반 도구**의 시각 언어를 차용합니다.
  - 데이터의 크기나 화려함보다 **"선(관계)의 명확성"**과 **"출처(근거)의 투명성"**을 시각적으로 극대화합니다.

```
[일반 핀테크 템플릿의 함정]          [줍(Zoop)의 금융 항해도 방향]
┌───────────────────────────┐      ┌───────────────────────────┐
│ 무의미한 보라/파랑 그라데이션  │      │ 차분한 딥 스프루스 틸 & 슬레이트│
│ 불필요한 카드 중첩 & 네온 효과 │  vs  │ 정밀한 항해 그리드 & 절제된 선  │
│ 출처 없는 "AI 상승 확률 87%"   │      │ 명확한 원문 인용 & "근거 3건"   │
│ 기능 과밀로 인한 시각적 피로   │      │ 1카드 1질문, 여백 기반 스캔    │
└───────────────────────────┘      └───────────────────────────┘
```

### 1.2 디자인 원칙 4훈 (비전공자 팀원 공유용)
1. **단 하나의 문장도 근거 없이 주장하지 않는다 (No Claim Without Evidence)**
   - AI 요약이든 그래프 간선이든, 화면에 노출되는 모든 해석과 연결은 반드시 원문 기사/공시의 인용 위치(`Evidence`)로 연결되어야 합니다. 근거가 없으면 "판단 보류"가 올바른 상태입니다.
2. **그래프는 목적지가 아니라 경로다 (Graph as Navigation, Not Destination)**
   - 그래프 시각화는 복잡함을 자랑하는 도식이 아닙니다. 내가 관심 있는 종목 주변의 사건을 탐색하는 도구일 뿐입니다. 언제나 텍스트 리스트(`[목록으로 보기]`)로 1:1 대체될 수 있어야 합니다.
3. **색 단독으로 정보를 전달하지 않는다 (Shape & Text Before Color)**
   - 한국 주식 관례(상승 빨강, 하락 파랑)를 따르되, 색각이상자 및 고대비 환경을 위해 항상 **부호(+/-), 방향 아이콘(▲/▼), 등락률 텍스트**를 3중 병기합니다.
4. **기능 과밀을 방지하고 여백으로 신뢰를 준다 (Spacious Scanning)**
   - 금융 초보자는 정보가 빽빽할수록 공포를 느낍니다(강사 피드백). 화면당 하나의 핵심 질문에 답하고, 세부 수치와 전문 필터는 2단계('더 보기') 뒤로 배치합니다.

### 1.3 라이트 테마 기본 및 다크 테마 정책
- **라이트 테마 (기본)**:
  - 항해 지도 양식의 깨끗한 슬레이트 화이트(`#F8FAFC`)를 기본 캔버스로 사용하고, 카드는 순백색(`#FFFFFF`)에 1px 정밀 테두리(`#E2E8F0`)를 적용합니다.
  - 브랜드 메인 색상은 깊고 진한 **딥 스프루스 틸(`#0A5C48`)**로, 차분한 신뢰감과 지적인 탐색 분위기를 형성합니다.
- **다크 테마 (동등 지원)**:
  - 칠흑 같은 검정이 아닌 야간 항해 콘솔을 연상시키는 **딥 네이비 슬레이트(`#0B0F17`)**를 기본 배경으로 채택합니다.
  - 카드는 `#151C28`, 테두리는 `#242F42`를 사용하며, 브랜드 색상은 명도를 높인 **민트 틸(`#2DD4BF`)**로 전환하여 야간 가독성을 보장합니다.

### 2.1 WCAG 2.2 AA 명도 대비 계산 공식 및 검증
웹 콘텐츠 접근성 지침(WCAG 2.2 AA) 및 한국형 웹 콘텐츠 접근성 지침(KWCAG 2.2 5.4.3)에 따라, **일반 본문 텍스트는 4.5:1 이상**, **큰 텍스트(18pt 이상 또는 14pt 볼드) 및 그래픽 UI 컴포넌트(포커스 링, 노드 테두리)는 3.0:1 이상**의 명도 대비를 엄격히 준수합니다.

#### 상대 휘도($L$) 계산 공식
sRGB 색상 성분 $R, G, B \in [0, 255]$에 대해 정규화 값 $C_{sRGB} = C / 255$:
$$C_{linear} = \begin{cases} \frac{C_{sRGB}}{12.92} & (C_{sRGB} \le 0.04045) \\ \left(\frac{C_{sRGB} + 0.055}{1.055}\right)^{2.4} & (C_{sRGB} > 0.04045) \end{cases}$$
$$L = 0.2126 \times R_{linear} + 0.7152 \times G_{linear} + 0.0722 \times B_{linear}$$
명도 대비 비율(Contrast Ratio):
$$\text{Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05} \quad (\text{단, } L_1 \ge L_2)$$

## 3. 컴포넌트 명세 (Component Specifications)

프로토타입에 실제로 필요한 27종 컴포넌트(기본 UI 12종 + 도메인 특화 15종)를 명세합니다.

### 3.1 기본 UI 컴포넌트 (12종)

#### 1. Button
- **목적**: 폼 제출, 모달 열기, 상태 변경 등 사용자의 단일 액션을 실행합니다.
- **변형(Variants)**:
  - `primary`: 배경 `brand.primary`, 텍스트 `text-inverse`
  - `secondary`: 배경 `surface-raised`, 테두리 `border-strong`, 텍스트 `text-primary`
  - `ghost`: 배경 투명, 호버 시 `surface-sunken`, 텍스트 `text-primary`
  - `destructive`: 배경 `error.bg-weak`, 테두리 `error.border`, 텍스트 `error.text`
- **상태(States)**: default, hover, active, focus-visible(2px `border-focus` 아웃라인, 오프셋 2px), disabled(opacity 0.45, 커서 `not-allowed`), loading(`Spinner` 아이콘 표시, `aria-busy="true"`, 클릭 차단).
- **접근성 규칙**: 버튼 텍스트는 목적을 명확히 명시. 아이콘 단독 버튼은 반드시 `aria-label` 필수. 최소 터치 타깃 $36 \times 36\text{px}$ (모바일 $44 \times 44\text{px}$).
- **Do & Don't**:
  - [Do] "관심 종목 3개 저장하기", "닫기"
  - [Don't] "확인", "클릭", "Go" 등 모호한 단독 동사.

#### 2. Input
- **목적**: 종목명 검색, 자유 질문 텍스트 입력을 받습니다.
- **변형**: `default`, `search`(좌측 돋보기 아이콘, 우측 삭제 버튼).
- **상태**: default, hover, focus(테두리 `border-focus`, 링 그림자), disabled, error(테두리 `error.main`, 하단 에러 메시지 연결).
- **접근성 규칙**: 항상 `<label>`과 `id`로 연결(`aria-labelledby` 또는 시각적 숨김 라벨). 에러 발생 시 `aria-invalid="true"` 및 `aria-describedby="error-id"` 제공.

#### 3. Select / Combobox
- **목적**: 그래프 기간 필터(1일/1주일/1개월), 정렬 기준 선택.
- **상태**: closed, open, selected, disabled.
- **접근성 규칙**: Radix `Select` 프리미티브 기반. 키보드 ↑/↓ 탐색, Enter 선택, Esc 닫기. `aria-expanded` 상태 자동 동기화.

#### 4. Badge
- **목적**: 상태, 카테고리, 메타데이터의 간결한 시각적 라벨.
- **변형**: `default`, `neutral`, `outline`, `success`, `warning`, `error`.
- **접근성 규칙**: 순수 장식이 아니면 스크린리더가 텍스트를 읽을 수 있도록 구성. 색상에만 의존하지 않고 라벨 텍스트 포함.

#### 5. Card
- **목적**: 연관된 정보를 그룹화하는 독립적인 표면 컨테이너.
- **구조**: `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter`.
- **상태**: default(배경 `surface-raised`, 테두리 `border-subtle`, 그림자 `elevation.raised`), interactive(호버 시 테두리 `border-strong`, 커서 포인터).
- **Do & Don't**:
  - [Do] 독립된 이슈 1건, 브리핑 세션 1개를 카드 단위로 캡슐화.
  - [Don't] 카드 안에 무의미한 중첩 카드를 3중 이상 감싸는 행위 금지.

#### 6. Tabs (SegmentedTabs)
- **목적**: 동일 맥락 내에서 뷰 전환 (예: 그래프 ↔ 목록, 요약 ↔ 관계도).
- **상태**: active(배경 `surface-raised`, 볼드, 그림자), inactive(배경 투명, 텍스트 `text-secondary`), focus-visible.
- **접근성 규칙**: Radix `Tabs` 기반. `role="tablist"`, `role="tab"`, `aria-selected="true/false"`. 좌우 방향키로 탭 전환.

#### 7. Dialog / Sheet (Modal & BottomSheet)
- **목적**: 상세 정보(기업 상세, 근거 문서 원문, AI 고지문)를 레이어로 표시.
- **형태**: 데스크톱에서는 중앙 모달 또는 우측 슬라이드 시트, 모바일(≤768px)에서는 3단 스냅 바텀시트(peek 20% / half 50% / full 90%).
- **접근성 규칙**:
  - 열릴 때 `role="dialog"`, `aria-modal="true"`.
  - 백그라운드 스크롤 잠금 및 포커스 트랩(Focus Trap).
  - Esc 키 또는 좌측 상단 [닫기] 버튼 클릭 시 닫히며, **열기 직전 클릭했던 트리거 버튼으로 초점 자동 복귀(NFR-12)**.

#### 8. Tooltip
- **목적**: 전문 금융 용어 풀이, 아이콘 버튼 설명, 축약된 텍스트 전체 보기.
- **상태**: hidden, visible (마우스 호버 또는 키보드 포커스 시 200ms 지연 후 노출).
- **접근성 규칙**: `role="tooltip"`, 트리거에 `aria-describedby` 연결. Esc 키로 툴팁 즉시 닫기 가능.

#### 9. Toast
- **목적**: "설정이 저장되었습니다", "링크가 복사되었습니다" 등 일시적인 피드백 알림.
- **지속 시간**: 4000ms 후 자동 퇴장 (마우스 호버 시 일시 정지).
- **접근성 규칙**: `aria-live="polite"`, `role="status"`. 중요한 에러 알림은 토스트 대신 인라인 `ErrorState` 사용.

#### 10. Skeleton
- **목적**: 비동기 데이터 로딩 중 레이아웃 흔들림(CLS) 방지용 플레이스홀더.
- **형태**: 텍스트 라인 스켈레톤, 카드 스켈레톤, 그래프 원형 노드 스켈레톤.
- **접근성 규칙**: `aria-hidden="true"` 설정, 컨테이너에 `aria-busy="true"` 명시.

#### 11. EmptyState
- **목적**: 검색 결과 없음, 관심 종목 없음, 연결된 사건 없음 상태 안내.
- **구조**: 아이콘(중립 회색) + 원인 설명 헤딩("검색된 사건이 없어요") + 해결 가이드 문구("철자를 확인하거나 다른 검색어를 입력해 보세요") + 복귀 CTA 버튼.
- **접근성 규칙**: 장애나 오류가 아님을 명확히 안내하며 스크린리더가 즉시 원인을 읽을 수 있도록 구성.

#### 12. ErrorState
- **목적**: API 통신 실패, 네트워크 장애, 권한 오류 상태 안내.
- **구조**: 경고 아이콘 + 실패 원인 문구("정보를 불러오지 못했어요") + [다시 시도] 버튼 + [이전 화면으로] 버튼.
- **금지 규칙**: **오류가 발생했을 때 0건(빈 상태)으로 위장하여 렌더링하는 것을 엄격히 금지함 (NFR-11).**

### 3.2 도메인 특화 컴포넌트 (15종)

#### 13. DatasetBadge
- **목적**: 화면에 표시된 데이터의 출처 신뢰 수준을 사용자에게 상시 고지.
- **종류**:
  - `approved-live` (실데이터 승인본): 초록 배경, 방패 아이콘, 문구: `실데이터 승인본`.
  - `synthetic-preview` (합성 미리보기): 보라 배경, 실험 비커 아이콘, 문구: `합성 미리보기`.
- **배치**: 메인 헤더 우상단, 노드 패널 상단, 브리핑 카드 상단에 필수 고정.

```
[실데이터 승인본]  [합성 미리보기]
 🛡️ 실데이터 승인본   🧪 합성 미리보기
```

#### 14. AiBadge / AiNotice / AiDisclosureSheet
- **목적**: 인공지능기본법 제31조 준수 — AI 생성 요약문임을 명확히 인식시키고 생성 한계 고지.
- **AiBadge**: AI 요약 카드 좌상단에 `✨ AI 요약` 라벨 부착 (아이콘 + 텍스트 병행).
- **AiDisclosureSheet ("이 요약은 어떻게 만들어졌나요?")**:
  - 클릭 시 열리는 시트: ① 사용 모델 정보, ② 요약에 사용된 원문 문서 범위 및 수집 기준 시각, ③ 사람 검수 여부("본 요약은 알고리즘 자동 추출본으로 전문 에디터의 최종 감수를 거치지 않았습니다"), ④ 면책 안내("요약문은 원문을 대체할 수 없습니다").

#### 15. EvidenceList / EvidenceQuote
- **목적**: 사건이나 관계의 근거가 되는 원문 인용구를 투명하게 제시.
- **EvidenceQuote 구조**:
  - 언론사/공시 출처 배지 + 발행 시각 (예: `연합뉴스 · 2026-09-29 09:15`)
  - 인용구 박스 (`surface-sunken`, 좌측 3px 브랜드 보더): `"삼성전자는 HBM3E 12단 제품의 고객사 퀄 테스트를 통과했다고 밝혔다..."`
  - 검증 상태 배지: `인용 검증 완료` (초록) 또는 `원문 대조 필요` (주황).
  - [원문 보기 ↗] 외부 링크 버튼.

#### 16. IssueCard
- **목적**: 시장이나 기업에 발생한 구체적 사건(Issue)의 단위 카드.
- **구성**:
  - 상단: 사건 타이틀 (40자 이내, bold) + 발생 시각 (미상일 경우 '발생 시각 미상' 표기)
  - 중단: 관련 기업 칩 (최대 3개: `[삼성전자]`, `[SK하이닉스]`)
  - 하단: `근거 3건` 링크 + 영향 분류 배지 (디자인시스템: 호재 가능성/악재 가능성/혼합/판단 보류, 프로토타입: `준비 중`)

#### 17. BriefingCard
- **목적**: 출근길/퇴근길 시장 및 내 종목의 변화를 3분 안에 파악하는 요약 카드.
- **구성**:
  - 헤더: `아침 브리핑` / `저녁 브리핑` 배지 + `기준 시각: 07:30 KST (발행 시각 미확정)` + `약 3분 소요`
  - 탭: `[핵심 요약]` / `[관계도 보기]`
  - 본문: 상위 3~5개 `IssueCard` 수직 나열
  - 푸터: `참고 문서 총 14건` + `DisclaimerNote`

#### 18. CompanyHeader
- **목적**: 기업 노드 패널 및 기업 상세 화면 최상단 헤더.
- **구성**:
  - 종목명(한글) + 티커 코드 (`005930`)
  - 개인화 맥락 배지: 내 보유 종목일 경우 `보유 (비중 18%)`, 관심 종목일 경우 `관심`
  - 현재가 및 등락률 영역: 프로토타입에서는 `UnavailableValue`("시세 준비 중") 배치

#### 19. RelationTypeTag
- **목적**: 그래프 간선 및 관계 패널에서 연결의 성격을 규정.
- **라벨 매핑**:
  - `INVOLVES` → `직접 관련` (파란색 태그, 실선 아이콘)
  - `STRUCTURALLY_RELATED_TO` → `사업 구조상 관련` (보라색 태그, 파선 아이콘)
  - `FOLLOWS` → `후속 사건` (주황색 태그, 화살표 아이콘)
  - `SHARES_ISSUE` → `같은 사건에 등장 (파생)` (회색 태그, 점선 아이콘)

#### 20. GraphCanvas
- **목적**: 기업 및 이슈 간의 관계 네트워크를 시각화하는 메인 인터랙션 캔버스.
- **구성 요소**: Cytoscape.js 뷰포트 + 좌하단 확대/축소/리셋 컨트롤러 + 우상단 `[목록으로 보기]` 전환 버튼.
- **접근성**: `role="img"`, `aria-label`을 동적으로 갱신 ("삼성전자 중심 관계 8개, 이슈 2개 표시 중").

#### 21. GraphLegend
- **목적**: 그래프 요소의 시각적 형태와 간선 종류의 의미를 안내.
- **구성**:
  - 노드 형태: `○ 기업 노드`, `⬡ 이슈 노드`
  - 간선 형태: `── 직접 관련`, `- - 사업 구조상 관련`, `·· 같은 이슈 공유(파생)`
  - **필수 주의문구 고정 표기**: *"노드의 크기, 화면상의 거리, 선의 굵기는 위험도나 인과관계의 크기를 의미하지 않습니다."*

#### 22. GraphModeSwitch
- **목적**: 그래프 탐색 모드 전환 (FR-16).
- **옵션 3종**:
  1. `시장 전체`: 핵심 이슈와 대표 기업 중심 부분 그래프
  2. `내 자산`: 모의 계좌에 연결된 보유 종목 중심 부분 그래프
  3. `관심 종목`: 사용자가 선택한 관심 종목(1~3개) 중심 부분 그래프
- **상태 처리**: 보유 종목이 없을 때 `내 자산` 선택 시 즉시 빈 상태 안내 및 계좌 연결 유도.

#### 23. NodePanel
- **목적**: 캔버스에서 노드를 클릭했을 때 열리는 세부 맥락 패널 (데스크톱: 우측 400px 슬라이드 패널, 모바일: 바텀시트).
- **구성**:
  - 헤더: 노드 명칭, 분류 태그, [상세 보기 ↗], [✕ 닫기]
  - 탭: `[관련 사건]` / `[연결 관계]` / `[AI에게 묻기]`
  - 본문: 해당 노드에 직접 연결된 `IssueCard` 및 `EvidenceList`

#### 24. DisclaimerNote
- **목적**: 금융소비자보호법 및 자본시장법 준수 투자 유의 면책 고지.
- **표준 문구**: *"본 서비스의 정보는 보도 및 공시를 분석한 참고 자료이며, 투자를 권유하거나 수익을 보장하지 않습니다. 투자 판단의 책임은 본인에게 있습니다."*
- **노출 위치**: 브리핑 하단, AI 질문 답변 하단, 기업 상세 하단에 1줄 고정.

#### 25. UnavailableValue ("준비 중" 표시 컴포넌트)
- **목적**: PoC 백엔드에 아직 데이터가 없거나 수집 대기 중인 항목을 지어내지 않고 정직하게 안내.
- **표시 형태**: 텍스트 영역에 `–` 또는 `[ 준비 중 ]` 회색 뱃지 표시 + 마우스 호버 시 툴팁("현재 시세 및 감성 분석 데이터 연동을 준비하고 있습니다").
- **적용 대상**: 주가 시세, 등락률, AI 감성 점수, 재무 PER/PBR.

#### 26. SentimentLabel (디자인시스템 전용)
- **목적**: 향후 감성 분석 도입 시 사용할 규격 컴포넌트 (프로토타입 화면에서는 `UnavailableValue`로 렌더).
- **디자인시스템 정의 라벨**:
  - `호재 가능성`: 연한 빨강 칩 + 텍스트 (한국 시장 관례)
  - `악재 가능성`: 연한 파랑 칩 + 텍스트
  - `혼합`: 연한 보라 칩 + 텍스트 ("긍·부정 요인 공존")
  - `판단 보류`: 연한 회색 칩 + 텍스트 ("근거 불충분 또는 해석 대립")
- **규칙**: 주가 상승/하락 확률 수치(예: "상승 확률 85%") 표기를 엄격히 금지함.

#### 27. PriceChangeBadge
- **목적**: 주가 및 등락률 표기 컴포넌트.
- **표시 규칙**:
  - 상승: 빨강 텍스트 + `+` 부호 + `▲` 아이콘 + 수치 (예: `▲ +2.34%`)
  - 하락: 파랑 텍스트 + `-` 부호 + `▼` 아이콘 + 수치 (예: `▼ -1.50%`)
  - 보합: 회색 텍스트 + `-` 아이콘 + `0.00%`
  - 데이터 부재 시(현재 프로토타입 기본): 회색 `시세 준비 중` 배지 렌더링.

## 4. 그래프 상호작용 명세 (Graph Interaction & Visualization)

Cytoscape.js를 기반으로 구축되는 관계 그래프의 상호작용 및 시각화 규칙을 정의합니다.

### 4.1 노드 예산 (Node Budget) 및 과밀 방지
금융 초보자에게 수백 개의 노드는 분석 도구가 아니라 시각적 소음입니다.
- **초기 진입 노드 예산**: **최대 20개 이내**로 제한 (FR-16).
  - 중심 기업 노드: 1개
  - 직접 연결된 핵심 이슈 노드: 최대 6개
  - 이슈에 연결된 1차 이웃 기업 노드: 최대 12개
  - 합계: $1 + 6 + 12 = 19 \le 20$개.
- **확장 규칙 (Expansion)**:
  - 노드 더블클릭 또는 패널의 `[이웃 1단계 펼치기]` 클릭 시 **추가 노드는 1회당 최대 8개**까지만 로드.
  - 화면 내 전체 누적 노드가 **60개에 도달하면 추가 확장을 제한**하고, 안내 팝오버 노출:
    *"표시된 노드가 많아 복잡해요. 일부 노드를 접거나 다른 종목을 중심으로 볼까요?"*

### 4.2 포커스 인터랙션 및 흐림(Dimming) 결정 (D-06 확정)
- **결정**: **포커스 + 컨텍스트 흐림(Focus + Context Dimming) 방식을 기본값으로 채택**.
- **동작 방식**:
  - 특정 노드 클릭(선택) 시:
    - 선택된 노드 및 **직접 1홉으로 연결된 이웃 노드와 간선**은 100% 불투명도(`opacity: 1.0`) 유지.
    - 선택 노드 외곽에 3px 브랜드 포커스 링(`graph.focus.ring`, `#0A5C48`) 및 후광 표시.
    - 그 외 관련 없는 노드와 간선은 **불투명도 0.22(`graph.dimmed.opacity`)로 흐림 처리**하고 클릭 이벤트를 비활성화.
  - 공간적 맥락 유지 이유: 노드를 아예 화면에서 숨겨버리면(Hide) 전체 네트워크 지형이 왜곡되어 사용자가 방향 감각을 잃게 됨(Kumu / Neo4j Bloom 연구 결과).
  - **예외 옵션**: 시각적 복잡도를 극도로 낮추고 싶은 사용자를 위해 그래프 툴바에 `[선택 관계만 남기기]` 토글을 제공하여 필요 시 숨김 모드로 전환 가능.

### 4.3 레이아웃 알고리즘 권고
- **기본 레이아웃: `cose` (Compound Spring Embedder) 또는 `cola`**:
  - Cytoscape.js 내장 물리 시뮬레이션 기반 레이아웃.
  - 기업 노드와 이슈 노드가 서로 밀어내고 연결된 간선이 당겨주어 자연스러운 클러스터를 형성.
  - 애니메이션 시간: 400ms (`motion.duration.slow`). `prefers-reduced-motion` 활성화 시 애니메이션 없이 즉시 렌더.
- **보조 레이아웃 (공급망/사건 순서 보기): `dagre`**:
  - 후속 사건(`FOLLOWS`)이나 공급망 관계를 확인할 때 상단 툴바에서 `[흐름 순으로 정렬]` 버튼 클릭 시 위에서 아래로 흐르는 계층형 레이아웃 적용.

### 4.4 노드 및 간선 시각화 형태 규칙
- **기업 노드 (Company)**:
  - 형태: 지름 48px 원형 (모바일 터치 44px 이상 만족).
  - 스타일: 흰색 배경, 2px 브랜드 틸 테두리, 중앙에 기업 로고 또는 2~4자 종목 약칭.
  - 상태 표식: 보유 종목은 우상단에 초록 점(`holding-badge`), 관심 종목은 노란 점(`watchlist-badge`).
- **이슈 노드 (Issue)**:
  - 형태: $44 \times 44\text{px}$ 육각형(Hexagon) 또는 둥근 마름모. 기업 노드와 즉각 구별.
  - 스타일: 밝은 슬레이트 회색 배경(`#F1F5F9`), 1.5px 진회색 테두리(`#64748B`), 중앙에 신문/사건 아이콘.
- **간선 시각 규칙**:

| 간선 유형 | 실제 의미 | 선 스타일 | 색상 토큰 | 두께 | 화살표 |
|:---|:---|:---:|:---|:---:|:---:|
| `INVOLVES` | 이슈와 기업의 직접 관련 | **실선 (Solid)** | `edge.involves` (`#0284C7`, Sky) | 2.0px | 없음 (무방향) |
| `STRUCTURALLY_RELATED_TO` | 사업 구조상(공급/협력 등) 관련 | **파선 (Dashed)** | `edge.structurally-related` (`#6D28D9`, Purple) | 1.5px | 대상 방향 |
| `FOLLOWS` | 사건의 시간적/인과적 후속 전개 | **실선 (Solid)** | `edge.follows` (`#D97706`, Amber) | 1.5px | 후속 사건 방향 화살표 |
| `SHARES_ISSUE` | **동일 이슈 공유 파생 가상 경로** | **점선 (Dotted)** | `edge.shares-issue` (`#94A3B8`, Slate) | 1.0px | 없음 (낮은 대비) |

> ⚠️ **범례 고정 경고문**: 기업과 기업을 잇는 점선은 직접 승인된 거래 관계가 아니며, "동일한 사건 보도에 함께 등장했음"을 의미하는 파생 경로입니다.

### 4.5 키보드 접근성 및 비시각 대안 뷰 (RelationList)
- **캔버스 자체 접근성**:
  - `<div role="img" aria-label="그래프: 삼성전자 중심 관계 8개, 이슈 2개 표시 중">`
  - 노드 선택이 변경될 때마다 `aria-live="polite"`로 상태 1회 낭독.
- **동기화 대안 뷰 (`RelationList`)**:
  - 그래프 캔버스 우상단에 `[목록으로 보기]` 버튼 항시 노출.
  - 클릭 시 그래프 캔버스가 숨겨지고 동일한 부분 그래프 데이터를 계층형 HTML 리스트(`<ul>`, `<li>`)로 렌더링.
  - 키보드 조작: `Tab` 키로 리스트 진입, `↑`/`↓` 방향키로 항목 탐색(로빙 tabindex), `Enter`로 상세 패널 열기, `Esc`로 선택 해제.
- **초점 이동 규칙 (NFR-12)**:
  - 노드 클릭 또는 리스트에서 Enter 입력 시 → **열리는 `NodePanel`의 첫 번째 헤딩(`<h3>`)으로 키보드 초점을 강제 이동**.
  - 패널의 [닫기] 버튼 누름 또는 Esc 입력 시 → **원래 선택했던 노드/리스트 아이템으로 초점 복귀**.

### 4.6 패널 상태 유지 및 동시성 레이스 컨디션 방지 (TC-16)
- **패널 열림/닫힘 시 상태 보존 (UI-09)**:
  - 우측 패널을 닫았다가 다시 열어도 캔버스의 중심 좌표(pan), 줌 배율(zoom), 선택된 노드 ID는 리셋되지 않고 유지됩니다.
- **느린 네트워크 응답의 덮어쓰기 방지 (TC-16)**:
  - 사용자가 기업 A를 클릭한 직후, 응답이 오기 전에 기업 B를 연속 클릭하는 시나리오 대응.
  - 프론트엔드 상태 머신 규칙:
    1. 새 노드 클릭 시 이전 요청의 `AbortController.abort()`를 즉시 호출하여 네트워크 취소.
    2. 로컬에 단조 증가하는 요청 시퀀스 번호(`requestSeq`)를 발급.
    3. API 응답이 도착했을 때 응답의 시퀀스 번호가 현재 활성 시퀀스 번호와 일치하지 않으면 결과를 폐기하고 화면을 갱신하지 않음.

#### 주요 문구 (UX Writing)
- 메인 타이틀: "내 종목 주변 사건의 연결과 근거를 보여주는 금융 지도"
- 데모 버튼: "데모 체험 시작하기 (로그인 없이 둘러보기)"

- 한도 초과: "처음에는 집중적인 분석을 위해 최대 3개 종목만 선택할 수 있어요."
- 튜토리얼 완료: "이제 나만의 금융 지도가 완성되었어요! 메인 화면으로 이동합니다."

### UI-03: 메인 관계 그래프 화면 (Main Knowledge Graph)

#### 목적
선택한 탐색 모드(시장/자산/관심)에 맞춰 종목과 이슈 간의 관계 네트워크를 시각화하고 실시간 탐색을 제공합니다.

#### ASCII 와이어프레임
```
+--------------------------------------------------------------------------+
| 줍(Zoop) | [탐색 모드: 관심 종목 ▼]  🔍 종목/이슈 검색     [🛡️실데이터] [마이] |
+--------------------------------------------------------------------------+
| 종목 사이드바   | 메인 그래프 캔버스                         [목록으로 보기] |
| ────────────── | ─────────────────────────────────────────────────────── |
| 내 관심 종목    |        [⬡ HBM 공급 계약]                                |
| • 삼성전자     |              | (INVOLVES)                                |
|   시세 준비 중  |              v                                           |
| • 현대차       |        (○ 삼성전자) <···(SHARES_ISSUE)···> (○ SK하이닉스) |
|   시세 준비 중  |              |                                           |
|                |              v (STRUCTURALLY_RELATED)                    |
|                |        (○ 원익IPS)                                       |
| [종목 편집]    |                                                         |
|                | ─────────────────────────────────────────────────────── |
|                | [범례] ○ 기업  ⬡ 이슈  ── 직접  - - 구조적  ·· 같은사건    |
|                | * 거리와 선 굵기는 주가 위험도나 인과를 뜻하지 않습니다.    |
|                | [ + ] [ - ] [전체 보기]           (노드 4개 / 간선 3개 표시) |

```

#### 표시 데이터 및 연동 API
- **엔드포인트**:
  - `GET /api/graph?mode=watchlist&asOf=latest&limit=20`
- **응답 필드 매핑**:
  - `nodes`: `[{id, kind: "company"|"issue", label, properties: {ticker, isHolding, isWatchlist}}]`
  - `edges`: `[{id, source, target, relation_type: "INVOLVES"|"STRUCTURALLY_RELATED_TO"|"FOLLOWS"|"SHARES_ISSUE", role, assertion_status}]`
  - `datasetKind`: `"approved-live"` 또는 `"synthetic-preview"`

#### 화면 상태
- `Loading`: 캔버스 중앙에 펄스 애니메이션 스켈레톤 노드 3개 및 "관계를 분석하고 있어요..." 라벨 노출.
- `Empty`: 자산 모드에서 보유 종목이 없는 경우 빈 캔버스 대신 안내 화면 출력:
  *"아직 연결된 계좌가 없어요. 상단 모드를 [관심 종목]으로 변경하거나 계좌를 연결해 보세요."*
- `Error`: 네트워크 오류 시 캔버스 내부에 `ErrorState` 노출 및 [다시 불러오기] 버튼 제공.

#### 주요 문구 (UX Writing)
- 캔버스 스크린리더 라벨: `"삼성전자 중심 관심 종목 지도. 기업 노드 3개, 이슈 노드 1개가 표시되어 있습니다."`

### UI-11: 공통 상태 (Common States & Feedback)

#### 목적
네트워크 지연, 데이터 부재, 시스템 오류 발생 시 사용자가 길을 잃지 않도록 일관된 피드백을 제공합니다.

#### 명세 규칙 (NFR-01, NFR-11)
1. **스켈레톤 로딩 (Loading)**:
   - 데이터 로드 중 콘텐츠 크기와 동일한 형태의 펄스 스켈레톤을 노출하여 Layout Shift(CLS)를 방지.
2. **빈 상태 (Empty State)**:
   - "데이터가 없습니다"라는 차가운 문구 대신, 원인과 대안 경로를 안내.
   - 예: `"선택한 기간 동안 발생한 사건이 없어요. 기간 필터를 [전체]로 변경해 볼까요?"`
3. **오류 상태 (Error State)**:
   - **오류를 빈 목록(0건)으로 속이지 않는다**: API 통신 에러 발생 시 목록을 빈 채로 두지 않고, 반드시 붉은색 경고 아이콘과 함께 [다시 시도] 버튼을 노출.
   - 예: `"일시적인 오류로 최신 지도를 불러오지 못했어요. 잠시 후 다시 시도해 주세요. [다시 시도]"`

## 6. UX 라이팅 및 컴플라이언스 규칙

비전공자 초보 투자자가 금융 데이터를 부담 없이 읽을 수 있도록 토스/뱅크샐러드의 검증된 라이팅 원칙을 채택합니다.

### 6.1 기본 원칙 4개 (Zero Jargon)
1. **해요체 사용**: 모든 대화형 문구와 안내문은 친근한 해요체를 기본으로 합니다 ("확인하세요" → "확인해 보세요").
2. **능동형 문장**: 피동형을 지양하고 주체가 명확한 능동형 문장을 씁니다 ("조회되었습니다" → "불러왔어요").
3. **긍정형 표현**: 부정적인 단어 대신 해결 가능한 긍정형으로 씁니다 ("데이터가 없어서 조회가 불가합니다" → "새로운 관심 종목을 추가해 보세요").
4. **한자어 전문용어 풀어쓰기 (`{명사}+{명사}` 회피)**:

| 전문/시스템 용어 | 줍(Zoop) 표준 쉬운 말 표기 |
|:---|:---|
| `INVOLVES` | **직접 관련** |
| `STRUCTURALLY_RELATED_TO` | **사업 구조상 관련** |
| `FOLLOWS` | **후속 사건** |
| `SHARES_ISSUE` | **같은 사건에 등장 (파생 연결)** |
| `Ego Network` | **내 종목 중심 지도** |
| `Node / Edge` | **종목·사건 / 연결선** |
| `Extraction / Mention` | **기사 속 사건 추출** |
| `Candidate / Validation` | **관계 검증 대기** |

금융소비자보호법, 표시광고법, 금융감독원 가이드라인에 따라 아래 단어의 UI 사용을 전면 금지합니다.

### 6.3 법률 및 안전 고지문 표준문 (Standard Disclaimers)

#### 2. 인공지능(AI) 생성물 사전 고지 (인공지능기본법 제31조)
> *"본 브리핑과 요약문은 인공지능(AI)이 수집된 뉴스 및 공시 원문을 바탕으로 추출·생성한 결과물입니다. 요약문은 원문을 대체할 수 없으며, 반드시 기재된 원문 출처와 작성 시각을 함께 확인하시기 바랍니다."*

#### 3. 데이터셋 성격 고지 (배지 툴팁)
- **실데이터 승인본**: *"사내 검증 파이프라인(Jev 검증)을 통과하여 원문 인용 위치가 일치하는 승인 데이터입니다."*
- **합성 미리보기**: *"시스템 기능 검증 및 시연을 위해 생성된 모의 데이터이며, 실제 시장 상황과 다를 수 있습니다."*

#### 4. 시세 및 감성 미제공 고지
