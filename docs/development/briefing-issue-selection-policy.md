# 이슈 중심 선정 및 판단 비교 v1

선정 키는 저장된 사건 `issueId`다. 같은 기업의 계약·투자·자본정책이 독립 사건이면 각각 선정할 수 있다. 핵심은 최대 3개이며 부족한 개수를 채우지 않는다. 기업 수·주가 크기는 사실 검증이나 신규성의 대체 근거가 아니다.

## 선정 경로

`briefing_grouped_run.py --issue-selection-policy issue-selection-policy-v1`로 새 실행을 준비한다. 기존 인자·승인·비용 제한은 그대로다. 인자를 생략하거나 `legacy`를 지정하면 기존 기록의 재현 경로를 유지한다. 정책을 바꾼 실행은 다른 run/input identity를 사용한다.

1. 기존 정확 인용·공개 시각·의미 지원·재보도 검증을 유지한다.
2. 모델은 전체 후보의 평가와 적격 사건 제안을 작성한다. 최대 3개 제약은 코드의 최종 선정에 적용한다.
3. 저장된 `importance`를 기본 우선순위로 사용한다. 신규 사건 또는 실제 추가 사실이 입증된 변경만 적격이다. `MATERIAL_UPDATE`는 현재 회차의 delta 인용이 필요하다.
4. 기존 복합 `priority` 점수로 순서를 바꾸지 않는다. 같은 중요도에서는 안정적인 사건 ID 순서다. 시세가 없다는 이유로 0점을 주거나 제외하지 않는다.
5. 같은 기사에서도 서로 다른 사건과 별도 인용 구간은 허용한다. 동일 원문 버전의 동일 인용을 다른 ID로 재사용한 제안은 중복으로 제외한다. 의미상 재보도 검증은 기존 평가/검증 경로를 함께 사용한다.
6. 개별 제안이 검증을 통과하지 못하면 다음 적격 제안을 검토한다. 원본 무결성·입력/계약 오류는 계속 실행을 차단한다.
7. 각 선택에 `selectionPolicy`를 보존한다. 정책 버전·cutoff·중요 이유·이번 회차에서 다루는 이유·기업 관계의 인용·주가/관계 신호의 사용 여부를 구분한다.

v1은 기존 importance를 호환 평가값으로 재사용한다. 새로운 세부 사업 중요도 등급이나 주가 반응 점수를 소급 생성하지 않는다. 가격과 관계는 설명의 맥락이며 현재 정렬 가산점은 없다. 비교 가능한 이슈별 가격 구간·관계 검증 기록이 마련되기 전까지 `not_used` / `context_only`로 남긴다. 따라서 정책 변경으로 순서가 달라졌다고 새 사실이나 AI의 판단이 바뀌었다고 표현하지 않는다.

## 이슈·기업별 비교 입력

`briefing_company_outlook.freeze_issue_inputs(...)`는 사건 하나당 독립 입력을 만든다. 같은 회사가 서로 다른 사건의 입력에 반복되는 것은 정상이다. `comparisonContract=issue-company-v1`과 `issueId`를 고정하며 기존 v1~v5 입력/기록은 재작성하지 않는다.

- 같은 사건 ID + 같은 기업 ID가 일치해야 한다. 제목·회사명 유사성으로 사건을 연결하지 않는다. 후속 발표는 기존 묶음 단계에서 동일 사건 ID로 승인되어 있어야 한다.
- 출근은 가장 최근 이전 퇴근 발행본, 퇴근은 당일 출근 발행본을 먼저 결정한다. 주말 때문에 직전 달력 날짜로 제한하지 않는다.
- 해당 발행본에 대상 사건·기업 판단이 없으면 비교 불가다. 더 오래된 다른 판단으로 임의 대체하지 않는다.
- 여러 사건을 합쳐 쓴 과거 기업 전체 판단은 사건 하나의 판단으로 승격하지 않는다. 동일 시점의 여러 판본이 모호하면 비교를 보류한다.
- 기존 추적 조건은 별도 목록에 보존하며 새 핵심 목록에서 빠졌다는 이유로 완료·무효·만료 처리하지 않는다.

생성/검증 validator도 이 입력의 사건·기업·이전 판본·cutoff를 확인한다. 이 변경만으로 과거 문안을 새 AI 결과로 바꾸거나 발행 DB를 갱신하지 않는다. 새 입력으로 생성·독립 검증하는 일은 유료 실행 승인 및 발행 경로에서 별도로 수행한다.

## 화면 (D-BRF-01/02)

기본 화면은 주요 시장 지표와 짧은 핵심 이슈 카드다. 클릭하면 이슈 상세 안에서 기업별로 한 줄 결론, 긍정 가능성/위험, 확인된 새 정보, 실제 시세, 이전 판단 및 다음 확인 조건을 구분한다.

짧은 결론·기회·위험은 저장된 출처 연결 문장을 사용한다. 긴 사업 분석·전망·위험 문장은 삭제하지 않고 `자세한 사업 분석·전망`에 보존한다. 원문 인용, 시세 관측 범위, 독립 S3 검증 및 전체 보기도 유지한다. 새 요약/등급을 브라우저에서 생성하지 않는다.

비교문은 저장된 이전 발행본을 공개 조회 API로 읽고 사건/기업/판본/근거를 대조한 경우에만 이슈 상세에 표시한다. 회사만 같은 다른 사건의 이전 판단은 비교로 쓰지 않는다. 이전 회차 조회 실패나 개정 판본 불일치가 현재 회차를 숨기지 않는다. 기존 전체 보기의 역사 문안은 보존한다.

## 오프라인 재현

```sh
python scripts/briefing_issue_policy_replay.py \
  --bundle /path/to/preserved/bundle-v2.json \
  --sources /path/to/preserved/sources.jsonl \
  --output /path/to/new-policy-replay
```

별도 디렉터리에 write-once `policy-comparison.json`을 만든다. 원본 bundle/source SHA를 검증하고 전후 SHA 일치를 확인한다. 키나 네트워크 transport 인자는 없다. 기존 선정 제안과 평가를 재사용하며, **미선정 후보 전체를 새로 평가한 결과가 아니다.** 회차별 기존/새 순서·분리된 입력·보존할 과거 추적 조건을 담는다.

실제 보존 4회차(10/21 퇴근~10/23 출근)를 대조한 결과, 선정 수 2/2/1/1을 유지하고 2회차에서 동률 정렬 순서가 바뀌었다. 화면의 사건별 근거 연결 문장 6건·저장 시세·기존 결과는 유지했다. 새 AI 호출은 0회다. 이 자료에는 같은 회사의 독립 사건 3개가 한 회차에 모인 사례가 없어 해당 조건은 합성 회귀 시험으로 확인했다. 새 선정의 품질 개선이나 전체 후보 재선정 성공을 주장하지 않는다.

원문·실제 응답·기존 호출 영수증은 새 PR에 추가하지 않는다. 공개 테스트는 작성한 합성 문장만 사용한다.
