# 개인화 이슈의 실제 AI 분석 (FS036 / D-BRF-01·02)

기존 개인화 선정 결과를 입력으로 사용해 해당 이슈가 보유·관심 기업에 미치는 사업 영향·관찰 조건을 새로 작성한다. 공통 브리핑과 평가 원장은 그대로 두고 `briefing_personal_analyses`에 회원별 별도 버전을 추가한다. GET 조회는 모델을 호출하지 않는다.

## 입력과 작성

`scripts/briefing_personal_ai.py`는 회차/동결 입력 SHA·인용·대상 기업·시세 cutoff를 검증한다. 모델에는 회원 ID/이메일/수량/금액/쿠키를 보내지 않는다. 관련 공개 기업명·모의 보유/관심 분류·정확 인용·저장 시세·비교 가능한 같은 이슈+기업의 이전 판단만 보낸다.

프롬프트는 `docs/prompts/personal-briefing-v1/`과 역할·날짜 표현을 보완한 `personal-briefing-v1.1/`에 있다. 생성 모델은 기존 설정인 `gpt-6-luna`다. 사업 영향 방향을 주가 전망과 구분하고, 원문 밖의 계약/직접 발언/납품 주체·효과 규모·인과관계를 추가하지 않는다. 문장별 evidenceIds를 연결하고 독립된 같은 모델의 별도 요청으로 대조한다. 검증에 실패한 초안도 보존하며 통과 결과만 등록한다.

## 저장과 복원

`scripts/briefing_personal_ai_import.py`는 생성·검증 요청/응답의 원본 bytes SHA, 입력·문안·검증 결과의 정확한 일치를 확인한 뒤 SQL을 작성한다. `--member-id`, `--calls <완료 기록 폴더>`(반복 가능), `--record <PASS 기록>`(반복 가능), `--output <새 비공개 폴더>`를 사용한다. 출력 SQL은 원문/평가를 갱신하지 않고 해당 회원·회차·선정 기준과 일치하는 AI 버전만 추가한다. 실제 모델 결과·회원 식별자·키 파일·SQL 출력은 공개 저장소에 포함하지 않는다.

후속 migration `V20261030121200`은 현재 보유/관심 집합·pool version·선정 이슈와 기업 조합을 고정한 입력, 검증 결과, 두 provider receipts를 저장한다. UPDATE를 막고 새 버전을 추가하며, 회원 삭제의 개인정보 파기를 위해 회원 FK의 DELETE CASCADE는 허용한다.

`GET /api/v1/briefings/{id}/personalized/issues` 응답의 `aiAnalysis`는 다음을 구분한다.

- `available`: 현재 회원·종목·선정 결과에 정확히 대응하고 원문 현재 권한과 생성/검증 증거가 일치하는 새 분석. `draft.overview`, `draft.issues[issueId].companies[companyId]`에 사업 영향·보유/관심 관점·실제 가격 관측·다음 확인사항을 제공한다.
- `unavailable`: 미생성, 새 기준 종목에 해당하는 결과 부재, 관련 적격 이슈 없음, 저장된 증거 불일치. 원래 선정·연결 사실은 유지하며 이전 AI 설명을 다른 회원이나 다른 종목 조합에 재사용하지 않는다.

직전 같은 이슈·기업의 개인화 분석이 있으면 추적 항목에 `personalAiNextCheck`와 `personalAiResultVersion`을 추가한다. 원래 확인사항을 덮어쓰지 않으며, 후속 근거 부재를 조건 충족으로 표시하지 않는다. AI가 비교 불가 안내의 출근/퇴근 명칭을 혼동할 수 있으므로, 화면은 그 안내 문장을 사실 요약에서 제외하고 현재 회차 메타데이터로 비교 불가 문구를 표시한다. 원본 모델 응답은 보존한다.

운영용 회원별 자동 생성 스케줄러나 새 사용자 요청을 곧바로 유료 실행하는 HTTP 쓰기 API를 활성화하지 않는다. 이번 연결은 명시적으로 실행한 생성·검증 결과의 저장과 실제 회원 API/화면 복원까지다.
