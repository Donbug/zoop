# 브리핑 후보 검토와 수집 부족 회차

## 해결하는 문제

첫 후보의 추출·독립 검증이 보류되면 다음 미검토 후보를 확인한다. 회차 호출 한도가 부족해 다음 후보를 보내지 못한 경우는 `not_sent / remaining_shared_call_capacity`로 기록한다. 실제 검증 보류와 구분하며, 과거 판정·완료 응답·미응답 예약을 수정하거나 재전송하지 않는다.

자동화 경로는 native 근거·기업 연결 검증 뒤에도 **사업 중요도·새 정보 평가와 독립 검증**을 수행한다. 여기서 선정할 이슈가 없으면 첫 native 성공에서 종료하지 않고 다음 미검토 기사를 검토한다. 날짜·기업·회원별 예외를 두지 않으며 향후 자동 회차에도 같은 흐름을 사용한다. 적격 후보가 나오면 남은 문서는 `not_examined / selection_satisfied`, 후보가 소진되거나 마감·예산에 도달하면 각 미검토 사유를 별도 파일에 남긴다.

사업 근거·기업명 식별·재보도·발행 시각·원문 범위·독립 검증 기준은 유지한다. 한도를 늘렸다는 이유로 후보가 검증을 통과하거나 발행되는 것은 아니다.

## 호출 수와 비용

작업기의 `BRIEFING_ROUND_CALL_LIMIT`은 기본 16회이며 16~64의 정수만 허용한다. 후보 보완 시 권장 설정은 **32회**다. 공통·선택 개인화 작업기는 같은 회차 한도를 사용한다. 공유 분석 사용 시 발행용 8회, 그 외 10회를 먼저 남겨 둔다. 새 자동화의 `selectionContinuation`은 추가로 선정·독립 검증·최대 1회 보완을 위한 4회를 남긴다. 따라서 공유 분석·32회 설정에서는 native가 실질적으로 사용할 수 있는 상한이 20회다. 작은 설정에서 native 최소 5회와 이 예비분이 함께 들어가지 않으면 시작을 거부하며 승인 한도를 조용히 늘리지 않는다. 이전 `selectionContinuation` 없는 실행기의 16회 기본 동작은 유지한다.

문서 내부 12회·검증 단계별 4회를 새 자동화의 독립적인 중단 기준으로 사용하지 않는다. 문서 예산과 관계/영향 검증 단계 한도를 회차의 실제 잔여 예약에서 계산한다. 다음 기사가 있고 예산이 충분하면 다음 정상 문서 최소 5회와 현재 문서 탈락 시 추가될 선정 검증 4회분을 남긴다. 32회 공유 설정의 첫 문서는 이 경우 최대 11회이며, 뒤에 후보가 없으면 잔여 native 예산을 사용한다. 단계별 한도를 합산해 호출할 수 있다는 뜻이 아니며 실제 물리 전송에는 공통 회차·하루 비용 가드가 항상 먼저 적용된다. 성공 후보 한 건의 일반적인 native 소요는 5회이며 관계 수와 보완에 따라 늘 수 있다.

설정을 32회로 변경할 때는 선택 개인화 작업기의 비공개 authorization JSON에도 `roundCallLimit: 32`를 명시해야 한다. 없으면 기존 16회로 해석한다. 공통 설정·선택 작업기 설정·authorization의 한도가 다르면 시작을 거부한다. 실제 서버 설정과 권한 파일을 이 PR이 자동 변경하지 않는다.

물리 요청 수를 늘려도 기존 **회차 USD 1 / 하루 USD 2** 보수적 비용 상한은 그대로다. 응답 미확인 요청도 예약에 포함하며 같은 요청을 다시 보내지 않는다. 개인화는 기존 허용 회원과 선택 종목 범위를 그대로 사용한다.

## 마감 전 선정과 완료 결과 재사용

내부 CLI `prepare-selection`은 실제 대기/실행 중인 회차와 동일한 ID·일정·입력 구간이며 마감 전 30분 이내일 때만 읽기 전용 입력을 만든다. 원문 공개·최초 관측·수집 시각은 실제 준비 시각을 넘을 수 없다. 선정 평가와 독립 검증을 통과하면 이 정확한 `prepared.json`·입력 SHA·요청/응답·검증 기록을 고정한다. 마감 후 발행은 이를 재사용하므로 선정 평가를 다시 유료 전송하지 않는다. UTC/KST 표기가 달라도 동일 순간인 회차만 허용하며 다른 회차·파일 변경·현재 권한 철회는 거부한다.

선정용 checkpoint는 원장 시도가 완료된 뒤에만 저장한다. 발행 단계의 캐시 읽기는 원장에 `replay`로 남기고 물리 호출과 구분한다. 마감 전 발행은 여전히 금지한다. 마감까지 전송 타임아웃과 기록 여유가 없으면 새 요청을 보내지 않고 `preparation_deadline`을 남긴다. 기존 실패 회차를 자동으로 다시 열지 않는다.

## 출력 잘림과 미응답의 구분

새 자동화의 native 출력 여유를 12,000→30,000 토큰으로 조정하되 모델·추론 설정·인용 및 검증 계약은 유지한다. 출력 상한에는 추론 토큰도 포함되므로 화면에 보이는 JSON 분량만을 위한 한도가 아니다. [OpenAI 추론 모델 문서](https://developers.openai.com/api/docs/guides/reasoning)를 참고한다.

`live_output_truncated`와 `live_set_work_exhausted`는 해당 응답을 실제로 수신했고, S2 집계 또는 S3 개별 응답 영수증과 공통 예약이 모두 정산된 경우에만 알려진 문서 미완료로 분류한다. 원본 부분 결과는 그대로 보존하고 다음 미검토 기사를 확인한다. 부분 검증의 pending·보류를 적격으로 올리지 않는다. 미응답·전송 불명·진행 중 요청·권한 오류를 이 경로로 숨기거나 동일 요청을 재전송하지 않는다. 출력 여유를 늘려도 다음 실제 입력에서 완성을 보장하는 것은 아니다.

## 본문과 수집 범위

- 한국경제의 기존 `articletxt`와 새 `article-container > article-body-wrap > article-body` 구조를 지원한다. 본문이 서로 다른 두 영역으로 잡히면 계속 거부한다.
- 접근 제한·robots·HTTP 거절·기사 시각·회차 마감·기업 식별 검사는 유지한다. 새 DOM 지원은 유료 본문이나 접근 제한을 우회하지 않는다.
- RSS 날짜와 제목은 수집 순서를 정하는 힌트다. 회차 날짜에 해당하는 후보를 먼저 확인한 뒤 기사 원문 시각으로 다시 검증한다. 제목의 기업 언급만으로 선정하지 않는다.
- 비공개 source registry의 허용 가능한 상한을 소스별 기사 시도 12→24, 보존 문서 4→8로 확장한다. 기존 registry 값은 그대로 동작한다. 확대하려면 별도 새 revision과 해당 grant를 검토해 배포해야 한다. 총 요청·시간·robots 제한은 그대로다.
- 파싱에 실패한 경우에도 이미 받은 원문 응답과 수집 시각·SHA를 비공개 작업 경로에 먼저 보존한다. 재실행 시 완료된 수집 결과를 사용하며 외부에 자동 공개하지 않는다.

## 수집·검증이 부족한 회차

시장 지표는 기업 후보 검증보다 먼저 독립적으로 수집한다. 기업 이슈가 보류됐다는 이유로 이미 확보한 마감 이전 지표를 버리지 않는다. 기존 발행본의 지표를 나중 값으로 덮어쓰지 않는다.

마감 전에 관측한 아래의 확정된 부족 상태만 `coverage-notice.json`에 원본 파일 SHA와 함께 고정한다.

1. 회차에 사용할 기업 자료가 없음
2. 검토를 끝낸 기업 후보가 모두 보류됨
3. 나머지 후보가 호출 한도 때문에 미검토됨
4. 다음 후보/선정 요청을 마감 전에 끝낼 전송 여유가 없어 미전송됨

이때 신규 핵심 이슈·전망을 만들어 채우지 않는다. 마감 후 서버가 현재 읽기 권한과 원본 해시를 다시 확인한 **이전 발행 이슈·확인 조건**을 `importance-continuity-v2 / coverage_limited`로 제공한다. UI에는 수집·검증 부족, 이전 자료 기준 시각, 전망 미갱신이 구분된다. 복기 전용 회차를 다시 복기 원본으로 택하지 않는다.

확인한 후보의 선정 검증은 완료했지만 중요도·새 정보 기준에 미달한 경우와 자료/검증 미완료는 안내 문구와 `coverage`에서 구분한다. 어느 쪽도 전체 시장에 새 소식이 없다고 단정하지 않는다. 기존 `/api/v1/briefings/{id}/recap`도 `continuity`에 고정된 이전 원문을 읽으며 현재 읽기 권한·정정·중단 검사를 유지한다. 과거 비교 필드가 없다는 이유로 유효한 고정 복기를 놓치거나, 새로운 다른 회차를 대신 찾아 붙이지 않는다.

개인화 복기는 고정한 선택 종목과 연결된 이전 이슈만 제공한다. 해당 종목의 이전 이슈가 없으면 없음으로 표시하고 다른 종목으로 채우지 않는다.

이전 원본이 없거나 현재 읽기 권한을 잃었다면 발행하지 않는다. provider 예외·미응답·진행 중 요청은 이 부족 상태로 바꾸지 않는다. 이미 종료된 실패 회차를 자동 재실행하거나 과거 마감 시각으로 새 관측을 소급하지 않는다. 기존 복구 승인·원장 fencing을 적용한다.

## 검증과 적용 범위

`scripts/tests`의 회귀 검사와 `BriefingServerPostgresTest`에서 후보별 보류/미검토 구분, 한도·돈·미응답 예약, 원문 범위, 이전 원문 보존, DB 발행·HTTP 조회, 개인화 종목 제한을 검사한다. 공급자 응답은 직접 작성한 합성 fixture이며 실제 모델 호출을 포함하지 않는다. `briefingAutoIntegrationTest`는 수집부터 공통·개인화 배달까지 기존 자동화 경로를 검증한다.

이번 변경은 내부 operator CLI의 `prepare-selection`·`prepare-coverage`와 기존 조회 DTO를 사용하며 새 공개 REST API나 DB migration은 추가하지 않는다. 배포·서버 설정 변경·실제 재생성은 별도 단계다. 기존 5회차 기록의 오프라인 회귀에서는 당시 탈락 판정·부분 결과·원본 해시를 보존하고 다음 후보 검토, 한도 및 복기 경계를 확인한다. 미검토 기사의 새 AI 분석이나 실제 서버 재발행 성공을 의미하지 않는다. 실제 새 회차 실행 전에는 기존 잔여 예산과 입력 크기에 따라 호출 수·비용을 다시 산정한다.
