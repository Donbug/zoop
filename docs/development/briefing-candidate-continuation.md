# 브리핑 후보 검토와 수집 부족 회차

## 해결하는 문제

첫 후보의 추출·독립 검증이 보류되면 다음 미검토 후보를 확인한다. 회차 호출 한도가 부족해 다음 후보를 보내지 못한 경우는 `not_sent / remaining_shared_call_capacity`로 기록한다. 실제 검증 보류와 구분하며, 과거 판정·완료 응답·미응답 예약을 수정하거나 재전송하지 않는다.

사업 근거·기업명 식별·재보도·발행 시각·원문 범위·독립 검증 기준은 유지한다. 한도를 늘렸다는 이유로 후보가 검증을 통과하거나 발행되는 것은 아니다.

## 호출 수와 비용

작업기의 `BRIEFING_ROUND_CALL_LIMIT`은 기본 16회이며 16~64의 정수만 허용한다. 후보 보완 시 권장 설정은 **32회**다. 공통·선택 개인화 작업기는 같은 회차 한도를 사용한다. 공유 분석 사용 시 발행용 8회, 그 외 10회를 먼저 남겨 두고 나머지로 native 후보를 검토한다. 성공 후보 한 건의 일반적인 native 소요는 5회다. 처리 중 보완이 필요하면 더 사용될 수 있다.

설정을 32회로 변경할 때는 선택 개인화 작업기의 비공개 authorization JSON에도 `roundCallLimit: 32`를 명시해야 한다. 없으면 기존 16회로 해석한다. 공통 설정·선택 작업기 설정·authorization의 한도가 다르면 시작을 거부한다. 실제 서버 설정과 권한 파일을 이 PR이 자동 변경하지 않는다.

물리 요청 수를 늘려도 기존 **회차 USD 1 / 하루 USD 2** 보수적 비용 상한은 그대로다. 응답 미확인 요청도 예약에 포함하며 같은 요청을 다시 보내지 않는다. 개인화는 기존 허용 회원과 선택 종목 범위를 그대로 사용한다.

## 본문과 수집 범위

- 한국경제의 기존 `articletxt`와 새 `article-container > article-body-wrap > article-body` 구조를 지원한다. 본문이 서로 다른 두 영역으로 잡히면 계속 거부한다.
- 접근 제한·robots·HTTP 거절·기사 시각·회차 마감·기업 식별 검사는 유지한다. 새 DOM 지원은 유료 본문이나 접근 제한을 우회하지 않는다.
- RSS 날짜와 제목은 수집 순서를 정하는 힌트다. 회차 날짜에 해당하는 후보를 먼저 확인한 뒤 기사 원문 시각으로 다시 검증한다. 제목의 기업 언급만으로 선정하지 않는다.
- 비공개 source registry의 허용 가능한 상한을 소스별 기사 시도 12→24, 보존 문서 4→8로 확장한다. 기존 registry 값은 그대로 동작한다. 확대하려면 별도 새 revision과 해당 grant를 검토해 배포해야 한다. 총 요청·시간·robots 제한은 그대로다.
- 파싱에 실패한 경우에도 이미 받은 원문 응답과 수집 시각·SHA를 비공개 작업 경로에 먼저 보존한다. 재실행 시 완료된 수집 결과를 사용하며 외부에 자동 공개하지 않는다.

## 수집·검증이 부족한 회차

시장 지표는 기업 후보 검증보다 먼저 독립적으로 수집한다. 기업 이슈가 보류됐다는 이유로 이미 확보한 마감 이전 지표를 버리지 않는다. 기존 발행본의 지표를 나중 값으로 덮어쓰지 않는다.

마감 전에 관측한 아래의 확정된 부족 상태만 `coverage-notice.json`에 원본 파일 SHA와 함께 고정한다.

1. 회차에 사용할 기업 자료가 없음
2. 검토를 끝낸 기업 후보가 모두 보류됨
3. 나머지 후보가 호출 한도 때문에 미검토됨

이때 신규 핵심 이슈·전망을 만들어 채우지 않는다. 마감 후 서버가 현재 읽기 권한과 원본 해시를 다시 확인한 **이전 발행 이슈·확인 조건**을 `importance-continuity-v2 / coverage_limited`로 제공한다. UI에는 수집·검증 부족, 이전 자료 기준 시각, 전망 미갱신이 구분된다. 복기 전용 회차를 다시 복기 원본으로 택하지 않는다.

개인화 복기는 고정한 선택 종목과 연결된 이전 이슈만 제공한다. 해당 종목의 이전 이슈가 없으면 없음으로 표시하고 다른 종목으로 채우지 않는다.

이전 원본이 없거나 현재 읽기 권한을 잃었다면 발행하지 않는다. provider 예외·미응답·진행 중 요청은 이 부족 상태로 바꾸지 않는다. 이미 종료된 실패 회차를 자동 재실행하거나 과거 마감 시각으로 새 관측을 소급하지 않는다. 기존 복구 승인·원장 fencing을 적용한다.

## 검증과 적용 범위

`scripts/tests`의 회귀 검사와 `BriefingServerPostgresTest`에서 후보별 보류/미검토 구분, 한도·돈·미응답 예약, 원문 범위, 이전 원문 보존, DB 발행·HTTP 조회, 개인화 종목 제한을 검사한다. 공급자 응답은 직접 작성한 합성 fixture이며 실제 모델 호출을 포함하지 않는다. `briefingAutoIntegrationTest`는 수집부터 공통·개인화 배달까지 기존 자동화 경로를 검증한다.

이번 변경은 내부 operator CLI의 `prepare-coverage`와 기존 조회 DTO를 사용하며 새 공개 REST API나 DB migration은 추가하지 않는다. 배포·서버 설정 변경·실제 재생성은 별도 단계다. 실제 새 회차 실행 전에는 기존 잔여 예산과 입력 크기에 따라 호출 수·비용을 다시 산정한다.
