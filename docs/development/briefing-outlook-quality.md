# 회차 전망의 문장·근거 품질과 추가 데이터 연결 순서

PR #258, 기준 2026-10-21. 대상은 로컬 과거 회차 재생·검증 경로다. PoC 추출·사건 묶음, ERD·공개 API 형태·운영 공급원은 변경하지 않는다.

## 현재 역할 필드 계약: market-context-v2.5-outlook

2026-10-21 실제 실행에서 v2.4의 필수 전망 슬롯은 유지됐지만 forecast_update에 새 forecast용 counterFactors가 들어가 결정 검사에서 거부됐다. 실행한 v2.4 리소스/원응답은 보존하고 v2.5로 분리했다.

- 필수 forecast_update/result_comparison은 targetId·direction=null, counterFactors=[]를 schema로 요구한다. updateAction은 forecast_update만 유지/강화/약화/철회 중 하나이며 나머지는 null이다. 필수 forecast의 targetId/direction은 null일 수 없고 지정 target/방향만 허용하며 evidenceIds/counterFactors는 적어도 하나다.
- 기존 의미 검증은 유지한다. 필드 형식 통과와 사실·해석의 검증 통과는 별개다. 보완 과정에서 전망을 서버가 창작/복사하지 않는다. 기존 v2.3/v2.4를 새 버전으로 재명명하지 않는다.
- 승인된 전체440/신규최대16 안에서 v2.4 4회차12회(3PASS/1WITHHELD) 후, v2.5로10/8 출근·퇴근을4회 재생성·검증했다. 마지막은10/7 출근·퇴근(v2.4) PASS,10/8 출근·퇴근(v2.5) WITHHELD다. 새16회/전체440, 새미응답0·기존unknown2보존이다.
- 마지막 보류는 전망 누락/갱신 필드 오류가 아니다. 출근은 매출·영업이익 결합 및 단일 기업 실적을 대형주 이익·수급으로 확대, 퇴근은 두 실적 지표 결합·인용에 없는 사상최대/수요해석 때문에 거부됐다. 이전 비교·새 전망은 초안에 존재하지만 시도 전체 보류 규칙에 따라 공개하지 않는다.
- 이번 실행의 권위 있는 신규 사용량은 최초424개 digest를 뺀 고유 신규16개의 complete 영수증 합계다(입력7,118,572/출력24,641). 부분 회차 실행 proof의 inputTokens/outputTokens는 해당 layer의 유지된 회차도 포함하므로 여러 layer proof를 단순 합산하지 않는다.
- 코드는 v2.4/v2.5를 별도 지원하며 같은 source/회차/선행 hash·원응답·검증·원장을 계속 결속한다. 실제4개 전부 통과·연속 전망 갱신/성과 비교 완료·운영 발행 준비 완료를 주장하지 않는다. 남은 호출0이고 추가 실행을 하지 않는다.

## 이전 보완 계약: market-context-v2.4-outlook (089 시점)

2026-10-21: 실제 v2.3 실행은 1 PASS/3 WITHHELD다. 아래 보완은 새 유료 실행 전 코드·오프라인/DB 검증이며 기존 결과의 재판정이 아니다.

- fact는 주체·술어·시간·범위가 고정된 독립 검증 주장 하나다. 동일 주장의 대상·기간·약/예정/잠정은 함께 보존한다. 합의 발표/소송 종결/라이선스, 제품 출하/부품 사용, 매출/영업이익은 같은 문서라도 분리한다. 사실 공간이 부족하면 덜 중요한 사실을 줄이며 필수 전망을 지우지 않는다.
- comparison/update는 사실 원자성 대신 역할 완전성을 검사한다. 비교는 이전 모의 판단 + 현재 관측/미관측 + 서버 평가 상태·사유, 갱신은 이전 모의 판단 + 새 근거 + updateAction이다. 서버 unavailable을 적중/실패로 바꾸지 않는다.
- 독립 verifier는 `factUnitAppropriate`(fact만 적용), `comparisonElementsComplete`(비교/갱신만 적용), `evidenceClauseCoverage`, `qualifiersPreserved`, `observableConditionsOnly`와 기존 기본6항목을 각각 검사한다. 역할 미적용 flag=true라는 계약이며 missing/false를 서버가 true로 덮어쓰지 않는다. 의미적 정확성은 여전히 별도 모델 평가가 필요하다.
- v2.4 생성 응답은 `claims` + `requiredClaims`다. 동적 strict schema는 target이 있으면 `requiredClaims.forecast`, 실제 선행 전망이 있는 출근에는 `forecast_update`, 선행 요약이 있는 퇴근에는 `result_comparison` 키와 해당 kind를 매 시도 필수로 요구한다. 필요한 역할의 추가 claim은 선택 배열에도 허용한다. 전체2~8개 제한은 합산한다.
- 보완도 같은 필수 슬롯 schema를 쓰고 이전 초안·판정·고정 입력을 함께 전달한다. 실패한 내용은 고치되 근거 있는 역할을 유지하도록 지시한다. 서버가 누락된 전망을 복사·창작하거나 올바른 claim만 잘라 PASS로 만들지 않는다. 모든 보완 결과를 재검증한다.
- Python/Java는 선택 claims 다음에 필수 슬롯(전망→갱신/비교)을 순서대로 투영한다. 실제 원응답과 일치할 때만 등록하며 공개 API/ERD/기존 DB 형태는 같다. v2.3 prompt/schema/실행/사용량/실패·미응답 기록은 불변이다.
- 일부 회차를 고치면 그 결과를 직전 입력으로 사용하는 후속 유료 회차도 자동 포함한다. 이번 요청3개에는10/8 출근이 의존 회차로 추가되어 실제 순차 재생성은4회차다. 선행 결과가 달라졌는데 이전 맥락을 그대로 사용하는 혼합 계보를 피한다.
- 현재424/425. 독립3개만 계산하면6~12회지만 연속 연결을 유지한4개는 생성+검증 최소8회, 회차별1보완 포함 최대16회다. 예상 누적432~440으로 기존425상한 대비 최소7/최대15 증액이 필요하다. 실제 추가승인은 아직 없으며 이번 보완에서 유료호출0이다. offline plan은 예산 부족을 표시할 수 있으나 execute는 최소 한도 미달 시 transport/출력 쓰기 전 거부한다.

## 이전 v2.3 계약과 당시 구현 이력 (아래의 잔여 호출/미실행 서술은 당시 기준)

### market-context-v2.3-outlook

- 출근: 전체 적격 기업 자료와 직전 퇴근의 실제 구조화 전망에 새 정보를 연결해 오늘의 잠정 방향을 갱신한다.
- 퇴근: 실제 아침 전망과 관측을 구분해 비교하고, 확인된 다음 거래일의 잠정 방향을 제시한다.
- fact 한 개는 독립 사실 하나다. 서버·생성기 모두 원문 문서 하나(동일 문서의 여러 인용 허용) 또는 지표 하나만 허용한다. 여러 원문의 사실은 분리하고 interpretation에서 종합한다. 이 앵커 검사만으로 원자성이 증명되지는 않는다.
- 별도 검증 모델의 `atomicClaim`, `evidenceClauseCoverage`, `qualifiersPreserved`, `observableConditionsOnly`를 모두 요구한다. 누락/false는 PASS가 아니다. 한 문서에 여러 사실이 있을 수 있으므로 의미적 원자성과 모든 사실 절의 근거는 이 검증으로 추가 판단한다. 이는 모델 판단이며 외부 사실 인증이 아니다.
- 원문의 약·최대·예정·미확정, 발언 주체, 기사 보도와 직접 발언, 수치 단위·각 지표의 기준일을 보존한다. 반대 요인도 새 사실을 만들어 적지 않는다.
- 현재 입력에 조건 원천·변수·단위·임계값·확인 시각·평가 기간의 등록부가 없다. 새 전망의 `conditions=[]`만 허용하고, 결과를 조건으로 반복하거나 관측 기준 없는 기대확산·수요유지 가정을 본문으로 우회하는 것도 독립 검증에서 거부한다. 근거가 엇갈리면 `uncertain`과 구체적 반대 요인을 사용한다. 전망 자체를 없애는 정책은 아니다.
- 과거 v2/v2.1/v2.2 결과·조건·요청 해시를 수정하지 않는다. 이전 조건의 충족 자료가 없으면 기존 `condition_outcomes_not_observed`를 유지한다. 빈 새 conditions가 과거 조건 충족의 증거가 되지는 않는다.
- 스키마/버전·목적·근거 참조·조건·생성/검증 실제 응답 바이트를 import 시 재확인한다. 한 회차 WITHHELD를 다른 성공 회차나 과거 기록의 PASS로 바꾸지 않는다.

CLI 신규 실행 기본 버전은 v2.3이다. 기존 완료 계획을 재사용할 때는 원래 `--prompt-version market-context-v2.2-outlook` 등을 명시한다. 프롬프트 4파일은 버전별로 보존하며 같은 출력 폴더에 다른 계획을 덮어쓰지 않는다. 조건 관측 연결을 추가할 때는 새 버전 계약으로 확장하며 현재 제한을 조용히 제거하지 않는다.

## 검증과 운영 전 남은 일

- 오프라인 반례: 여러 문서/지표를 한 fact에 묶음, 근거 없는 사실, 이전 요약을 사실 대체, 목표 결과 반복 조건, 비관측 조건, 한 품질 flag의 false/누락을 각각 거부한다.
- 합성 provider 기록으로 v2.3의 생성→검증→실제 PostgreSQL import/조회 투영과 기존 이력 보존을 검사한다. 합성 응답 통과를 새 실제 AI 문안의 품질 통과라고 보고하지 않는다.
- CI 병렬 기록 저장은 완성된 임시 파일을 원래 경로에 원자적으로 게시한다. 다른 회차가 작성 중인 빈/부분 JSON을 receipt로 읽지 않는다. 기존 파일은 동일 바이트일 때만 재사용한다.
- 409/415 예약으로 잔여 6회다. 현재 v2.2의 실제 4회차는 보존하고, 이번 변경은 새 유료 생성 없이 검사한다. 4회차 새 생성+검증 최소 8회는 현 잔여 한도보다 많다. 기존 완료 호출을 다시 보내거나 이전 399 기준으로 사용량을 되돌리지 않는다.
- BRF-DEV-088에서 runner/importer의 연속 `outlookHistory` 보존을 최대8층으로 확장했다. 각 층의 해시·뉴스/회차·원문·모델 기록·영수증을 검사하며 같은 영수증은 동일 내용일 때만 한 번 계산한다. 더 오래된 baseline으로 돌아가 누적 예산을 우회하지 않는다.
- 실제 관측 원천·사용권한, 추가 실행 한도, 연속 history 지원, 새 실제 문안 검증 후 최종 DB→API→화면 확인이 남는다. 이번 PR 업데이트는 병합/배포 승인이 아니다.

## 2026-10-21 후속 검토: 범위·재현·다음 실행 한도

- `conditions=[]`는 배열 조건의 결정 검사다. 본문에 숨긴 가정·출처 층위·수식어의 의미 판단은 verifier 모델에 의존하며 결정적 보증이 아니다. v2.3 검증 문안에서 옛 v2.2의 비관측 가정 허용 예시를 제거하고, 지속/확산을 사실로 위장한 문장·기자/회사/애널리스트 주체 변경·약/예정 탈락을 거부하도록 명시했다.
- 합성 반례의 기대 판정을 작성해 보류 경로와 원 기록 보존을 검사한다. 합성 verifier 응답은 실제 모델 정확도·재현율을 측정한 결과가 아니다. 실제 새 출력에서 claim별 quote/indicator와 verifier reason을 다시 대조해야 한다. 새 4회차만으로 일반적인 정확도를 계산하지 않는다.
- **실패 범위는 시장 요약 생성 시도 전체다.** 하나의 claim 의미 검증이 실패하면 그 시도의 시장 요약 전체를 WITHHELD로 남기고 최종 text/summary를 공개하지 않는다. 올바른 claim만 조용히 잘라 다시 PASS로 만들지 않는다. 원문 참조 등 결정 검사 실패 시 최종 claims=[]·verificationRequestDigest=null로 초기화하되 이전 시도의 attempts/checks/요청·영수증은 보존한다. 최대 1회 보완 결과만 새 시도로 검사한다. 핵심 이슈별 부분 발행 및 다른 회차의 저장 정책은 이 규칙과 별개다.
- 조건 등록부를 구축하면 **v2.5 등 별도 새 버전**의 입력 schema·생성/검증 prompt·서버 허용 버전·조건 판정 규칙/평가를 함께 추가한다. v2.3의 conditions=[] 계약이나 완료된 요청/인용/모델 응답을 변경하지 않는다. 087 시점의 v2.3은 실제 유료 실행 전 개발 초안이었으며 Git commit과 prompt artifact SHA를 함께 고정한다.
