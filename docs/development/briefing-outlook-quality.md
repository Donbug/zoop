# 회차 전망의 문장·근거 품질과 추가 데이터 연결 순서

PR #258, 기준 2026-10-21. 대상은 로컬 과거 회차 재생·검증 경로다. PoC 추출·사건 묶음, ERD·공개 API 형태·운영 공급원은 변경하지 않는다.

## 새 생성 계약: market-context-v2.3-outlook

- 출근: 전체 적격 기업 자료와 직전 퇴근의 실제 구조화 전망에 새 정보를 연결해 오늘의 잠정 방향을 갱신한다.
- 퇴근: 실제 아침 전망과 관측을 구분해 비교하고, 확인된 다음 거래일의 잠정 방향을 제시한다.
- fact 한 개는 독립 사실 하나다. 서버·생성기 모두 원문 문서 하나(동일 문서의 여러 인용 허용) 또는 지표 하나만 허용한다. 여러 원문의 사실은 분리하고 interpretation에서 종합한다. 이 앵커 검사만으로 원자성이 증명되지는 않는다.
- 별도 검증 모델의 `atomicClaim`, `evidenceClauseCoverage`, `qualifiersPreserved`, `observableConditionsOnly`를 모두 요구한다. 누락/false는 PASS가 아니다. 한 문서에 여러 사실이 있을 수 있으므로 의미적 원자성과 모든 사실 절의 근거는 이 검증으로 추가 판단한다. 이는 모델 판단이며 외부 사실 인증이 아니다.
- 원문의 약·최대·예정·미확정, 발언 주체, 기사 보도와 직접 발언, 수치 단위·각 지표의 기준일을 보존한다. 반대 요인도 새 사실을 만들어 적지 않는다.
- 현재 입력에 조건 원천·변수·단위·임계값·확인 시각·평가 기간의 등록부가 없다. 새 전망의 `conditions=[]`만 허용하고, 결과를 조건으로 반복하거나 관측 기준 없는 기대확산·수요유지 가정을 본문으로 우회하는 것도 독립 검증에서 거부한다. 근거가 엇갈리면 `uncertain`과 구체적 반대 요인을 사용한다. 전망 자체를 없애는 정책은 아니다.
- 과거 v2/v2.1/v2.2 결과·조건·요청 해시를 수정하지 않는다. 이전 조건의 충족 자료가 없으면 기존 `condition_outcomes_not_observed`를 유지한다. 빈 새 conditions가 과거 조건 충족의 증거가 되지는 않는다.
- 스키마/버전·목적·근거 참조·조건·생성/검증 실제 응답 바이트를 import 시 재확인한다. 한 회차 WITHHELD를 다른 성공 회차나 과거 기록의 PASS로 바꾸지 않는다.

CLI 신규 실행 기본 버전은 v2.3이다. 기존 완료 계획을 재사용할 때는 원래 `--prompt-version market-context-v2.2-outlook` 등을 명시한다. 프롬프트 4파일은 버전별로 보존하며 같은 출력 폴더에 다른 계획을 덮어쓰지 않는다. 조건 관측 연결을 추가할 때는 새 버전 계약으로 확장하며 현재 제한을 조용히 제거하지 않는다.

## 추가 데이터의 수집·연결 순서

| 순서 | 데이터와 연결점 | 완료 기준·없을 때 처리 |
|---|---|---|
| 1 · 현재 흐름 안정화 | 원문 버전·원발행/수집 시각·권한·검수 revision·AI jobId → 적격 문서 → 기존 사건 → 회차 cutoff/입력 artifact | 미확인 권한·미래 정보 제외. 입력 SHA와 당시 고정 근거 보존. 과거 시뮬레이션은 당시 수집/동일 본문을 보증하지 않음 |
| 2 · 회차 관측 정확화 | 거래 캘린더, 회차 시각의 KOSPI/KOSDAQ 관측값·전일/당일 종가, USD/KRW 기준환율 → round snapshot | 원천명·관측/수집 시각·단위·지연·원본 SHA 보존. 09:20에 전일 종가를 장초반 실시간값으로 표시하지 않음. 은행 고시는 FX 종가와 구분 |
| 3 · 조건 관측 등록부 | 독립 선행 변수의 원천·변수 ID·단위·임계값/연산자·확인 시각·유효기간 → 고정 허용 조건 ID → 이후 조건 관측 | 전망 목표 지수의 같은 종가/방향을 조건으로 삼지 않음. 허용 조건만 다음 버전 생성에 제공. 누락/미완료는 평가불가; 오늘 조건을 임의 창작하지 않음 |
| 4 · 업종·시장 범위 확장 | 업종별 수익률·거래량·외국인/기관 수급, 기업-업종 매핑과 유효 버전 → broad market context | 이용 가능한 공급원과 사용권한부터 확정. 원천 근거 없는 공급 관계·시장 대표성 금지. 숫자·기간·업종 매핑을 실제 원문과 연결 |
| 5 · 야간/예정 정보 | 해외 주요 지수·금리·원자재·환율의 실제 관측, 공시/실적/정책 일정 → 직전 퇴근 이후 새 정보 | 거래 시간대·예정/실제 발표·수집 가능 시각을 분리. 원문·정확 인용/관측 근거 없이 예상 결과를 사실로 넣지 않음 |
| 6 · 순차 평가 | 고정 이전 발행본/전망·조건/목표일 실제 관측 → 출근 갱신·퇴근 비교 → 불변 결과·사용량 → DB→API→화면 | 방향 일치와 조건 충족·인과를 별개로 평가. 목표일 미관측/조건 미확인은 unavailable. 실패/보완·사용량·미응답은 원형 보존 |

2일 내 범위는 현재 흐름 안정화·검증과 팀 검토 준비다. 3~5의 공급원 전체 구현·AWS 운영까지 완료한 것으로 보지 않는다. 실제 공급원 연결 시 필요한 계정/키를 서버 전용 비밀 설정으로 받아야 하며 현재 키·권한이 있다는 이유로 새 공급원까지 접근 가능하다고 가정하지 않는다. 예전 발행본에 새 데이터를 소급 주입하지 않고 별도 실행·버전으로 검증한다.

## 검증과 운영 전 남은 일

- 오프라인 반례: 여러 문서/지표를 한 fact에 묶음, 근거 없는 사실, 이전 요약을 사실 대체, 목표 결과 반복 조건, 비관측 조건, 한 품질 flag의 false/누락을 각각 거부한다.
- 합성 provider 기록으로 v2.3의 생성→검증→실제 PostgreSQL import/조회 투영과 기존 이력 보존을 검사한다. 합성 응답 통과를 새 실제 AI 문안의 품질 통과라고 보고하지 않는다.
- CI 병렬 기록 저장은 완성된 임시 파일을 원래 경로에 원자적으로 게시한다. 다른 회차가 작성 중인 빈/부분 JSON을 receipt로 읽지 않는다. 기존 파일은 동일 바이트일 때만 재사용한다.
- 409/415 예약으로 잔여 6회다. 현재 v2.2의 실제 4회차는 보존하고, 이번 변경은 새 유료 생성 없이 검사한다. 4회차 새 생성+검증 최소 8회는 현 잔여 한도보다 많다. 기존 완료 호출을 다시 보내거나 이전 399 기준으로 사용량을 되돌리지 않는다.
- 현재 runner/importer는 `outlookHistory` 한 층만 지원한다. 이미 history가 있는 v2.2 결과에서 다음 실행을 하려면 기존 모든 history 호출·원본을 잃지 않는 연속 이력 지원을 먼저 추가하고 검증해야 한다. 더 오래된 baseline으로 돌아가 누적 예산을 우회하지 않는다.
- 실제 관측 원천·사용권한, 추가 실행 한도, 연속 history 지원, 새 실제 문안 검증 후 최종 DB→API→화면 확인이 남는다. 이번 PR 업데이트는 병합/배포 승인이 아니다.

## 2026-10-21 후속 검토: 범위·재현·다음 실행 한도

- `conditions=[]`는 배열 조건의 결정 검사다. 본문에 숨긴 가정·출처 층위·수식어의 의미 판단은 verifier 모델에 의존하며 결정적 보증이 아니다. v2.3 검증 문안에서 옛 v2.2의 비관측 가정 허용 예시를 제거하고, 지속/확산을 사실로 위장한 문장·기자/회사/애널리스트 주체 변경·약/예정 탈락을 거부하도록 명시했다.
- 합성 반례의 기대 판정을 작성해 보류 경로와 원 기록 보존을 검사한다. 합성 verifier 응답은 실제 모델 정확도·재현율을 측정한 결과가 아니다. 실제 새 출력에서 claim별 quote/indicator와 verifier reason을 다시 대조해야 한다. 새 4회차만으로 일반적인 정확도를 계산하지 않는다.
- **실패 범위는 시장 요약 생성 시도 전체다.** 하나의 claim 의미 검증이 실패하면 그 시도의 시장 요약 전체를 WITHHELD로 남기고 최종 text/summary를 공개하지 않는다. 올바른 claim만 조용히 잘라 다시 PASS로 만들지 않는다. 원문 참조 등 결정 검사 실패 시 최종 claims=[]·verificationRequestDigest=null로 초기화하되 이전 시도의 attempts/checks/요청·영수증은 보존한다. 최대 1회 보완 결과만 새 시도로 검사한다. 핵심 이슈별 부분 발행 및 다른 회차의 저장 정책은 이 규칙과 별개다.
- 조건 등록부를 구축하면 **v2.4 등 새 버전**의 입력 schema·생성/검증 prompt·서버 허용 버전·조건 판정 규칙/평가를 함께 추가한다. v2.3의 conditions=[] 계약이나 완료된 요청/인용/모델 응답을 변경하지 않는다. 현재 v2.3은 실제 유료 실행 전 개발 초안이며 Git commit과 prompt artifact SHA를 함께 고정한다.

이번 대상은 시장 요약만 다시 생성하는 10/7 출근→퇴근→10/8 출근→퇴근 4회차다. 수집·추출·묶음·선정·핵심 이슈 문안은 기존 완료 기록을 재사용한다.

| 실행 범위 | 신규 호출 | 기존409 포함 총량 | 현재415 대비 필요한 한도 증가 |
|---|---:|---:|---:|
| 각 회차 생성1+검증1, 보완 없음 | 8 | 417 | +2 |
| 각 회차 최대1회 생성 보완+검증까지 | 최대16 | 최대425 | +10 |

현재 남은6회를 이미 포함한 계산이다. 16회 신규 호출을 승인받는다면 전체425회 상한이 필요하며, 실제로 모두 쓰겠다는 뜻은 아니다. 결정 검사 실패는 verifier 호출을 생략할 수 있어 실제 사용량은 줄 수 있다. 제한 안에서 모두 PASS한다는 보장도 없다. 기존 미응답2건도 누적409 안에 포함돼 있으며 재전송하지 않는다. 신규 호출 승인 없이 이번에 실행하지 않는다. 추가 한도만으로 실행 가능한 것은 아니며 이미 history가 있는 baseline의 연속 이력 지원도 먼저 보완해야 한다.
