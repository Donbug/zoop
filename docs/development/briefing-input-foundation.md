# 브리핑 후보 선정·입력 고정·시장 지표 기반

브리핑 생성에는 회차 기준으로 선정한 이슈와 그 판단 근거, 기준 시점의 시장 지표를 재현할 수 있는 입력이 필요하다. `com.zoop.briefing` 패키지는 최대 3개 이슈 선정, 회차/거래일 구분, 시장 snapshot과 불변 입력 준비를 제공한다. 사용 방법은 [브리핑 입력](../../api/docs/BRIEFING_INPUT.md)에 있다.

추적 이슈는 [#190](https://github.com/Donbug/zoop/issues/190)이며, 관련 요구사항은 FS030·FS031·FS035와 WBS6.8.3/6.8.4/6.8.8/6.8.15이다. 목표 API는 `getBriefing`, `listBriefingRounds`, `getBriefingGraphBasis`, `appendBriefingCorrection`이다.

## 구현한 동작

- 선정기: 검수·사용 권한·영향 근거·신규 사실을 검사하고 최대 3개를 고른다. 부족하면 0~2개를 유지하며, 보류/제외/선정 이유를 남긴다. 원천 조회 실패를 정상적인 빈 결과로 취급하지 않는다.
- 입력 고정: 원문/분석/버전 참조, 선정 결과와 실제 AI 요청 JSON을 SHA-256 기반 파일로 보존한다. 같은 입력은 재사용하고 변경된 입력은 별도 파일로 남긴다. 등록 receipt의 해시/크기를 검증한다.
- 회차·거래일: 생성 시작 기준은 09:20/17:30 Asia/Seoul이다. 명시적 캘린더를 사용하며 빠진 날짜를 평일로 추정하지 않는다.
- 시장 지표: KOSPI·KOSDAQ·원/달러 개발용 수집과 snapshot 재생을 제공한다. 수집 성공과 실제 값 가용성을 구분하고 기준일·지연·출처를 보존한다. 장중 값이나 은행 고시값을 확정 종가/외환시장 마감값으로 바꾸지 않는다.

이슈 전체의 완료 체크는 위 후속 조건까지 확인한 뒤 갱신한다. 입력 모듈 시험 통과만으로 기능 이슈를 종료하지 않는다.

## DB·운영 연결 순서

현재 입력 모듈은 새 HTTP route·DTO·migration·entity·DB 설정을 추가하지 않는다. `briefingMarketCapture`는 `--development-read`가 필요한 명시 실행 task이며 build/test/startup에서 수집·모델 호출을 시작하지 않는다.

1. 기존 `V20261014120000__create_document_registry.sql`의 공통 `artifacts`를 사용한다. kind CHECK, 불변 UPDATE trigger와 문서 FK를 유지하고 필요한 참조/검증을 추가한다.
2. 현재 적용 migration을 수정하지 않고 신규 번호의 후속 migration을 작성한다. 기존 DB 전체 적용 후 업그레이드 시험으로 순서와 기존 데이터 보존을 확인한다.
3. ERD v6 §19의 `briefing_rounds` 통합 구조에 맞춰 발행 내용·이슈/근거·전망과 `briefing_changes` 정정 이력을 연결한다.
4. 실제 articles/article_versions·분석·현재 권한/철회·검수 revision·graph 준비 상태의 담당 adapter를 연결한다. 이전 허용 기록을 현재 전송/공개 승인으로 사용하지 않는다.
5. 발행 transaction/잠금·AI 호출/사용량 기록과 조회 복원을 연결하고 실제 principal·공개/회원 계약을 검증한다. 운영 캘린더/공급원·스케줄러 연결 후 회차 전체 흐름을 시험한다.

시장 공급원은 개발용 읽기이며 운영 저장·모델 전송·재배포 권한은 미확정이다. 실제 키·환경 파일·사용자 기록·원문 응답·DB는 저장소와 시험 fixture에 포함하지 않는다.

## 검증·리뷰·롤백

선정기·입력 파일·시장 snapshot의 합성 fixture/localhost 시험과 기존 company/auth PostgreSQL 회귀를 검증한다. 로컬 시험, GitHub CI, 실제 외부 연동 및 웹E2E의 결과는 각각 구분해서 PR에 기록한다.

브리핑 담당은 선정 이유·시점·근거·입력 무결성을, API/DB 담당은 공통 registry·후속 migration·발행/인증 경계를 검토한다. 입력 기반 PR의 롤백은 해당 커밋 revert이며, DB 변경이 없어 데이터 복원 migration은 필요하지 않다.
