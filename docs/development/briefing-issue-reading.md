# 근거에 연결된 이슈 읽기 개선

D-BRF-01/02의 간단히 화면은 제목 아래 선정 이유를 먼저 보여주고, 펼치면 공통 사실 → 기업 연결 이유 → 기업별 판단·시세 → 다음 확인사항 순서로 읽는다.

## 기존 기록과 표시 검토의 구분

- `issueIntelligence`, 원래 `items`, 사건 ID, 근거, 시세, 평가 대상은 변경하지 않는다.
- 선택적인 `issueReading`은 기존 선정·독립 검증 기록의 중요도 이유·이번 회차의 새 정보·기업 연결 근거를 재사용한다. AI 생성이나 새 독립 검증을 뜻하지 않는다.
- `scripts/briefing_issue_reading.py::annotate`는 필수 인자 `frozen`과 `verified_calls()`로 읽은 `calls`를 받아 원래 발행본의 projection을 재검증한다. 선정 평가의 생성·검증 receipt와 동결된 분석 입력을 대조하므로 관계 설명의 두 사본 또는 가격 순위 사용 표시만 바꿔도 거부한다. 입력 응답의 items·issueIntelligence·보존본도 재검증한 projection과 같아야 한다. 정확한 인용·기업별 근거 소속을 확인한 후 사본에만 메타데이터를 추가한다. 네트워크와 모델 호출이 없다.
- 동일 기업 또는 동일 문서라는 이유만으로 사건을 자동 통합하지 않는다. 검토자가 동일 결정의 조건부 절차라고 확인한 명시적 그룹만 표시를 묶는다. 그룹에는 원래 사건 ID와 정확한 원문 인용을 보존한다.
- 프론트는 회차·생성 버전·마감·근거 일치를 다시 검사한다. 불일치하면 경고와 원래 이슈를 표시한다. 개인화 화면에 그룹 일부만 있으면 묶지 않는다.
- 전체 보기는 원래 항목별 분석을 유지한다. 간단히에서도 묶은 항목의 분석·원문·S3 결과·평가를 세부 사건별로 열 수 있다. 통합 카드에 새로운 평가 대상 ID를 만들지 않는다.

## 기업별 설명과 읽기

검증된 관계 근거와 기록된 사건 역할을 함께 사용해 직접 당사자를 앞에 둔다. 일반 고객 관계만으로 특정 사건의 영향을 만들어 내지 않는다. 서로 다른 사건의 이전 판단은 통합 비교하지 않고 원래 세부 사건에서 읽는다. 상충하는 방향을 평균하거나 하나의 새로운 판단으로 바꾸지 않는다.

공통 사실은 한 번 표시하고 정확히 같은 기업별 사실만 중복 제거한다. 긍정·위험은 기존 완결 문장 한 개를 우선 표시하고 나머지 전체 설명을 펼친다. 문자를 강제로 자르거나 없는 긍정·위험을 생성하지 않는다. 사실은 중립 색상, 긍정 방향만 초록색으로 구분한다.

검증 범위와 자료 오류 경고는 유지한다. 피드백 조회 실패는 기능 위치의 중립 안내로, 사용자가 실행한 저장 실패는 해당 위치의 오류로 보여준다.

## 검증

- Python: `PYTHONPATH=scripts python3 -m unittest discover -s scripts/tests -p 'test_briefing_issue_reading.py'`
- Web: `cd web && ./node_modules/.bin/vitest run tests/briefing` (프로젝트 test 스크립트 대신 로컬 vitest 직접 실행도 가능)
- 묶음 없는 동일 기업의 독립 사건 유지, 원문 변경·검증 실패 거부, 부분 개인화 격리, 선정 이유 상단 표시, 원래 ID/평가 및 원본 불변 회귀 검증.

이 기능은 검토된 저장본의 읽기 구성을 보완한다. 자동 후보 추출·사건 식별기의 일반적인 중복 문제를 해결하거나 새 핵심 후보를 재선정한 것은 아니다.

기존 호출자는 `annotate(response, row, groups, frozen=frozen_input, calls=verified_calls(output_dir))`로 전달해야 한다. 인증 자료가 없는 이전 호출 방식은 허용하지 않는다. 기존 발행·AI 응답·예산 기록은 수정하지 않는다. 묶음 상세에는 각 사건의 기업별 원래 방향·문안·조건·시세를 표시하며, 다른 사건의 판단으로 덮어쓰지 않는다.
