# 명시 종목 선택 개인화 브리핑 (D-BRF-01/02)

필수 흐름은 개인화 브리핑 버튼 → 회원 로그인 확인 → 기준 종목 직접 선택 → 전체 적격 이슈에서 관련 핵심 이슈 선정 → 공통과 같은 이슈 카드·분석·근거·회차 시세 보기다. 로그인하지 않으면 결과·종목 목록을 제공하지 않는다. 로그인했어도 처음 선택은 0개이며, 보유·관심 종목은 별도 불러오기 동작으로만 선택에 추가한다. 해당 계정의 모의 계좌 구분도 표시한다. 로그인 뒤 선택 화면으로 돌아갈 위치를 보존한다.

- GET `/api/v1/briefings/personalization/options`: 회원 전용 종목 목록. 기본 selectedIds는 빈 배열. importMine=true를 명시하면 현재 회원 본인의 모의 보유·관심 종목을 반환한다.
- POST `/api/v1/briefings/{id}/personalized/selection`: 회원 세션·CSRF 필수. companyIds(1~20개의 중복 없는 등록 기업), maxIssues(1~3, 기본3), minIssues(0~max, 기본0), perCompanyLimit(1~3, 기본3)를 받는다. 계좌 설정이나 발행 원문을 수정하지 않는 읽기 연산이다.
- 클라이언트는 현재 회차·cutoff·선택 ID가 응답과 일치하는지 확인한다. 계정 전환·로그아웃·회차 전환에서 선택과 응답을 폐기하며 브라우저 저장소에 선택을 자동 보존하지 않는다.

선정은 중요도·새 정보·정확 인용·시점·현재 원문 권한을 먼저 확인한다. 동일 기업의 독립 사건은 허용하고, 동일 eventKey 또는 동일 원문/본문 SHA/인용은 중복 선정하지 않는다. 공통 issue-selection-policy-v2처럼 동일 중요도에서 가격이 모두 관측·동일 기준·공유 관측 중복 없음일 때만 가격을 보강에 쓴다. 검증된 직접 기업 관계는 최대3으로 제한하고 안정적인 ID로 동순위를 정렬한다. 비슷한 기업 이름이나 계좌 비중으로 중요도를 바꾸지 않는다.

최소 개수는 희망치다. 검증을 낮추거나 재보도로 채우지 않으며 minimumShortfall로 부족 개수를 알린다. 종목당 최대 개수는 사용자가 명시했을 때만 제한하며 기본3에서는 같은 기업의 독립 이슈3개를 허용한다. 이전 회차는 고정된 predecessor의 같은 종목/이슈 후보와 확인 조건을 추적하며, 후속 근거가 없으면 충족됐다고 판단하지 않는다.

`scripts/briefing_personal_pool.py --baselines <고정 공통 응답 폴더>`는 기존 모델 생성·독립 검증 영수증을 재검증한 공통 이슈 분석/상세만 sharedView로 후보에 결속한다. 가격 보강 신호와 전체 적격 후보도 포함한 새 불변 pool version을 만든다. 코드에서 임의 긍부정 문안을 생성하지 않는다.

반환 presentation은 공통 `IssueCentricBriefing` 및 `BriefingItemDetails`를 재사용한다. 기업 시세의 기존 검증 기준은 companyPriceBasis로 분리해 보존하며, 그 안의 다른 사건의 사업 문안을 현재 이슈의 판단으로 사용하지 않는다. 선택 목록을 원 발행 목록이나 공개 그래프/평가 대상으로 위장하지 않는다.

분석이 있는 이슈는 기존 검증본을 재사용한다. 전체 적격 후보 중 공통 기준 AI 분석을 아직 생성하지 않은 후보도 선정에서는 숨기지 않는다. 이 경우 analysisStatus=needs_generation과 pendingAnalysisCount를 반환하고 검증된 사실·인용을 제공하며 새 전망은 표시하지 않는다. 이번 POST는 유료 모델 실행이나 운영 자동 생성 작업을 시작하지 않는다. 따라서 모든 임의 종목 조합의 새로운 AI 분석 생성까지 완성된 기능으로 취급해서는 안 된다. 새 미생성 분석의 실제 실행은 승인된 호출 예산·공통 생성/검증 경로를 연결하는 후속 단계다.

기존 공통 발행본·평가 및 이전 개인화 생성 결과는 바꾸지 않는다. 이번 개발은 로컬 검증이며 원격 업로드·병합·신호 전송과 구분한다.
