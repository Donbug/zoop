## Generative QA v1 contract under review

This is proposed acceptance scope for F10, not implemented behavior.

1. Allow one active server job per conversation. Separate durable job ID from request trace ID; the same job/idempotency ID with a different payload returns a conflict.
2. A retry keeps the initial context, requested date and evidence/source versions fixed. Store that frozen input so later graph or document updates cannot silently change the job.
3. Represent insufficient evidence as a domain outcome, distinct from transport, timeout and validation failures.
4. A v1 validation failure ends in a recorded failure; there is no automatic answer regeneration.
5. Persist the result and outcome before declaring completion.
6. Closing the panel changes client visibility, not server execution. Any cancellation behavior needs a separate explicit server contract.
7. Confirm retention, guest permissions and job recovery rules through D03/D04 before implementation.
