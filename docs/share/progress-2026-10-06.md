# 줍 프로토타입 진행 보고 (2026-10-06)

작성: UI/UX·연동·API 명세 담당. 화면계획서와 프로토타입을 팀 기준으로 쓰는 것이 반확정된 것을 전제로, 문서 체계와 API 명세를 만들고 팀 요청 기능을 반영했다.

## 1. 통합 문서 체계와 API 명세

- **원본은 저장소에 둔다.** 화면 ID ↔ 기능·비기능 명세 ↔ 요구사항 ↔ WBS ↔ API ↔ 구현 상태를 ID로 잇는 추적표가 `docs/system/`에 있다. 팀이 보는 파일은 스크립트로 만든다. 갱신 절차: [docs/system/README.md](../system/README.md).
  - 팀용 엑셀: [zoop-trace.xlsx](../system/out/zoop-trace.xlsx)(구글 시트로 가져오기). 시트: 추적표, 화면→기능→API, 기능→WBS→구현 상태, API 목록, 오류 코드, 경고.
  - 화면별·기능별 한 쪽 요약: [docs/system/out/index.md](../system/out/index.md).
- **API 명세는 정식 서버가 구현할 목표 계약이다.** 정본 [openapi.yaml](../api/openapi.yaml)(OpenAPI 3.1, 작업 84개). 팀용 문서 [zoop-api-spec.md](../api/out/zoop-api-spec.md). WBS 6.1.2(공통 API 계약·오류 응답 규격)와 6.10.1(계약 통합 점검)의 산출물로 쓴다.
  - 공통 규칙: `/api/v1` 경로, 회원·관리자 세션 분리와 CSRF, 오류 형식과 오류 코드 26개, 요청 ID·멱등성 키, 커서 페이지, 시각·asOf, 그래프 공개 버전 고정, 부분 실패, AI 질문 작업, 긍부정 판정.
  - 작업마다 연결된 FS/NFS·화면 ID·WBS 번호·우선순위·프로토타입 대응·팀 확인 사항이 붙어 있다. 명세가 「확인 필요」로 남긴 수치(세션 수명, 페이지 크기, 보존 기간 등)는 계약에 넣지 않았다.
- **자동 검사**: `build.py --check`가 끊긴 ID, API 없는 P1 기능, 화면 없는 API, 목표 계약과 프로토타입 API의 차이를 보고한다. 현재 끊긴 참조·누락은 0건이다. 경고 282건은 의도한 경로 차이(`/api` → `/api/v1`)와 원본 확인 사항이다([warnings.md](../system/out/warnings.md)).

## 2. 긍부정 판정

설계 전문: [docs/design/sentiment.md](../design/sentiment.md). 실제 모델 호출은 하지 않았다. 코드와 고정 응답 테스트만 있다.

| | 문서 × 기업 | 브리핑 회차 |
|---|---|---|
| 판정 대상 | 공개 사건으로 그 기업과 이어진 문서(저장 본문이 있는 것) | 회차에 고정된 핵심 이슈와 그 문서 판정·시장 지표 |
| 뜻 | 기사가 그 기업의 사업·재무·평판에 유리한 사실을 보도하는지. 주가 전망이 아니다 | 이번 회차 이슈들의 전반적 성격. 가격·지수 전망 문장 금지 |
| 라벨 | 긍정 · 부정 · 혼재 · 판단 보류 (확률·점수 없음) | 같음 |
| 근거 | 원문 인용 필수. 원문에 그대로 없으면 판정을 버린다 | 근거 이슈 ID 필수 |
| 고정 | 같은 입력은 다시 호출하지 않는다 | 발행 시점에 고정, 이후 변경 없음. 핵심 이슈 0개면 호출하지 않음 |

- 화면: 판정이 있으면 기업 패널·기업 상세 문서 목록·브리핑에 라벨이 보이고, 누르면 이유·인용·판정 시각·모델이 나온다. 판정이 없으면 아무것도 그리지 않는다. 관리자 AI 사용량에 판정 호출이 따로 집계된다.
- 실행 준비: `prototype/bff/scripts/judge_sentiment.py --dry-run` 기준 현재 데모의 문서 × 기업 판정 대상은 72쌍(호출 72회)이다. 이미 발행된 브리핑 회차는 바꿀 수 없으므로, 회차 판정은 데모 회차를 다시 만들 때 함께 생성해야 한다.

## 3. 팀 요청 반영

| 요청 | 반영 |
|---|---|
| 지도의 그래프와 목록을 다른 메뉴로 | 새 메뉴 「종목」(`/companies`, FS037: 목록·검색·상세 이동·관심 토글, 비회원 열람). 헤더는 지도·종목·브리핑·내 종목, 모바일 하단 탭은 지도·종목·브리핑·AI·내 종목. 지도 면적 비율은 변경 전과 같다 |
| 기업 노드 패널에 상세 정보 | FS020 v2 순서로 현재가·등락·기준 시각, 1개월 시세 추이, 주요 지표(접힘), 모의 보유, 사건·관련 기업·뉴스. 한 영역이 실패해도 나머지는 유지한다 |
| 상세 페이지 좌측 기업 전환 | 기업 검색, 보유·관심·최근 본 기업 목록(현재가·등락). 전환해도 기간·기준 시점·탭은 유지한다. 모바일은 기업 전환 시트 |
| 타임라인 세분화 | 기간 1일·1주·1개월·1년(기본 1개월), 기간별 해상도(5분·1시간·일), 시간 묶음별 사건 수와 차트 위 표시, 묶음 선택 → 사건 카드, 그 시점에 공개되지 않은 사건은 숨김, 주소(`?period=&asOf=&tab=&issue=`)로 복원 |
| 상세 페이지의 기업 중심 관계 그래프 | 1·2단계, 기준 시점(asOf)에 맞춘 그래프. 타임라인 선택 ↔ 그래프 사건 ↔ 차트 표시가 함께 강조된다. 차트에서 시점을 고르면 그 시점 그래프로 바뀐다. [지도에서 보기]로 지도 포커스 |

화면계획서를 위 변경에 맞춰 **v2.1**(77쪽)로 다시 만들었다: [zoop-screen-plan-v2.1.pdf](../screen-plan/zoop-screen-plan-v2.1.pdf), [.pptx](../screen-plan/zoop-screen-plan-v2.1.pptx). 새 화면은 D-STK-01·M-STK-01(종목), D-COM-03~06·M-COM-02(기업 상세 전환·관계 그래프·사건 묶음 연동·기준 시점 변경), D-SEN-01·02(긍부정 표시 규칙, 디자인시스템 예시), 부록 「문서 체계」다. 요구 번호는 10-06 정의서 기준으로 바꿨다.
