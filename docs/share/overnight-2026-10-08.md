# 새벽 작업 기준과 아침 확인 사항 (2026-10-08)

> **역사 기록 안내:** 이 문서는 새벽 작업 당시의 판단과 증거를 보존한다. 이후 사용자가 확정한 [현재 작업 기준](day-work-2026-10-08.md)이 우선한다. 특히 FS074~FS081을 포함한 모든 명세/WBS 요구는 팀합의 설계대상이며 프로토타입은 전권 범위다. Figma는 폰트를 제외한 최종 목표 디자인(SUIT 유지), 일정은 WBS 기준이며 Notion 일정은 오래된 자료다. 아래의 검토 전 범위 제외·Figma 대응안·별도 프로토타입 일정 가정은 현재 기준이 아니다. 기존 구현/실행 증거와 미결정 운영 정책은 이 주석으로 완료·실행 승인으로 바뀌지 않는다.

기준은 사용자가 전달한 팀 결정과 [최신 원본 대조](../evidence/doc-delta-2026-10-08.md)다. 우리 프로토타입·화면계획서를 기준으로 유지하며, 새 Figma는 이를 개선한 대응안으로 검토한다. 이번 주 프로토타입 마감과 팀 전체 본개발 일정은 구분한다.

## 3. 아침에 확인할 사항

지금 답을 받아야만 하는 작업은 중단하지 않고, 아래 항목과 무관한 로컬 작업을 먼저 진행한다.

1. **신규 파이프라인의 본개발 담당·범위:** 명세는 검토 전, WBS 본문은 P1·담당·기간 지정, 표지·요약은 미산정이다. 기존 PoC를 어디까지 이식할지와 실제 미구현 부분을 구분한 뒤 승인한다.
2. **본개발 일정:** WBS의 11/05·11/06·11/27과 Notion의 개발 완료 `24→28` 중 동결·검증·인수 날짜를 각각 확정한다. 이번 주 프로토타입 마감과 묶어 바꾸지 않는다.
3. **긍부정 예산·운영:** 모델·추론 설정 방식은 결정됐지만 실제 모델 값, 단가, 호출 예산, 재판정·사람 검수는 아직 미정이다. 실제 호출은 별도 승인 전 실행하지 않는다. 외부 PoC에도 추론 수준을 전달하려면 읽기 전용 원본의 변경·이식 범위를 따로 승인해야 한다. BFF 판정 경로는 이번에 반영했다.
4. **시연 후 확인:** 회차 그래프 범위, 타임라인 기준 시점/사건 선택 구분, 퍼센트 미표시 안을 실제 화면으로 확인한다. 위 가결정을 최종 팀 결정으로 기록하지 않는다.
5. **Figma의 시각 의미:** 흰 기업 원·사건 마름모·검은 CTA까지 전면 반영할지, 기존 토큰을 유지하며 가독성만 반영할지 확인한다. 이번 안은 후자다. 중심/전체 카운터와 ‘크기=활동’은 산식·범위를 먼저 정해야 한다.
6. **기업 정보·소셜의 선행조건:** 추가 기업 정보의 공급원·갱신 기준, Google/카카오 앱 등록과 callback·동의 범위를 확인한다. 이번에는 기존에 확보된 기업 정보와 모의 로그인만 유지한다. 비밀값을 보고서나 채팅에 적을 필요는 없다.

커밋·푸시·팀 문서 원본 게시, 유료 호출, 클라우드 배포는 이번 새벽 작업에서 수행하지 않는다.

## 4. 이번 주 작업 재산정

작업량은 새 행 개수가 아니라 **기존 구현 재사용 / 실제 연결 차이 / 새 생산자 / 결정 대기**로 나눈다. 이번 주 완료 기준은 기존 데이터로 사용자 흐름을 시연하고, 미연결·미판정은 정직하게 표시하며, 본개발 담당자가 화면·API·WBS·시스템 구조를 함께 찾을 수 있는 상태다. 실서비스 배포나 모든 제안의 완성을 프로토타입 마감과 동일시하지 않는다.

### Figma 반영 범위

[대응표](../evidence/wireframe-delta-2026-10-08.md)는 앱 화면 54개 중 47개 정적 대응, 2개 상태 후보, 5개 독립 화면 미수록을 구분한다. 종목 검색·기업 문서/정보 탭·기업 전환은 이미 있으므로 신규 기능 공수를 넣지 않는다.

- **유지·개선:** 실제 데이터와 기존 SUIT/중성색·틸 토큰, 기존 접근성·터치 영역을 유지한다. 라벨 가독성은 먼저 개선한다.
- **아침 확인 후:** 흰 로고 원·사건 마름모·검은 CTA의 전면 시각 전환, 중심 기업과 전체 집계의 관계, ‘크기=활동’ 산식은 별도로 확정한다. Figma의 고정 숫자·사건 제목을 데이터로 옮기지 않는다.
- **추가 입력 필요:** 기업의 정식 명칭·시장 세부구분·대표·설립·홈페이지는 데이터 공급/누락 정책이 필요하다. Google·카카오는 앱 등록·redirect·동의 정보가 필요하다. 값이나 로그인 성공을 하드코딩하지 않는다.
- **시연으로 확인:** 모바일에서 빠진 전/후 상태, 실제 지도 노드, AI 오류/복구, 버킷/asOf 선택 결과는 Figma의 프레임 이름만으로 완료 판정하지 않는다.

## 5. 완료한 구현·도식과 검증

- **모델 설정:** `prototype/bff/.env.example`에 모델·추론 수준의 공개 변수명을 정리했다. `ZOOP_SENTIMENT_MODEL`은 live 실행 시 필수이고 `ZOOP_SENTIMENT_REASONING_EFFORT`가 비어 있으면 공급자 요청 필드를 생략한다. `--model` 우회 플래그는 제거했다. 설정이 바뀌면 문서/회차 캐시도 분리된다. 미지원 옵션을 조용히 제거하거나 낮춰 재호출하지 않는다. 실제 `.env`와 키는 읽거나 고치지 않았다.
- **외부 PoC 경계:** 원본 PoC는 기존 모델 환경변수를 읽지만 추론 수준을 요청에 전달하는 코드가 없다. 이번에는 읽기 전용 경계를 지켜 수정하지 않았다. 본개발에서 같은 설정 정책을 적용할 때 별도 이식 항목으로 다룬다.
- **그래프 이름표:** 추정한 글자 폭 대신 렌더러의 실제 라벨 상자를 사용하고, 사건/기업명과 간선 요약을 함께 선별한다. 경로 스타일이 숨긴 라벨을 다시 노출하던 우선순위도 고쳤다. 노드·선·배지·데이터는 유지하고 숨긴 이름은 호버·선택·관계 목록에서 읽을 수 있다. [측정 원본](../design/v9/label-measurements.json)과 [데스크톱 캡처](../design/v9/label-1440-light-samsung.png), [모바일 상세 그래프](../design/v9/label-390-dark-company-2hop.png)를 보존했다.
- **시스템 구성도:** [전체·프론트엔드·백엔드 3장 PDF](system-architecture/out/system-architecture.pdf), [Mermaid·SVG·재현 안내](system-architecture/README.md)를 준비했다. 현재 사용자 조회의 게시 snapshot/SQLite, 관리자 원장 inspect, 별도 PoC/판정 CLI, 본개발 `/api/v1`·클라우드 초안을 구분했다. 각 장을 실제 렌더링으로 확인했다.
- **BFF:** 전체 테스트 **328개 통과**, 기존 Starlette/httpx deprecation 경고 1건이다. 합성 `.env`를 읽는 실제 CLI replay와 임시 실제뉴스 fixture의 dry-run도 관측했다. 모델 호출 0, dry-run 전후 SQLite 내용·그래프 파일 불변을 확인했다.
- **웹:** 테스트 **93개 통과**, 타입 검사·빌드 통과, 캐시된 impeccable의 소스 및 URL 검사 결과는 빈 목록이다. URL 검사는 비인증 경로이며 보호된 그래프 검증을 대신하지 않는다. 그래프 선택·줌·팬·AI 창 왕복·기업 상세 1/2단계는 별도 로그인 브라우저에서 확인했다.
- **구조도 smoke:** 별도 합성 상태의 health/schema/공개 graph/companies 조회는 모두 200이었다. 게시 파일과 SQLite 버전의 hash가 일치했다. 이 결과는 실제 시장 공급자·관리자 원장·유료 모델·클라우드 검증이 아니다.
- **문서 비밀정보 검사:** 갱신 문서 트리 대상 gitleaks에서 노출 0건을 관측했다. 실제 `.env`는 검사 입력에 넣지 않았다.

그래프의 측정한 **텍스트 상자 간 충돌은 0개**였지만, 사건 원·배지·간선 스트로크와 글자의 교차, 모바일 모달이 지도를 가리는 기존 동작까지 없앴다는 뜻은 아니다. 화면에 보이는 라벨 수와 패널에 가리지 않은 라벨 수를 측정 JSON에 따로 남겼다. 기존 대형 JavaScript 번들 경고와 복귀 시 고립 사건 묶음의 가장자리 위치 변화도 남아 있다.
