@everyone
주말 작업과 오늘 오전 반영 내용을 공유드립니다. **이제 GitHub·공유 시트·Notion에서 확인하실 수 있습니다.** 별도로 전달하지 못했던 아키텍처 구성도 의견도 함께 정리했습니다.

**1. 문서·API 정리**
- 최신 기능명세·WBS와 팀 피드백을 대조해, 메인그래프 v2·AI 챗봇 v2 기준으로 기능 연결을 정리했습니다. 기존 이력과 권한·중복 실행 방지 등의 요구는 유지했습니다.
- 공유 시트의 브리핑 리뷰 ID를 `FS066-01`로 바로잡고, 1년 주가차트를 **주 단위**로 명시했습니다. WBS의 AI 백엔드 업무 참조도 현재 기능명에 맞춰 수정했습니다.
- 추천 종목 영역은 온보딩에서 제외했지만, **추천 API 자체는 삭제하지 않고 유지**했습니다.
- 담당자·일정·진척률은 임의로 바꾸지 않았습니다. FE 복합 참조, 일부 목차 범위, 재무 요구 연결과 일정 충돌은 확인 사항으로 남겼습니다.

**2. 프로토타입 구현**
- 시세·지표·가격 조회에서 **정상적인 자료 없음과 공급자 장애를 구분**하고, 화면 안내와 재시도 처리를 맞췄습니다. 누락된 지표를 0으로 채우지 않습니다.
- 원문 저장·정제·문서 버전 관리·중단 후 재개·인용 위치 추적을 오프라인으로 구현했습니다. 실제 뉴스 정기 수집이나 사용자 화면 공개까지 완료한 것은 아닙니다.
- 로컬 검증은 BFF 380개, 웹 110개 시험이 통과했습니다. 합성 데이터를 이용한 결과이며, 실공급자·운영 부하·배포 검증과는 구분합니다.

**3. 아키텍처 구성도 의견**
앱과 AI/배치 분리, PostgreSQL·Neo4j를 나눈 큰 구조는 유지해도 좋겠습니다. 다음 경계를 보완하면 본개발 기준으로 더 명확해질 것 같습니다.

- 모든 이슈를 사람이 승인하기보다는 **보류된 결과를 사람이 검수하고, 허용한 결과도 자동 재검증 후 공개**하는 흐름이 현재 명세와 맞습니다.
- 브리핑은 **정시 생성→검증→발행**을 기본으로 두고, 관리자는 예외 재처리·정정·중단을 맡는 안을 권합니다.
- DB 저장과 별도로, **그래프·기업 상세의 조회 준비를 확인한 뒤 공통 공개 버전을 전환하는 단계**를 표시하면 좋겠습니다.
- RDS는 Single-AZ 인스턴스라도 일반적인 DB subnet group에 서로 다른 두 AZ의 서브넷이 필요합니다. DB를 두 대 띄우자는 뜻은 아닙니다.
- AI 서버의 내부 접근 범위, 세션의 최종 저장소, 앱·worker의 DB 쓰기 책임을 명시하면 좋겠습니다.

그림 검토 의견이며 실제 AWS 설정을 확인한 것은 아닙니다. 그림에 없는 요소가 실제 구성에도 없다고 단정하지는 않았습니다.

**4. 오늘 확인하고 진행할 내용**
저는 기존 PoC와 문서 준비 기능을 재사용해 **문서→사건·주제 후보→근거 연결** 흐름을 진행하려고 합니다. 관련 WBS 납기가 10/14~16에 몰려 있고 GraphDB 책임 표기에도 상충하는 부분이 있어, **오늘 담당 경계와 이번 주에 실제로 인수할 범위부터 짧게 맞추면 좋겠습니다.** 담당 부분에서 다른 기준이나 이미 진행한 작업이 있으면 이 스레드에 알려주세요.
