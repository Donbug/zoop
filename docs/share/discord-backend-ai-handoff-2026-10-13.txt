@everyone 오늘 AI·백엔드 연동 작업 공유드립니다.

**오늘 구현·검증한 범위**
- S2 사건 추출과 S3 관계 분석의 내부 HTTP를 연결했습니다. 접수·상태/결과 조회·취소·복구를 지원하며, 실제 S2 → S3 흐름을 검증했습니다.
- S3 관계별 allow/reject와 재검증을 연결했습니다. 조회 당시 sourceVersion/sourceRevision이 달라지면 거부하고, 같은 요청을 재전송해도 검수 이력이나 호출이 중복되지 않도록 했습니다. allow와 검증 통과는 공개 완료가 아닙니다.
- 문서·권리 변경 시 관련 분석 후보를 찾는 읽기 전용 영향 조회를 추가했습니다. 실제 철회·GraphDB 비활성화까지 구현한 것은 아닙니다.

**연동 시 확인 부탁드리는 점**
- 공개 API의 앱 jobId와 내부 AI jobId를 구분해 저장하고, 앱 검수 revision과 AI 원천 revision도 따로 전달해야 합니다.
- S2는 서버가 승인한 입력 digest로만 실행합니다. 호출자가 기업 목록·사건 snapshot·파일 경로를 임의로 지정하지 않습니다. S2 완료가 S3 접근 권한을 자동으로 부여하지도 않습니다.
- 응답 유실이나 중단 시 새 작업을 바로 만들지 말고 기존 ID로 조회·복구해야 합니다. 결과 반환·앱 저장 시에는 현재 권리를 다시 확인해야 합니다.

로컬 검증은 서비스 테스트 461개, 실제 pipeline 연동 테스트 96개와 두 HTTP smoke가 통과했습니다. 사람이 작성한 replay 응답을 사용했으며 외부 모델 호출은 없었습니다. 실제 모델 품질·운영 배포 완료를 뜻하지 않습니다.

공유 WBS에는 윤서진 담당 18개 행의 진행 내용과 남은 범위를 추가했습니다. 일정·담당·가중치·진행률 숫자는 바꾸지 않았으며, FS074–081 전체를 완료 처리하지 않았습니다.

다음 연결은 Spring 소비, 앱 작업↔AI 작업 저장, 문서/분석 결과 수입과 GraphDB 공개 반영입니다. 관리자 검수 화면 연동도 별도로 남아 있습니다. 새 운영 요구(09–18시 운영·야간 복구·09:20/17:30 브리핑)는 실제 스케줄러와 함께 검증해야 합니다.
