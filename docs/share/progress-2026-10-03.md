# 줍 프로토타입 진행 보고 (2026-10-03)

작성: UI/UX·연동 담당. 주말에 올라온 회의록(Notion)·갱신 명세·WBS v0.2·화면계획서 v1.7(PPTX·Figma)을 확인하고, 화면계획서에서 가져올 것을 프로토타입에 반영했다. 새 화면계획서 v2.0을 프로토타입 실제 화면으로 만들었다.

## 1. 새 화면계획서 v2.0

- 파일: v2.0(10-03 커밋 `1cf82df`). 10-06에 [v2.1](../screen-plan/zoop-screen-plan-v2.1.pdf)로 대체됐다. 다시 만드는 방법: [docs/screen-plan/README.md](../screen-plan/README.md).
- v1.7의 화면 ID 체계(D-AUT·D-ONB·D-WAT·D-GRP·D-COM·D-BRF·D-AI·M-*·A-ADM)와 슬라이드 형식(왼쪽 화면, 오른쪽 진입 조건·번호별 동작·상태·명세 ID)을 그대로 이었다. 65쪽, 화면 45개 묶음에 번호 159개다. 화면은 모두 실제 프로토타입 캡처이고, 번호 설명은 스크립트로 실제 눌러 본 결과다.
- 9/30 강사 피드백 반영: 누르면 나오는 결과를 번호마다 적었다. 색은 뜻(주 행동·선택, 상승·하락, 경고·오류)에만 쓰고 모든 화면에서 같게 했다. 모듈 구분은 ID·아이콘으로 한다. 모바일 화면도 포함했다.

## 2. v1.7에서 가져온 것과 가져오지 않은 것

평가 전문: [screen-plan-v1.7-review.md](../evidence/screen-plan-v1.7-review.md)

| 가져온 것 (프로토타입 반영) | 가져오지 않은 것 (근거) |
|---|---|
| 장 마감 보드의 회차 비교 의도 → 퇴근 브리핑에 시장 지표 3개(KOSPI·KOSDAQ·원/달러, FS031)와 「아침 이후 바뀐 내용」(신규·빠짐) | 간선 클릭 모달 D-GRP-06 (명세 FS022·D03: 이슈–기업 선은 누르지 않음) |
| 근거·원문 접근 상태 표(슬라이드 39·40) → 삭제·비공개 자료 안내 추가, 상태 매트릭스 문서화 | 외부 원인 노드 10종·기업 간 직결 관계선 (데이터 없음, 노드는 기업·이슈 두 종류) |

| 비회원 권한 표·관리자 감사 규칙의 형식 | 관심 종목 최대 3개 (9/30 결정·FS012: 제한 없음) |
| | 브리핑 08:00/18:00 (정본: 07:40/18:10 생성 시작) |

같이 반영한 것: 9/30 결정과 갱신 명세 `메인그래프 v2` FS017·FS019·FS026에 따라 내 종목 지도에 **전체·보유·관심 범위 필터**를 넣었다(기본 전체, 같은 세션에서만 유지, 범위 밖 기업을 고르면 범위를 바꾸지 않고 안내 후 [전체로 보기] 제안).

## 3. 갱신 자료에서 확인한 것

상세: [spec-wbs-delta-2026-10-03.md](../evidence/spec-wbs-delta-2026-10-03.md), [notion-delta-2026-10-03.md](../evidence/notion-delta-2026-10-03.md)

- **명세(10-03)**: 13 → 15시트. 기존 상세 60개가 바뀌었고 `메인그래프 v2`·`AI 챗봇 v2`가 기존 시트와 **나란히** 추가됐다. 대체 선언·변경 내역 기록이 없어 어느 쪽이 정본인지 문서만으로 알 수 없다.
- **WBS v0.2**: 개발 작업(6.x)의 담당이 모두 비어 있다. 와이어프레임·화면계획서(4.1·4.2)는 10/02–10/06. 현재 프로토타입을 쓸지는 언급이 없다. 본표와 일정 요약의 날짜가 그래프·AI·통합 일정에서 서로 다르다.
- **Notion**: 9/30·10/1·10/2 회의록과 역할안, 최종 시퀀스가 새로 올라왔다(10/3 회의록은 없음).
