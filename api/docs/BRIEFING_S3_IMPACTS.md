# Briefing S3 issue/company impact read

`GET /api/v1/briefings/{roundId}/items/{eventId}/impacts?graphVersion=...` is a read-only projection of the exact publication graph's registered handoff receipt. It never generates new labels, reads the latest graph in place of an old version, imports results, writes a publication, or calls an AI/provider.

The briefing owner first validates the immutable published selection and current source authority. An unknown issue of that round is 404; unavailable authority or corrupt storage is 503. A requested version must match the publication (422 on mismatch). A historical round with no original `graph_version_id` returns explicit `unavailable/publication_snapshot_not_recorded`; a later reconstructed graph does not invent an S3 history.

For an imported public graph, reuse the round-pinned graph reader (cutoff, exclusions, visible issue and company relations), `EvidenceService.graphImportBundle` (artifact registry/hash/size and version binding), and the full existing evidence read (current article/source rights, source revision, exact article version/text/span). The read is one repeatable-read transaction. The S1 document sentiment and existing v5 company outlook are not substituted for S3 impact results.

Bundle -6/-7 rows are closed over each visible INVOLVES relation's S3 source references. Source provenance is retained. Verified effect citations must be unique/disjoint, belong to that relation's own article versions, and remain visible/readable. The API recomputes the label using the producer's existing rule: insufficient target or any uncertain effect → undetermined; positive+negative → mixed; one direction → that direction; neutral only → undetermined. Unverified rows cannot carry labels or citations. Current source withdrawal withholds the entire affected row rather than dropping a negative quote and keeping its positive label. Storage outages remain failures, not missing output.

Different S3 source rows remain separate even when they concern the same issue/company. Their conflict is never silently aggregated into an edge or company label. `proposal.reason`, proposed direction, private paths, job/candidate IDs and verifier request digests are not returned. The source quotes explain the assessment; producer wording is not presented as verified reasoning. Assessment IDs are opaque digests scoped to a public relation.

`companies[].assessments[].status` distinguishes verified, no-evidence, not-proposed, not-applicable, technical-reject, verifier-reject and withheld. A verified `undetermined` means an actual evaluation lacked directional support; empty output means no recorded evaluation. `provenance.executionMode=replay` / `recordingKind=authored-test` must be visibly identified as synthetic replay, not independent live inference. Labels concern business impact; prices, predictions and news causation remain separate.

D-BRF-01/02: expanding a compact issue requests this endpoint and shows S3 assessments with connected company, quote effect, exact quote and original URL. The existing v5 business judgment is labelled separately. Full reading keeps the old content and adds a lazy S3 disclosure. Existing prices, evidence, graphs and full analyses remain available. Late responses, foreign issues/companies, wrong versions and future citations cannot be rendered as the current assessment. Transient fetch errors have retry and differ from missing stored results.

Tests: `S3ImpactRowsTest` uses the team producer's retained synthetic export, preserving positive/negative/undetermined source rows; `s3Impacts.test.tsx` checks HTTP binding, disclosures, provenance, missing/error distinctions and late response handling. A dedicated synthetic PostgreSQL/importer/HTTP check is kept in the task's private runtime. It is not a claim that the user's historical rounds possess real S3 results.


## Historical real-news reassessments

`GET /api/v1/briefings/{roundId}/items/{eventId}/impact-reviews` is a separate later review. Configure `zoop.briefing.impact-review.manifest` and its exact `zoop.briefing.impact-review.sha256`; defaults contain no review data. No publication, graphVersion or original receipt is replaced, and a GET never calls a model.

`scripts/briefing_s3_review.py` freezes selected issues, companies, original publication SHA and the preserved quote contexts. It reuses the team S3 impact prompt/schema, native Jev verifier and quote-effect decision policy; S2 grouping and S3 relationship extraction are not rerun. Article versions map losslessly between the public `sha256-` wrapper and native SHA identities. Null citation offsets resolve only from a unique literal quote. The input is the stored quote context, not necessarily the full article or the identical article version at the historical cutoff.

Requests, provider receipts and completed outputs are private immutable files. Completed responses are reused; an attempt without a response is never automatically resent. Generation and verification share the explicitly approved count and USD budget. A proposal without citations does not manufacture a Jev verdict. Low-confidence Jev results remain undetermined under the unchanged team thresholds.

The read checks manifest/input/publication hashes, company membership, current `getItem` source rights, exact source versions, provider receipt hash/status/model, Unicode spans, cutoff and label consistency with verifier effects. Missing data differs from corruption/rights errors. Private proposal rationale, raw distributions, receipt paths, job IDs and keys are not returned.

The UI shows `reviewContext.mode=historical_reassessment`, its later `assessedAt` and preserved-context scope. Original v5 analysis, prices, full reading and evidence stay separate. An absent original S3 receipt can lead to this optional route; review corruption remains an error. This is local replay-result handoff, not AWS deployment, a scheduler or calibrated prediction quality.


## Complete source context and abstention (D-BRF-01/02)

`scripts/briefing_s3_citation_context.py` reuses the immutable generation response and expands citation anchors to complete source paragraphs. When a Board or omitted subject needs an adjoining sentence, it retains that exact source span and the explicit company name. Approximate amounts, future dates, conditional wording and final-agreement qualifications remain literal. A clipped or nonunique anchor fails closed; text is never padded or silently shortened. Catalogue aliases identify the target; they never prove an event.

Changed context is a deterministic citation candidate, not a new AI-generated business opinion. Independently recheck its effects using the unchanged team Jev policy (choice >=0.90 AND confidence >=0.80). Reuse an existing positive assessment without changing its effect citations; expanded fact context remains separate. Existing provider requests, receipts and reviews are retained under their original identities. Rechecks share the original cumulative reservation and USD budget; do not reset it in a new output directory.

Manifest v2 adds `citationPolicy=complete-source-paragraph-1`, the parent manifest SHA and per-row repair provenance. API `assessments[].facts` contains exact source spans with title, URL, date and article version, **without effect or label**. These facts can be shown even when the independent effect is undetermined, or a producer supplied no directional citations. Every fact is checked against current permissions, the preserved context, Unicode offsets, version and cutoff. A wider fact disclosure is not proof that every displayed sentence was independently assessed by Jev: `evidence` continues to expose only the exact assessed effect citations. Later fact-only supplements do not change the assessment or imply another provider call.

The original `/impacts` route and publication stay untouched. `/impact-reviews` stays a later read, not an original historical verdict. GET never starts a model. Compact and full views retain existing prices, summaries, evidence and links.


## Offline evidence preparation for held assessments

`briefing_impact_evidence_plan.py` reads registered full article copies and prepares exact excerpts, native Jev request bodies (not sent) and an explicit collection queue. Current assessment labels, effect citations and receipts are unchanged. An unchanged direct excerpt (such as a shipping-delay sentence with no new causal evidence) is marked `collect_direct_evidence_first` rather than recommending another identical paid check.

`Assessment.evidencePlan` is editorial preparation with `status=prepared_not_evaluated`. Source excerpts are separate from the already assessed `evidence`: `direct`, `issuer_explanation`, `conditional_risk` and `background` distinguish the issue's own facts, company assertions, conditional risk and context. A company's unrelated purchasing agreement cannot establish a shipping delay's cause. Existing full-text excerpts may extend beyond the former 1,800-character input window. The reader first reuses the current round/issue/source-authority check, then matches the same registered article version, source identity, cutoff, whole artifact SHA/size and exact Unicode span. An excerpt is at most 2,000 code points. No arbitrary path or additional article may be introduced, and text matching is never labelled independent semantic verification.

Collection needs distinguish missing contemporaneous evidence (`before_cutoff_gap`) from future outcome checks (`future_followup`). Realised 2027/2028 outcomes must not leak into a 2026 retrospective input. Actual sales/results are not a universal prerequisite for a source-supported conditional business interpretation: a documented mechanism and its assumptions can support an interpretation before its later outcome is known. Verification remains unchanged and must be run under new approval; preparation alone never promotes a held verdict. GET performs no collection, generation or verification.

## Later primary-source references (D-BRF-01/02)

`evidencePlan.research` optionally links separately reviewed official documents to the exact round/issue/company. Status is `editorial_sources_not_ai_evaluated`; summaries and short literal excerpts are editorial references, not native Jev effect evidence. `historicalVersionVerified=false` and source limitations remain visible. SEC index acceptance is explicitly labelled as an acceptance time used for historical simulation, not a contemporaneous collection receipt or an exact public-dissemination timestamp. `web_tool_extract` hashes refer to the local extracted text, not the SEC source HTML.

The opt-in SHA-pinned review bundle contains bounded `supplements/` files. The reader checks exact bindings, current original-item permissions, official HTTPS URLs, cutoff/modified times, file/time-proof SHA, Unicode spans and symlink/path boundaries. Unsupported effects/labels and claims of verified historical identity are refused. These documents do not enter the immutable publication's `evidence` or alter its provider receipts/labels. The historical preparation tool and its reviewed source annotations remain local; this PR supplies the bundle reader and validation rules, without publishing source-bearing preparation inputs.

`research.timeCheck` records a disagreement between the original bound publisher time and a distribution time. It is an annotation, not a silently corrected source timestamp. The known NVIDIA/Sina example stores publisher-declared 02:33Z while the wire declares 06:33 ET (=10:33Z); stored HTML metadata and visible publisher time agree with the stored value. This does not establish which publisher first disseminated the article. A later wire release cannot be newly admitted before an 08:30Z cutoff, and an unexplained fixed eight-hour correction must not be applied globally. Original records remain preserved.

## Completed supplemental rechecks (D-BRF-01/02)

An optional `assessments[].supplementalReview` presents a saved later Jev check over additional official sources. Original `label`, facts, effect citations, publication and prices remain unchanged. The UI leads with the new label, prior label, dated explanation and source-bound confirmed facts, then preserves the previous review under an explicit history label. Korean summaries are editorial explanations of the saved verdict and source text, not model-generated rationales.

The pinned bundle's `rechecks/` files contain the immutable input, exact native request and provider receipt. The reader checks original round/issue/company/publication bindings and current original source permissions first, then the input/receipt hashes, request digest/model/status, exact quote identities/spans and the already checked `research` source files. It independently interprets all saved native choices using the unchanged probability0.90/confidence0.80 gates and recomputes the label. Any uncertain quote keeps the label undetermined. Invalid or unbound results fail closed; GET never calls AI. Explanatory facts must reference the actual assessed quote IDs.

Additional documents remain later-collected historical-simulation material: cutoff eligibility and SHA integrity do not establish historical version identity. Existing `research` and preparation statuses describe the earlier collection/preparation record; `supplementalReview` explicitly records the later verification. No additional document is silently registered as original publication evidence. The local historical preparation tool assembles a separate immutable bundle from completed results without network/AI/DB calls; that source-bearing tool is not included in this PR.
