# 브리핑 재실행·검증 기록의 보존

## 통합 범위

시장 문맥·전망·기업 분석·짧은 읽기·회차 시세와 후속 안정성 수정은 같은 개발 브랜치에서 검토합니다. 로컬 회귀와 CI 성공은 main 병합 승인이나 운영 적합성 판정과 구분합니다.

## 정상 빈 회차의 증거

원입력이 없는 창과 원입력을 평가했지만 선정하지 않은 창을 구분합니다. 입력이 없으면 호출 없이 빈 상태를 보존합니다. 입력이 있으면 원문 SHA·실제 발췌·전 문서 평가의 완료 응답을 대조하고, 중요도/우선순위·사건 중복 제거·상한에 따른 후보 목록을 재구성합니다.

기본 v2의 후보가 모두 반복으로 제외됐으면 기존 신규성 판단과 별도 검증 기록을 허용·보존합니다. 후보가 남았으면 같은 원문/평가의 실제 최종 선정 응답이 비어 있어야 정상 빈 결과가 됩니다. 문안 생성·검증 호출은 정상 빈 결과에 포함하지 않습니다. 보류 상태를 바꾸고 영수증을 지우거나, 신규성 audit와 호출을 함께 없애도 정상 빈 결과로 승격할 수 없습니다. 모든 검사는 DB/artifact 등록 전에 수행합니다.

## 남은 리뷰 수정

- 선정 요청·보완 요청의 응답이 미확정이면 요청/예약/사용량 미확정/운영자 보류 기록만 검증·저장합니다. 응답을 만들어 내거나 재전송하지 않으며 다른 회차는 계속 저장·조회할 수 있습니다.
- recovery 실행은 호출 상한 확인·복사·예약 전에 동일 출력 폴더의 배타 잠금을 획득합니다. 오프라인 계획도 기존 기록을 복사하므로 같은 잠금을 사용합니다. 잠금 파일이 남으면 자동 삭제·자동 재실행하지 않습니다.
- 고정 preview에 제공한 거래일 달력은 원본 SHA와 함께 보존합니다. 실행과 서버 import 모두 같은 바이트와 회차 입력을 대조합니다.
- 일부 날짜만 선택해 실행해도 비선택 기업 분석과 이전 판단을 보존합니다. 선행 판단이 바뀌면 영향을 받는 기존 후속 회차도 함께 선택해야 합니다. 짧은 읽기가 연결된 결과의 기업 분석을 변경하려면 하위 읽기를 별도로 다시 만들어야 합니다.
- 완료 재사용은 원본 번들·원문 파일·선택 날짜/회차·프롬프트·모델·실행 ID·승인 참조·호출 상한을 대조합니다. 입력 식별 sidecar가 없는 이전 완료 폴더는 덮어쓰지 않으며 새 출력 폴더에서 재사용합니다. 미응답 예약은 재전송하지 않습니다.
- 생성·검증의 전체 응답 스키마는 Java에서 frozen 입력으로 재구성합니다. 해시와 영수증만 맞는 true-only 검증 기록이나 strict=false 요청은 거절합니다. 기업 전문과 짧은 읽기에 같은 검사를 적용합니다.
- 이전 성공 발행본의 실제 날짜·출근/퇴근 종류를 선택 필드로 제공합니다. 과거 스냅샷에 해당 필드가 없으면 회차 종류를 추측해 링크를 만들지 않습니다.
- 기업 전망이 없으면 미제공을 표시합니다. 기존 시장 요약·지표는 별도로 유지합니다. 시세 요청 실패는 정상 빈 이력과 구분합니다.

최종 시장 요약 보완의 구조 오류 시 claims/verification digest를 비우는 처리는 이미 후속 코드에 반영되어 있어 중복 수정하지 않았습니다.

## 검증 경계

합성 공급자 기록으로 실패·미응답·변조 경계를 재현하고 전용 PostgreSQL→공개 HTTP 조회를 검증합니다. Python 생성 스키마와 Java 재구성 스키마를 실제 함수 출력으로 비교하고, 요청 해시·영수증을 다시 계산한 true-only 반례도 거절하는지 검사합니다. 합성 응답을 실제 모델 생성 결과로 표시하지 않습니다.

기존 실제 4회차 결과는 새 유료 호출 없이 완료 기록으로 재사용할 수 있습니다. 시세·모델 응답을 다시 수집하거나 기존 DB/실행 폴더를 덮어쓰지 않습니다. 과거 이력은 당시 수집본, 운영 권한, 전망 적중률을 입증하지 않습니다.
