# Quiet-round briefing policy (D-BRF-01·02)

`zoop.briefing.replay.continuity-enabled=true` opts a private local replay into `importance-continuity-v2`. Default false preserves legacy imports. Use a separate DB/artifact directory; changing this option against an already imported run is a conflict, never an in-place replacement.

1. Keep the already verified grade 2–3 headline set, at most three. Never pad a one- or two-item briefing with lower-grade stories.
2. Only when the headline set is empty, consider grade 1 as **reference news**. Reuse the completed importance assessment, independently validated candidate population, company links and freshness recording. Keep its original `HOLD`/reason; that HOLD applied the former grade-2 floor. A reference displays a neutral company heading and exact source quotations, with plans/estimates explicitly distinguished from confirmed results. It is not upgraded into a core issue or a new company forecast.
3. Keep exact body/version/span, (from,to] publication, canonical company identity, registered company scope, recorded SUPPORTED event/company-role verification, REPEAT/UNCERTAIN exclusion and material-update delta checks. Grade 0 never qualifies. Rank grade-1 references by the saved priority then stable ID, at most three, one story per source document. Previously referenced events require a supported material update.
4. If neither tier qualifies, retain a briefing with source scope and verification conditions. Copy an earlier validated publication and its existing watch conditions only if its cutoff is at/before the current window start. Label every copy as historical. Do not regenerate a direction/price target or claim an old forecast remains valid.
5. Source/clock shortages are `coverage.status=insufficient`; without safe references, mode `coverage_limited` stays held. Validation failure/unknown paid reservations are `validation_failed`, never quiet success. Retrospective inputs are `limited`, which describes coverage scope, not a network failure or worldwide news absence.

The importer preserves original bundle/recordings and its original selectionStatus, and stores the deterministic policy under public_snapshot.continuity. A qualified quiet/reference publication has zero **core** items, with reference quotations separately bound in references.evidenceIds and the existing source grants. The ordinary DB→authority→API path remains in use. Recap authority and current correction/suspension are checked again at read time. A changed prior publication hides its recap and old conditions; failed authorization fails closed.

Mobile quiet rounds show the result, scope and watch conditions first. The original market/indicator/empty/detail blocks remain under an expandable section; full reading retains them. Optional OpenAPI `continuity` fields expose the same distinction. No ERD/migration, PoC modification, paid call or public graph approval is introduced.

## Evidence sufficiency, not an 80-character minimum

The old 80-code-point rule was a development heuristic added to reduce under-supported generated headlines; no API contract, native PoC semantic rule or measured accuracy result required that number. It neither proves sufficiency for a long quote nor disproves a complete short fact. Reference news therefore has no fixed minimum length.

Before accepting a reference, `BriefingReferenceSupport` verifies the actual completed `issue_grounding` request/response digest, usage/response identity, original prompt hash, authorized source digest, unchanged full article, native mention title/action/assertion status/participants, exact original evidence offsets and SUPPORTED verdict. The current candidate must match that proven document/version/body/span. Missing/HOLD/REJECT support and blank/altered quotations are rejected regardless of length. References introduce no factual paraphrase, target price or inferred outcome; the original qualified quote is the visible content. Source truth itself is not independently certified, and estimates/plans remain estimates/plans.

The original reference-only revision preserved headline requests. The current opt-in core semantic policy is documented in [BRIEFING_CORE_EVIDENCE](BRIEFING_CORE_EVIDENCE.md): new grouped requests bind a new input/prompt identity, while old recordings keep their recorded contract. Revalidating completed recordings does not rerun selection or upgrade grade-1 candidates. Old previews and original model recordings are retained.
