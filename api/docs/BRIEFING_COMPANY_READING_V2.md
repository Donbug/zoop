# 기업별 판단·새 사실·다음 확인 조건

D-BRF-01/02의 기업 카드는 `한 줄 판단 → 새 사실 → 다음 확인 조건`을 먼저 제공한다. 배경·이전 판단의 유지/변경 이유·각 문장의 근거는 펼쳐서 확인한다. 기존 기업 전망 전문·시세·시장 요약·지표·상세·회차 지도는 유지한다.

## 생성과 검증

- `briefing_series_company.py --prompt-version company-outlook-v4`: 매출원·비용·생산/공급능력·자본정책 중 실제 사건과 연결되는 경로를 쓰고, 원문에 있는 이전 실적/기존 계획과 현재 변화만 비교한다. 출근은 직전 퇴근, 퇴근은 같은 날 아침의 **같은 기업** 판단과 정확한 결과 버전을 연결한다. 가격/거래량/업종 관측 부재를 뉴스 인과나 적중으로 채우지 않는다.
- `briefing_company_reading.py --prompt-version company-reading-v2`: 별도 생성·독립 검증으로 `brief`(140자), `fact`(160자), `watch`(180자), `background`(240자), `change`(180자)를 만든다. 한 문장에 사실·의미·전망을 몰아넣던 v1의 70자 제약을 역할별로 나눴다. CLI 새 실행의 기본은 v2이고 과거 v1은 명시적으로 실행/재생할 수 있다. 기업 전망 CLI의 새 실행 기본도 v4이며 기존 완료 실행 재개는 기록된 버전을 자동 유지한다. 새 실행에 과거 v1/v2/v3를 사용하려면 버전을 명시한다.
- 사실성 `supported`와 별도로 **구체성·새 정보·이전 판단 연결·반복**을 불리언으로 검증한다. 하나라도 false이면 1회 보완 후 다시 검증하고, 계속 미달하면 전체 짧은 문안을 WITHHELD로 남긴다. 통과한 문장만 잘라 PASS로 만들지 않는다. 이는 모델 판단이며 외부 사실의 진실/주가 성과를 인증하지 않는다.
- 배경·새 사실·조건의 인용은 같은 기업의 허용 `sourceIds`에만 속한다. 이전 판단은 원문 증거를 대체하지 않는다. 원문에 기존 계획·실적 수치가 없으면 ‘예상보다’ 등의 비교를 만들지 않고 빠진 비교 기준을 밝힌다. 회사 발표와 언론 해석도 구분한다.

원시 생성·검증 응답과 요청 digest, 실제 prompt/schema bytes, 완료 시각·사용량, 전문의 결과 버전·회차·cutoff·원문 provenance를 Python과 Java에서 각각 결속한다. 공개 API의 `reading.schemaVersion`, `fact`, `background`는 선택 필드로 추가되며 옛 v1 발행본은 변환하지 않는다. ERD/migration 변경은 없다.

## 같은 입력의 대표 3기업 비교

```sh
python3 scripts/briefing_reading_evaluation.py \
  --improved /absolute/private/v2-reading \
  --output /absolute/private/new-comparison \
  --authorization-ref '<승인 참조>'
```

기본은 OFFLINE이다. 새 모델 호출은 `--execute --key-file <서버 전용 키 파일> --max-calls <승인 누적 상한>`을 명시한다. 이 상한은 해당 원장의 예약 수이며 여러 단계/폴더를 실행한다면 작업 전체 예산도 별도로 관리해야 한다.

비교기는 같은 전문·원문·이전 판단으로 v1 문안을 새로 생성·검증하고 v2 입력과의 일치를 해시로 확인한다. 서로 다른 3이슈에서 고른 3기업의 A/B 순서를 뒤집어 두 번 평가하고, 사실 지지와 네 품질 기준을 각각 기록한다. 길이/항목 수 자체를 우수함으로 보지 않는다. 구 baseline이 WITHHELD면 통과한 baseline처럼 비교하지 않는다. `comparison.json`은 소수 표본에 대한 모델 평가이며 사람의 선호 보정·일반 품질 점수·예측 성과와 구분한다.

## 회차와 데이터 보존

09:20/17:30 KST 마감과 실제 publisher 시각을 고정한다. 뒤늦게 수집한 과거 본문은 retrospective로 표시하며 당시 수집/본문 동일성을 주장하지 않는다. 중요도·재보도·회사 동일성·원문/clock 검증은 그대로다. 신규 핵심 이슈가 없는 회차는 확인된 참고 소식/이전 발행본 정책을 따르고 억지로 기업 전망이나 핵심 이슈를 만들지 않는다. 기존 DB·완료 결과·실패/미응답 기록을 덮어쓰지 않는다.

## 배경 조회와 실제 생성 피드백

편집 이력에 `retrievalPolicy=reviewed-issuer-first-v1`을 명시하면 같은 기업의 검토된 `sourceRole=issuer_release`, `reviewStatus=reviewed` 자료를 상위 4개 이력 안에 우선 포함한다. 검색 순위/키워드 중복으로 공식 과거 발표가 밀려 재보도가 신규 사건이 되는 일을 줄인다. 현재 창 시작 이후 자료는 조회하지 않는다. 조회 우선순위는 진위/신규성 승인이 아니며 시각이 불확실한 기록은 그 상태를 유지한 채 독립 편집 검증을 받는다. 기본 과거 이력의 순서는 바뀌지 않는다.

`company-outlook-v4`는 비교 불가와 현재 자료의 확인 범위를 구분한다. 이전 판단 미제공 상태에서 현재 원문으로 입증된 사실을 쓸 수 있으며, 최초 사건이라는 주장은 별도 근거가 필요하다. 생산능력 예약/장비 설치/전력 수요반응을 실제 공급·가동·확정 비용 절감으로 확대하지 않는다. 기존 출처 결속·독립 검증·보류 규칙을 유지하며 과거 v3 프롬프트를 보존한다.

항목별 복구(`briefing_grouped_recovery_run.py`)는 기존 계약대로 원 선정/원 응답을 보존하고1~3개 원자적 문장·별도 사실/신규성 검증을 적용한다. 이 결과를 읽기 전용 presentation으로 연결하는 경우 `briefing_company_outlook.py --prompt-version company-outlook-v4`를 사용할 수 있다. broad marketContext가 없는 추출형 presentation은 선정된 검증 인용만 기업 입력으로 제공한다. Python/Java 모두 없는 배경 자료를 추가하지 않고 같은 기업·사실·원문·버전 결속을 검사한다. `briefing_company_reading.py`는 실제 전문 계층을 확인해 series/presentation을 구분한다. 시장 요약의 근거 문장 재구성은 별도 모델 전망 생성과 구분해 표시한다.
