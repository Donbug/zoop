# #89 기업 문서 조회 결정

`GET /api/v1/companies/{id}/documents`는 D-COM-02의 공개 뉴스·공시 목록이다.

- `round`는 #89 범위에 포함하지 않는다. 회차별 그래프·문서 판정 발행본 연결이 구현되기 전에는 409 `VERSION_UNAVAILABLE`을 반환한다. 최신 발행본으로 대체하지 않는다.
- `from` 또는 `to`가 있으면 발행 시각 미상 문서는 기간 안임을 확인할 수 없어 제외한다. 범위가 없을 때만 정렬의 맨 뒤에 둔다.
- `to`는 선택된 공개 그래프 버전 안에서 기사·사건·기업 직접 간선의 시점 상한으로도 적용한다. `to`가 그래프 버전 선택을 대신하지는 않으며, 버전 선택은 `asOf`/`graphVersion`의 공통 규칙을 따른다. 구조적 간선은 그 시점까지 검증된 근거가 있어야 한다.
- 기업의 사건은 공개 스냅샷의 직접 승인 간선(`INVOLVES`, `STRUCTURALLY_RELATED_TO`)만 사용한다. 각 사건의 mention/evidence가 가리키는 `(articleId, articleVersion)`으로 문서와 인용을 묶는다. 한 기사가 여러 사건·버전에 나타나면 공개 발행 시각이 가장 늦은 버전 한 건을 반환하고, 시각이 같으면 version ID 오름차순으로 결정한다.
- 날짜만 있는 발행 정보는 KST 그날 전체와 기간이 겹치면 포함한다. 응답의 `publishedAt`은 시각을 지어내지 않고 `null`로 둔다. 정렬에는 KST 자정 기준 값을 사용한다.
- 그래프 스냅샷이 문서를 고정한다. 레지스트리에 해당 문서 버전이나 공개 가능한 기사 행이 없으면 목록에서 제외한다. `kind`와 `publisher`는 레지스트리에서 읽는다.
- 프로토타입의 `poc.withdrawn`/`analysis_store.denied`는 운영 저장소에 같은 필드가 없다. 운영 `articles.access_status`가 `private` 또는 `deleted`인 기사는 제외한다. 문서 메타데이터 공개에도 선택된 그래프 버전의 import receipt에 결속된 현재 source grant를 확인하며, 권한 거부 시 문서 전체를 제외한다. registry 장애는 503으로 전달한다.
- 운영 스냅샷에는 기사별 `REPORTS`/`PROVIDES_BACKGROUND` 관계가 저장되지 않는다. `events[].relationType`은 계약에서 허용하는 `null`로 반환하며 추측하지 않는다. 기사별 관계가 필요하면 스냅샷 생산자·형식·검증부터 확장해야 한다.
- 인용은 같은 공개 버전에서 `getEvidence`가 현재 권한으로 제공한 것만 반환한다. 명시적 `asOf` 조회에서는 근거 응답의 `metadata.graphVersion/asOf`도 문서 목록과 일치해야 한다. 분석 결과는 최신 요청과 현재 권한을 확인한 뒤 제공한다. 명시적 `asOf` 또는 `graphVersion` 조회에서는 S1 분석과 그래프 공개 시점의 결속을 증명할 수 없어 저장 결과를 `withheld`로 둔다. 감성 판정의 실행 수신자는 실제 sentiment 실행 행에서 읽어야 한다. 캐시 판정은 검증된 exact receipt로 원래 실행과 수신자를 증명한 경우에만 제공한다.
- 커서는 요청 조건, 첫 페이지의 그래프 버전과 기준 시각, 마지막 문서의 정렬 키에 결합한다. `asOf`가 없으면 후속 페이지에서도 첫 페이지의 버전을 읽고 같은 기준 시각을 응답한다. 앞 페이지의 문서가 비공개로 바뀌어도 위치 번호 때문에 다음 문서를 건너뛰지 않는다.
